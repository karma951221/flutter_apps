## 1. 새로 찾은 결함 — 삭제된 게시물의 댓글이 테이블 경로로 샜다

`post_comments_select_visible` 정책이 `deleted_at is null` 과 차단만 보고 **부모
게시물이 살아 있는지는 보지 않았다.** 앱은 댓글을 `post_comments_visible`(definer 뷰,
부모 생존을 확인한다)로만 읽으므로 화면에는 드러나지 않았지만, 로그인한 사용자가
PostgREST 로 원본 테이블을 직접 조회하면 이미 삭제된 게시물의 댓글이 읽혔다.

```text
소프트 삭제 후, A 의 JWT 로
  post_comments_visible?post_id=eq.<삭제된 글>   → []        ← 앱이 보는 경로
  post_comments?post_id=eq.<삭제된 글>           → [ {...} ] ← 샌다
```

**왜 여태 안 걸렸나.** [2026-08-24 검수](audit-2026-08-24.md)는 "삭제된 글이 피드에서
빠짐 · 그 댓글도 **뷰에서** 빠짐"까지만 확인했다. 뷰만 보고 테이블 경로를 보지 않은
것이 그대로 사각이 됐다. §8 주석의 "테이블 경로가 뷰보다 좁은 것은 안전하다"도 이
축에서는 성립하지 않았다.

**고침.** `20260827161417_hide_comments_of_deleted_post.sql` 이 조회 정책에
`exists (posts …)` 를 더한다. `posts` 는 다른 테이블이라 42P17(정책 자기참조 재귀)이
나지 않는다 — INSERT 정책이 이미 같은 모양을 쓰고 있었다.

트랜잭션 안에서 후보 정책으로 먼저 확인하고 적용했다.

| 확인 | 결과 |
|---|---|
| 삭제된 게시물의 댓글 | 0건 |
| 살아 있는 게시물의 댓글 | 그대로 보임 |
| `insert ... returning` (앱이 실제로 쓰는 경로) | 동작 |
| 삭제된 게시물에 댓글 삽입 | 여전히 42501 |
| `post_comments_visible` (definer) | 영향 없음 |
| 42P17 재귀 | 나지 않음 |

적용 후 REST 로 다시 확인했고 위 표와 같다.

**anon 은 원래부터 못 읽었다** — `post_comments` 에 SELECT GRANT 가 없다. 영향
범위는 "로그인했고 삭제된 게시물의 id 를 아는 사용자"였다.

## 2. 닉네임 중복 확인의 `ilike` 와일드카드

리뷰가 코드만 보고 지적한 것을 실제로 재현했다. `profiles` 에는 길이(2–20) 말고 문자
제약이 없어서 `%` · `_` · `*` 가 **정상적인 닉네임 문자**인데, `ilike` 는 그것들을
와일드카드로 해석한다.

로컬에 `alice` · `alpha` · `a%` 세 프로필을 두고 확인했다.

| 입력 | 실제 결과 | 사용자가 보는 것 |
|---|---|---|
| `a_ice` | `alice` 한 건에 매칭 | **비어 있는 닉네임을 "이미 사용 중"으로 막는다** |
| `a%` | 3건 매칭 → `PGRST116` | 확인이 조용히 실패한다 (`NicknameCheck.idle`) |
| `a*` | 3건 매칭 → `PGRST116` | 같음 — PostgREST 가 `*` 를 `%` 로 바꾼다 |
| `alice` · `ALICE` | 1건 | 정상 (대소문자 무시는 의도된 동작) |

리뷰는 "1건 매칭 시 오판정"만 짚었는데, **`a_ice` 가 그 1건 매칭 사례**라는 것까지는
실제로 돌려 보고 알았다.

**고른 해법.** 이스케이프만으로는 부족하다 — PostgREST 가 `*` 를 `%` 로 바꾸는 것은
이스케이프로 막히지 않고(`\*` → `\%` 가 되어 리터럴 `%` 를 찾는다), 값을 큰따옴표로
감싸면 따옴표가 패턴에 포함돼 아무것도 매칭되지 않는다(둘 다 확인했다). 그래서
두 단계로 나눴다 — DB 필터는 `NicknameMatch.escapeLikePattern` 으로 좁히고, 최종
판정은 `NicknameMatch.isSameNickname` 이 Dart 에서 `lower()` 비교로 한다.
`*` 때문에 필터가 넓게 걸려도 Dart 비교가 걸러내므로 결과는 옳다.

상한(`candidateLimit`)에 걸려 진짜 중복을 놓치면 "사용 가능"으로 보이지만 저장은
유일 인덱스가 막는다 — 사전 확인의 실패 방향으로는 이쪽이 옳다.

같은 구현이 `auth` · `profile` 두 datasource 에 복제돼 있었다. 규칙 ⑥ 때문에
datasource 끼리 참조할 수 없으므로 **정책만** `core/data/nickname_match.dart` 로
올리고 쿼리는 각자 둔다.

## 3. 리뷰가 틀렸던 것 두 가지

**`_displayDate` 는 "완전히 동일"하지 않았다.** 리뷰는 두 벌이 같다고 적었는데,
`post_tile` 은 연도를 넣고(`2026.08.22 09:30`) `comment_tile` 은 뺀다(`08.22 09:30`).
자리맞춤 코드만 같다. 형식을 합치지 않고 자리맞춤만
`core/extension/date_time_format.dart` 로 모았다.

**다크 대비 관찰은 테마가 거꾸로였다.** [preferences 기록](../features/preferences/history.md)이
"`like` 는 **다크** 표면 대비 ~3.5:1 로 AA 에 걸린다"고 적었는데, 실측하면 반대다.

| | 라이트 | 다크 |
|---|---|---|
| `AppColors.like` | **3.28** (AA 미달) | 5.38 (통과) |
| `AppColors.dislike` | **4.29** (AA 미달) | **4.11** (AA 미달) |

`~3.5` 는 라이트 값이었다. 셋 다 큰 글자·아이콘 기준(3:1)은 넘는다. 두 토큰은 여전히
어디에서도 쓰이지 않아 지금 화면에 영향은 없다.

`colorScheme` 파생색은 두 테마 모두 본문 기준(4.5:1)을 넉넉히 넘는다 —
`onSurface/surface` 16.30 · 14.32, `onSurfaceVariant/surface` 8.91 · 10.86,
`error/surface` 6.14 · 10.93. 수치는
`test/design_system/theme/app_theme_contrast_test.dart` 가 고정한다.

## 4. 커서 tie-break

`created_at` 이 **완전히 같은** 게시물 6건을 만들고(직접 UPDATE 로 값을 맞췄다)
`limit 2` 로 끝까지 읽었다.

```text
페이지 3개 · 읽은 건수 6 · 중복 0 · 누락 0
```

같은 timestamp 안에서는 `id desc` 가 순서를 정하므로 본문 번호 순서와 다르게 읽히는
것이 정상이다. 앱과 같은 방식(`limit + 1` 로 다음 페이지 존재를 판단하고, **잘라낸 뒤
실제로 돌려주는 마지막 항목**으로 다음 커서를 만든다)으로 돌렸다.

## 5. Patrol E2E — 처음으로 실제 실행

status 에 2026-08-24 부터 `- [ ] Patrol E2E 실행 (에뮬레이터 필요)` 로 남아 있던
항목이다. 에뮬레이터(`emulator-5554`, Medium_Phone)와 로컬 Supabase 위에서 돌렸다.

### 준비에서 걸린 것

- `patrol_cli` 가 설치돼 있지 않았다 (`dart pub global activate patrol_cli` → 4.7.0).
- **`patrol doctor` 가 통과해도 JDK 가 없으면 `patrol test` 가 죽는다** —
  `Failed to read Java version`. `doctor` 는 Java 를 보지 않는데 실제 실행은
  Gradle 을 거친다. macOS 에 별도 JDK 가 없으면 Android Studio 번들 JBR 을
  `JAVA_HOME` 으로 잡는다. [E2E 문서](../e2e.md)에 반영했다.

### 다국어가 E2E 를 깨뜨리고 있었다

첫 실행에서 `tap '회원가입'` 이 실패했다. 앱이 이제 기기 언어를 따라가는데
에뮬레이터가 `en-US` 라 화면이 **영어로** 떴고, 한국어를 단언하는 E2E 가 전부
어긋난 것이다. [언어 계획](../features/preferences/plan-language.md)의 "테스트 이행"
절은 위젯 테스트만 다루고 E2E 를 빠뜨렸다.

`launchApp()` 이 `SharedPreferences` 의 `language` 를 `ko` 로 심게 했다. 기기
locale 을 바꾸지 않는 이유는 어느 에뮬레이터에서도 같게 돌아야 해서다. 위젯 테스트
하니스가 `locale: Locale('ko')` 를 고정하는 것과 같은 결정이다.

### 결과

| 테스트 | 결과 |
|---|---|
| `auth_test` 가입 → 피드 → 로그아웃 → 재로그인 | ✅ (8s) |
| `post_test` 작성 → 피드 반영 → 삭제 | ✅ (9s) |
| `auth_test` 잘못된 비밀번호로는 로그인되지 않는다 | ⚠️ 아래 |

세 번째는 **자기 단계와 단언을 전부 통과하고도** 프로세스가 죽는다.

```text
✅ 1. waitUntilVisible signIn.email      ✅ 4. tap FilledButton
✅ 2. enterText signIn.email             ✅ 5. waitUntilVisible FailureText
✅ 3. enterText signIn.password
→ '_pendingExceptionDetails != null': A test overrode FlutterError.onError...
```

테스트 본문이 끝난 **뒤에** 로그인 실패 경로에서 비동기 오류가 하나 더 올라오는
모양이다. 화면 동작 자체는 정상이다 — 오류 문구가 뜨고 화면은 로그인에 남는다.

**CI 에 걸 때 주의.** 이 테스트는 실패로 **집계되지도 않는다.** 프로세스가 죽어
결과를 돌려주지 못하므로 Patrol 의 요약에서 성공에도 실패에도 들어가지 않는다.
종료 코드만 1 이다.

```text
✅ Successful: 2
❌ Failed: 0
exit=1
```

"Failed: 0" 을 보고 통과했다고 읽으면 안 된다. **종료 코드를 기준으로 판단한다.**

**원인은 못 짚었다.** 확인한 것만 적는다.

- 파일을 나눠 테스트를 하나씩 두어도 그대로다. Patrol 은 `patrol_test/` 전체를
  **하나의 번들**(`test_bundle.dart`)로 묶으므로, 파일을 갈라도 프로세스마다
  나머지를 건너뛰는 구조는 같다. (시험 삼아 나눠 보고 되돌렸다.)
- `patrol_cli` 4.7.0 이 최신이라 패키지(4.9.0)와의 버전 어긋남은 아니다.
- **이번 세션의 변경 때문은 아니다.** 로그인 경로에서 바뀐 것은
  `SupabaseAuthRepository` 의 `_guard` 가 공용 `guard` 로 바뀐 것뿐이고, `AuthException`
  은 `Failure` 가 아니라 두 구현의 동작이 같다. E2E 는 이번이 첫 실행이라 그동안
  드러날 기회가 없었을 뿐이다. (다만 이전 상태로 되돌려 재현해 보지는 않았다.)

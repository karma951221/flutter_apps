## 계획 밖에서 정한 것

| 판단 | 이유 |
|---|---|
| `SocialAvailability` 를 `getIt.init()` **전에** 싱글턴으로 넣고, `SupabaseClient` 는 getIt 에 등록하지 않는다. `RegisterModule` 이 이것을 보고 Supabase 저장소 또는 "쓸 수 없음" 저장소를 등록한다 | 초기화가 실패하면 클라이언트가 없다. 등록해 두면 처음 꺼내는 곳에서 앱이 죽는다(계획 결정 8 — 로컬 우선) |
| 로그인 뒤 돌아가기: push 로 열렸으면 **pop**, 바로 열렸으면 `from` 으로 **go**. `from` 은 `/` 로 시작하고 `//` 가 아닌 앱 안 경로만 믿는다 | 상세 · 모두의 산책에서 올라온 경우 pop 이 원래 화면 상태를 지킨다. 딥 링크로 바로 열린 경우만 `from` 이 필요하다. 바깥 주소로 튀지 않게 |
| `DogsRedirect` 가 `/sign-in` · `/community` 는 반려견 0마리여도 보낸다 | 둘 다 내 반려견과 무관하다. 막으면 반려견 없는 사용자가 둘러보기도 못 한다 |
| 가입 전에 닉네임을 미리 확인한다(대소문자 무시). 가입이 유일 위반으로 실패해도 같은 `nicknameTaken` | GoTrue 는 `profiles_nickname_lower_idx` 위반을 "Database error saving new user" 로만 돌려줘 원인을 모른다. 사전 확인 + 경합 시 변환으로 둘 다 덮는다 |
| 커서는 `created_at`(UTC, **마이크로초**) + `|` + `id` 를 base64url 로 감싼 불투명 문자열 | timestamptz 가 마이크로초라 밀리초로 자르면 같은 밀리초 안의 글이 건너뛰어지거나 겹친다 |
| 로그인이 필요한 동작의 실패 코드는 새로 만들지 않고 core 의 `FailureCode.authenticationRequired` 를 쓴다 | 트레이더와 뜻이 같다. 화면은 이 코드를 보고 로그인 화면을 연다 |
| 상세의 공유 항목은 `WalkDetailCubit` 이 아니라 따로 `WalkShareCubit` | 상세의 읽기 · 삭제 · 즐겨찾기는 로컬이고 이것만 서버를 부른다. 세션 변화 구독도 이 cubit 만 한다 |
| 쓰기는 **RPC 로만**(`publish_walk_post` · `unpublish_walk_post`). `walk_posts` 직접 insert · update · delete 는 GRANT 없음 | 리뷰 수정 `8f62152`. 입력 크기(반려견 1~10 · 메모 500 · 경로 64점)와 `author_id` 를 서버 한곳에서 지킨다 |
| 다시 공유하면 그 행을 되살리고 `created_at` 을 지금으로 올린다 | 공유 취소 뒤 다시 공유한 글이 목록 아래 묻히지 않게. 커서가 `created_at` 기준이라 새 글처럼 맨 위에 온다 |
| **시간 제한**: 모든 Supabase 요청에 10초(`TimeoutHttpClient`), postgrest 읽기 재시도는 1번 | 에뮬레이터 QA 에서 API 컨테이너를 멈추자 모두의 산책이 끝없이 돌았다. 기본 재시도 3번이면 최악 약 47초, 1번이면 약 21초. gotrue 가 감싼 요청 실패(상태 코드 없는 `AuthRetryableFetchException`)도 core 에서 network 로 분류한다 |
| **경로 감추기 규칙**: 누적 거리로 앞뒤 150 m 를 자른 뒤, 원래 출발점 · 도착점에서 직선 150 m 안인 점도 버린다. 2점 미만이면 경로 없이 | 누적만으로는 집 앞을 맴돌거나 중간에 집 앞을 다시 지나간 점이 남는다(최종 리뷰). 320 m 산책은 경로가 다 잘린다 — 의도한 결과 |
| **지운 산책의 공유**: 지우기 전에 공유 중(또는 여부를 모름)이고 로그인했으면 공유 취소를 먼저 보낸다. 실패해도 지우고 스낵바 `walkSocialUnshareOnDeleteFailed`. 로그인하지 않았으면 서버에 묻지 않는다 | 지운 산책이 모두의 산책에 남으면 안 된다. 그래도 기록은 기기의 것이라 서버 때문에 지우기를 막지 않는다. 순서는 상세 페이지가 정한다(`WalkShareCubit.unshareForDelete` → `WalkDetailCubit.delete`) |

## 리뷰에서 고친 것

| 리뷰 | 소견 | 고친 것 |
|---|---|---|
| 태스크 1 | 직접 update 로 남의 열을 바꿀 여지 · 좋아요 보임 · 입력 크기 · 다시 공유 순서 · 스크립트 빈틈 | RPC 로만 쓰기, 좋아요는 지운 글에 못 함, 크기 제한, 다시 공유 시 `created_at` 갱신, 스크립트 53/53 (`8f62152`) |
| 최종 1 | 요청에 시간 제한이 없어 서버가 멈추면 끝없이 돈다 | `TimeoutHttpClient` 10초 · 재시도 1번 · gotrue 네트워크 실패 분류 (`e4a005c`) |
| 최종 2 | 누적 거리만 자르면 집 앞을 오간 · 다시 지나간 점이 남고 주석의 "보수적" 이 틀렸다 | 출발 · 도착점 직선 150 m 안도 버림, 주석 고침, 테스트 교체 · 추가 |
| 최종 3 | 공유한 산책을 지워도 모두의 산책에 남는다 | 지우기 전 공유 취소(최선), 실패 스낵바 |
| 최종 4 | 더 읽기가 실패하면 스크롤마다 다시 요청하고 스낵바도 매번 | `loadMoreFailed` — 스크롤 재요청을 막고 목록 끝 "다시 시도" · 새로고침만 다시 연다. 스낵바는 실패당 한 번 |
| 최종 5 | 공유 · 공유 취소를 보내는 사이 로그인이 바뀌면 새 사용자의 상태를 덮어쓴다 | `toggle` 이 시작 때 epoch 를 잡고, 바뀌었으면 상태를 쓰지 않고 결과만 알린다 |
| 최종 6 | 공유 여부 읽기가 실패하면 "공유 안 됨" 으로 짐작해 "모두에게 공유" 를 보인다 | 실패면 항목을 숨기고, 다음 상세 열기 · 로그인 변화 때 다시 읽는다 |

## 넘기는 것

- 서버 오류 안내가 뭉뚱그려져 있다(`Failure.localizedMessage` 의 일반 문구) — 원인별 문구는 아직
- 새로고침과 좋아요가 겹치면 새로고침 결과가 낙관적 갱신을 덮을 수 있다(되돌리기는 같은 값일 때만)
- Supabase 를 쓸 수 없을 때도 `walkSocialLoadFailed` 문구를 다시 쓴다 — 전용 문구 없음
- 산책을 고쳐도 이미 공유한 글은 바뀌지 않는다 — 다시 공유하면 바뀐다
- 잘린 경로의 선 방향이 여전히 집 쪽을 가리킬 수 있다
- pawlog 에는 계정 삭제가 없다(트레이더와 같은 계정 — 삭제는 트레이더 앱에서)
- 초기화가 실패하면 앱을 다시 켤 때까지 모두의 산책은 쓸 수 없다

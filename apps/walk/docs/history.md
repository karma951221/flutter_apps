## 2026-09-27 — 설계 판단

### 걸음은 세지 않고 Health Connect 에서 읽는다

센서(`pedometer`)는 재부팅 후 누적값만 줘서 날짜별 기록을 앱이 백그라운드로 쌓아야 하고,
앱이 꺼진 구간은 비거나 뭉개진다. Health Connect 는 폰의 헬스 앱이 이미 날짜별로 기록해
두므로 앱 안에 저장소 · 백그라운드 작업이 없다. 대신 폰에 걸음을 기록하는 헬스 앱이 있어야 한다.

### 거리 · 칼로리는 계산하지 않는다

헬스 앱 숫자와 어긋나는 추정치를 보이지 않기로 했다(사용자 결정). 기록이 없으면 `–`.
키 · 몸무게 설정 화면도 그래서 없다. 칼로리는 활동 칼로리(`ACTIVE_ENERGY_BURNED`) —
총 칼로리는 기초대사량을 포함해 하루 2,000kcal 가 넘는다.

### 이름은 `health` 가 아니라 `walk`

의존하는 pub 패키지 이름이 `health` 라 앱 패키지 이름으로 쓸 수 없었다.

### 권한 정책은 공용 `packages/permission`

commute 와 같은 "이번 세션에 한 번 거부하면 다시 묻지 않기"를 `PermissionRequester` 로
공유한다. 시작할 때 `ensure()` 로 한 번 묻고, "권한 허용" 버튼은 `requestAgain()`.
Health Connect 는 두 번 거부하면 다이얼로그를 조용히 생략하고 그 사실을 알려주지 않아서
(`permanentlyDenied` 가 없다), 이번 세션에 거부했으면 "설정 열기"를 함께 보인다. 설정
화면을 여는 API 가 `health` 패키지에 없어 `MainActivity` 에 MethodChannel 하나를 뒀다.

### cubit 은 페이지가 만든다

`PeriodActivityCubit` 이 기간 종류(week/month)를 받아야 해서 셋 다 DI 에 등록하지 않고
페이지가 `getIt<WalkUseCase>()` 로 만든다. 선택한 막대는 차트 위젯의 상태다.

## 2026-09-27 — 최종 리뷰에서 고친 것

- **권한 확인 직렬화** — Health Connect 권한 화면이 앱을 pause/resume 시키면 복귀 확인이
  시작할 때의 요청이 끝나기 전에 돌아 두 번째 권한 창을 띄울 수 있었다. 플러그인은 대기
  중인 결과를 하나만 들어서 한쪽 Future 가 영영 끝나지 않을 수도 있다. 저장소가
  진행 중인 확인 Future 하나를 공유하게 했다.
- **기간 단위 조회** — 처음엔 하루 × 타입마다 한 번씩 물어 한 달 새로고침이 IPC 90여 번
  (복귀마다 오늘 · 주간 · 월간 세 번)이었다. Health Connect 읽기 쿼터를 넘기면 플러그인이
  오류를 삼켜 0보로 보이므로, 타입마다 기간 전체를 한 번에 묻고 하루 버킷으로 나눈다.
  interval 단위가 초라는 것은 플러그인 네이티브 소스(`Duration.ofSeconds`)로 확인했다.
- **없는 값이 0 으로 오는 것** — 플러그인은 기록 없는 버킷의 값을 0 으로 채운다. 기록 원본이
  빈 버킷은 건너뛰어 거리 · 칼로리가 `0.0 km` 가 아니라 `–` 로 보이게 했다.
- **막대 선택 갱신** — 같은 기간을 새로고침해도 선택 줄이 이전 걸음 수를 보이던 것을,
  선택을 날짜로 저장해 매번 새 값을 찾게 했다.
- **복귀 때 이중 읽기** — 복귀 중 권한이 막 허용되면 첫 읽기와 새로고침이 겹쳐 돌았다.
  이미 허용돼 있던 경우에만 새로고침한다.

## 2026-09-27 — 알람 · 설정 탭 설계 판단

### 새 앱이 아니라 walk 를 넓힌다

사용자가 만보기만 있으니 심심하다며 알람을 같은 앱에 넣기로 했다. 알람은 걸음과 연동하지 않는
진짜 기상 알람이다. 하단 탭 [알람 · 걷기 · 설정], 첫 탭은 걷기. 앞으로 생활 도구를 더 넣을 수 있어서
표시 이름을 **Life Tool** 로 바꿨다(폴더 · 패키지 · applicationId 는 `walk` 유지). 기존 걷기 코드는
`domain|data|presentation/walk/` 하위로 이동만 하는 커밋으로 먼저 옮겼다.

### 울림은 `alarm` 패키지, 반복은 14일 선예약

`alarm` 패키지가 정확한 예약 · 반복 재생 · 진동 · 전체 화면 알림 · 스누즈 버튼 · 잠금 화면 표시 ·
재부팅 복원을 준다. `flutter_local_notifications` 는 알림 채널 소리라 기상용으로 약하고, 네이티브
직접 구현은 크다. 패키지는 1회성만 알고, 앱이 꺼진 채 알림에서 끄면 Dart 가 돌지 않아 "울릴 때 다음
회차 예약"은 빠질 수 있다. 그래서 앞으로 14일 안의 회차를 모두 걸어 두고 앱이 열릴 때마다 채운다
(`AlarmUseCase.sync`, 멱등). 패키지 id 는 `alarmId * 100 + 날짜 index` — 목록 순번으로 하면 오늘
회차가 지나는 순간 index 가 밀려 스누즈를 덮어쓴다.

### 알람 정의는 벽시계 시각이다(UTC 아님)

"7시에 깨워줘"는 지금 있는 곳의 7시다. UTC 로 저장하면 여행지에서 새벽에 울린다. 시 · 분 · 요일을
저장하고, 1회성의 `oneShotAt` 도 오프셋 없는 로컬 ISO 문자열이다. 서머타임은 날짜를
`DateTime(y, m, d + n, h, mi)` 생성자로 만들어 기기 규칙을 따른다.

### 남은 시간은 예약된 것을 기준으로 한다(2026-09-29)

기획 자체 리뷰에서 "반복 규칙으로 계산"하면 스누즈 중인 1회성이 카드에서 사라지는 것을 찾았다
(sync 가 원래 시각이 지난 1회성을 끄므로). 그래서 `nextRings()` 는 스케줄러에 실제로 걸린 예약에서
알람별 가장 이른 시각을 고르고, 1회성은 예약(스누즈 포함)이 하나도 남지 않았을 때만 끈다. 권한이 없어
예약이 안 걸리면 울리지 않을 알람을 울릴 것처럼 보이지 않는다는 장점도 있다.

### 시간대 변경은 수신기 + 엔진 재사용(2026-09-30)

14일 치 예약은 AlarmManager 에 절대 시각으로 들어가 시간대가 바뀌면 옛 시간대의 7시에 울린다.
`TIMEZONE_CHANGED` 수신기가 앱이 떠 있으면 메인 엔진에 `resync` 를, 아니면 헤드리스 엔진으로
`Alarm.init` → `sync` 를 돌린다. 한 프로세스에 엔진 둘이면 패키지의 네이티브 싱글턴이 엉킬 수 있어
떠 있을 때는 새 엔진을 띄우지 않는다. 구현 중 **"복귀 때 sync 가 바로잡는다"는 설계 전제가 틀렸음**을
에뮬레이터에서 찾았다 — 패키지가 예약 시각을 오프셋 없이 저장했다가 현재 시간대로 다시 읽어 `sync`
에게는 늘 맞아 보인다. 메인 엔진 경로는 `timeZoneChanged()` = 저장된 예약 전체 재설정(`checkAlarm`)
→ `sync` 로 바꿨다.

## 알람 — 확인하며 고친 것

에뮬레이터 확인(2026-09-27 · 09-30)과 스펙 기준 테스트 보강(2026-09-30, 빈 곳 25개를 기능별
서브에이전트 4개가 채움 — 먼저 실패한 테스트 = 버그)에서 고친 것.

- **끄기 직후 1회성 스위치가 켜진 채** — 패키지 `stop` 이 저장소에서 지우고 울림 스트림을 갱신하면
  리스너가 울림 화면을 걷고 목록이 다시 읽혔는데, 그 읽기가 `stop` 의 sync 보다 먼저 돌았다. use case 의
  읽기(`list` · `find` · `nextRings`)도 직렬 줄을 타게 했다.
- **1회성이 울리는 순간 꺼짐** — 막 된 예약(울림으로 잡히기 전)이 "미래도 울림도 아님"으로 판정돼
  울리는 중에 스위치가 꺼졌다. 스누즈 보존 창과 같은 유예(`dueGrace`)를 남은 예약으로 센다.
- **꺼진 알람의 5분 안 예약이 울림** — 스누즈 보존 창이 꺼진 알람의 예약도 남겼다. 켜진 알람만 남긴다.
  꺼진 · 지워진 알람의 울림을 스누즈하면 다시 걸지 않고 멈춘다.
- **알림에서 끈 뒤 sync 없음 · sync 실패 시 목록 미갱신** — 셸의 `didPopNext` 가 목록만 읽었고,
  시작/복귀 새로고침이 sync 오류를 다시 던져 목록을 읽지 않았다. 권한 → sync → 목록을 늘 끝까지 돈다.
- **권한 확인 예외 → 저장 실패로 보이고 다시 저장하면 알람 둘** — 저장 뒤의 권한 확인 예외를 삼킨다.
- **목록 읽기 실패 시 무한 로딩 · 저장+재읽기 실패 시 낙관적 상태 잔류** — 목록에 failure 상태와
  다시 시도를 뒀다.
- **깨진 prefs 로 알람 탭 먹통 · 테마 prefs 타입 오류로 시작 시 크래시** — 깨진 항목만 건너뛰고 원본은
  `walk.alarms.corrupt` 에 백업, 테마는 모르는 값이면 시스템.
- **남은 시간 1초 미만 자투리 버림** — `inSeconds` 로 올림해 1분 적게 보였다. 마이크로초로 올림한다.
- **요일 토글이 두 줄** — `Wrap` 대신 같은 폭 원형 토글 7개를 한 줄에 둔다(320dp 확인).

## 2026-10-03 — 시각 · 인터랙션 강화

설계: [시각 · 인터랙션 강화](../../../docs/superpowers/specs/2026-10-03-walk-visual-refresh-design.md). 계획 문서의 모호한 곳은 아래처럼 정했다.

### 판단

- **R1 목표 문구** — `walkGoalOf` 에 이미 포맷된 걸음 수를 넘겨 `목표 10,000 걸음` 으로 쓴다(스펙은 `목표 10,000`).
  앱의 걸음 단위 표기와 맞춘다.
- **R2 → R6 링 트랙** — 처음엔 트랙을 `surface` 로 했지만 다크 카드에서 검은 도넛처럼 보여
  `onPrimaryContainer` 12% 로 바꿨다(기기 확인에서 발견). 진행은 `primary`.
- **R3 모서리** — `AppRadius` 에 `sm` · `lg` 만 있어 카드 · 스켈레톤은 `lgAll`, 작은 타일 · 막대는 `smAll`.
- **R4 요약 타일** — `GridView` 대신 `Expanded` 타일 두 줄(`Row` 둘). 높이를 내용에 맡긴다.
- **R5 스켈레톤** — 기간 영역 로딩 자리는 `period_section.dart` 를 가진 그래프 단계가 맡는다.
- **오늘 막대 테두리** — 미달이면 `primary`, 달성해 막대가 `primary` 로 차면 테두리가 묻히므로 `onPrimaryContainer`.
- **셸 페이드 생략** — 탭 전환 페이드는 `AnimatedSwitcher` 가 탭 상태를 버리므로 넣지 않고 `IndexedStack` 을 그대로 둔다.
- **보폭 추정** — 남은 거리는 새로 입력받지 않고 오늘 거리 ÷ 오늘 걸음으로 추정한다. 오늘 거리가 없거나 걸음이 0이면 남은 걸음만 보인다.

### 리뷰 · 기기에서 고친 것

- **축하는 날짜 기준 1회** — 처음엔 화면 상태로 막아 재진입 · 재시도 · 자정 넘김에서 되풀이하거나 놓쳤다.
  `goalCelebratedOn`(날짜)과 오늘 날짜를 비교해 연출 키를 날짜로 잡았다. 실패 뒤 재시도 · 어제 달성한
  화면에 오늘 값이 와도 맞게 돈다.
- **목표 라벨이 막대를 가림** — 목표선 라벨을 오른쪽 거터로 빼고 막대 영역과 분리했다. 마지막 막대와 라벨이
  겹치지 않고 목표 높이의 마지막 막대도 눌린다.
- **달성한 오늘의 테두리** — 위 오늘 막대 테두리 판단.
- **링 트랙 색** — 위 R6.
- **링 탭 시 카드 높이가 줄어 아래가 튐** — 남은 걸음 줄이 지표 줄보다 낮았다. 아래 줄 높이를 고정했다.
- **목표를 낮추면 옛 목표가 다시 저장됨** — `PrefsSettingsRepository.save` 가 키마다 await 하며 쓰는 사이에
  걷기 탭의 축하 판정이 `load()` 해 새 테마 + 옛 목표 스냅샷을 나중에 써 버렸다. 모든 키 쓰기를 await 전에
  시작해(`Future.wait`) 캐시가 곧바로 전체 스냅샷을 갖게 했다.
- **숨은 걷기 탭이 축하를 써 버림** — `IndexedStack` 이 숨은 탭도 살려 두어, 설정 탭에서 목표를 낮추면 화면 밖에서
  연출 · 진동하고 오늘 축하 날짜를 저장했다. 셸이 `WalkHomePage(active:)` 로 보이는지 알려 주고, 숨은 동안은
  판정하지 않다가 보이게 될 때 지금 값과 목표로 다시 판정한다.

### 2026-10-13 — 일기

[설계](../../../docs/superpowers/specs/2026-10-10-walk-diary-design.md) · [실행 계획](../../../docs/superpowers/plans/2026-10-10-walk-diary.md).
설계의 결정 기록(§3)은 그대로 두고, 여기에는 스파이크가 바꾼 것과 구현 · 리뷰 중 정한 것(R1~R29) 가운데
동작이 달라진 것만 남긴다.

### 스파이크가 바꾼 것(T1, 에뮬레이터)

- **사진 긴 변 1600** — `flutter_image_compress` 의 `minWidth`/`minHeight` 는 **짧은 변**을 맞춘다(4000×3000 → 2133×1600).
  원본 크기를 먼저 읽어 긴 변이 1600 이 되도록 비율대로 목표를 준다(`photoTargetSize`). 키우지는 않는다(R3).
- **영상** — `video_compress` 를 쓴다(`light_compressor` 불필요). `Res1280x720Quality` 는 긴 변 1280 기준이라 720p 를 만족한다.
  결과 · 썸네일이 외부 앱 폴더에 생겨 앱 폴더로 옮기고 `deleteAllCache()` 로 비운다(R3). 동시에 두 번 부르면 `StateError` 라
  처리기 안에서 한 줄로 세우고(`24e36ff` — 동시 압축 중 `deleteAllCache` 가 앞 결과를 지우던 것), 작성 화면도 하나씩 가져온다(R10).
- **폰 인증** — `local_auth` 3.x 는 취소를 `false` 가 아니라 `LocalAuthException(userCanceled)` 로 던진다. 예외 코드를
  성공 · 취소 · 화면 잠금 없음 · 폰 쪽 잠김으로 나눠, 취소는 실패로 치지 않는다(R4). 안드로이드는 틀린 기기 PIN 을 시스템 화면이
  흡수하고 끝에 `lockedOut` 으로 끝나므로 **`lockedOut` 도 24시간 차단**이다(R15).
- **장소 이름은 조건부 채택** — `geocoding` 5.x 는 에뮬레이터에서 15분 넘게 응답이 없었다(오류도 없음). 생성자 `locale` 이 버려져
  호출마다 넘기고, 8초 `.timeout` 으로 감싼다(R5). 성공한 응답을 아직 못 봐서 `Placemark` 의 어느 필드가 채워지는지 모른다 —
  이름은 `locality` · `subLocality` · `thoroughfare` 중 앞의 둘로 만들고 실제 폰에서 확인한다.

### 구현 · 리뷰에서 정한 것

- **빈 검색** — 글 · 스토리는 빈 입력이면 조회하지 않는다(빈 LIKE 가 모든 기록을 돌려주므로). 태그 · 장소는 입력 전 상위 추천(R6 · R9).
- **저장소 경계** — 기본 스토리는 닫을 수 없고, 옮기기는 `updatedAt` 을 바꾸지 않는다(R7). 영구 삭제는 이미 휴지통에 있는 기록만,
  다시 휴지통에 넣으면 처음 `deletedAt` 을 지킨다(R8).
- **고아 청소** — 살아 있는 · 휴지통 기록의 원본과 썸네일을 모두 남기고, 저장 중인 사본을 지우지 않게 `media/` 도 24시간 안에 바뀐
  파일은 남긴다(R11, `72a6daf`). 앱 시작 때 한 번, 탭 정리(`maintain`)는 기다리지 않고 오류를 삼킨다(R14).
- **정리가 오프라인에서 멈춤** — 장소 이름 찾기가 오프라인이면 남은 기록은 묻지 않고 멈추고, 겹쳐 부르면 진행 중인 작업을 기다린다
  (R13, `42a26e9`). 최종 리뷰에서 결과를 `named` · `noName` · `offline` 셋으로 나눴다 — 이름을 붙일 수 없는 좌표 하나가 뒤의 기록을
  영영 막지 않도록 `noName` 은 건너뛰고, 한 번에 20곳까지만 묻는다(`5d5e174`).
- **처음 보기 모드는 줄글**(설계에 없음, R12). 타임라인과 모아보기는 같은 보기 모드를 기억한다(R26).
- **잠금 설정을 바꾸면 게이트를 다시 맞춘다** — 설정 화면이 `true` 로 닫히면 `DiaryLockCubit.configChanged()`(R16, `3f3b9ba`).
  잠금이 꺼져 있으면 다시 잠기는 시간 행은 누를 수 없다(R27).
- **스토리 바 표지** — 지정한 표지 → 최신 기록의 첫 사진 → 영상 썸네일 → 이니셜. 표지 시트는 영상(썸네일)도 고를 수 있다(R17 · R24).
- **탭 머리** — 스토리 이름 · 기간 줄과 보기 토글, `＋`, ⋮(스토리 관리 · 휴지통), 🔍 의 자리를 정했다(R18).
- **릴스** — 설계의 "전체 화면"은 일기 탭 몸통을 꽉 채우는 것으로 하고(하단 탭은 남음) 머리 · 토글 · 🔍 · ⋮ 를 반투명하게 위에 얹는다
  (R19 · R25). 소리는 켠 채 재생한다(R20). 가려진 탭(`15e6532`) · 위에 얹힌 화면이나 시트(`7d66485`)에서는 멈춘다. 다시 잠겼다가
  위 화면의 잠금에서 풀리면 릴스가 새로 만들어지며 "안 가려짐"으로 시작해 상세 화면 밑에서 소리가 났다 — 구독할 때 지금 가려졌는지로
  시작한다(R29, `ff4877e`).
- **수정 중 시각 변경** — 새 기록만 지금 위치를 뺀다. 고치는 기록은 저장된 위치를 그대로 둔다(R21). 시각 비교는 분 단위(`697ba9a`).
- **일기 화면의 잠금** — 셸 위로 여는 일기 화면은 모두 `pushDiaryRoute` 로 `DiaryLockGate` 를 씌운다. 작성 cubit 은 게이트 바깥에 있어
  다시 잠겨도 쓰던 글이 메모리에 남는다(R22). 잠금 화면에서 뒤로 가기는 무시한다(`d08939b`).
- **닫힌 스토리로 옮기기** — 지난 여행 정리를 위해 허용한다. 닫힌 스토리에 **새 기록**만 거절한다. 다시 열었다 닫는 세 번의 쓰기 대신
  한 번에 옮긴다(R23, `3ed6cd4`).
- **잠긴 동안 내용이 새지 않게** — 게이트 하나가 잠기는 순간 일기 위의 팝업(시트 · 다이얼로그 · 메뉴)을 닫는다. 보이지 않는 일기 탭은
  다른 탭의 팝업을 닫지 않는다. 정리는 풀려 있을 때만 하고, 설정의 휴지통 기간 · 다시 잠기는 시간도 잠긴 동안 막는다
  — 비밀 없이 휴지통을 비우는 길을 막는다(R28, `d08939b`).

## 2026-10-05 — 알람 작은 개선

### 볼륨 패널을 끈다

울리기 시작할 때 · 끝날 때 시스템 볼륨 패널이 떴다. 패키지 `VolumeSettings.fade` 의 `showSystemUI`
기본값이 `true` 라 볼륨을 올리고 되돌릴 때 `FLAG_SHOW_UI` 를 붙였다. `false` 로 넘긴다(`9c35d66`).

### 헤드업 알림은 그대로 둔다

앱이 앞에 있을 때 울리면 리스너가 울림 화면을 띄우고, 그 위에 헤드업 알림이 겹친다. 알림은 패키지
`AlarmService` 가 울리는 동안 `startForeground` 로 거는 알림이다. 채널이 `IMPORTANCE_HIGH` 이고 전체 화면
인텐트가 붙어 있어, 안드로이드는 화면이 켜져 있고 잠금이 풀려 있으면 전체 화면 대신 고정 헤드업으로
보인다. 포그라운드 서비스 알림은 앱이 `cancel` 할 수 없고, 앱이 앞에 있는지는 시스템이 따지지 않는다.

본 대안 — 앱이 앞이면 울림 화면을 띄우지 않고 헤드업만 보이기, 울림 화면이 뜨면 네이티브에서 같은 id 를
조용한 채널로 다시 올려 헤드업을 걷기(패키지 내부 동작에 기대는 우회라 깨지기 쉽다). 두 화면 모두
같은 [알람 끄기] · [5분 뒤 다시 울림] 이라 동작은 맞으므로 그대로 두기로 했다(사용자 결정). 실제 폰에서
써 보고 거슬리면 다시 본다.

## 2026-10-21~22 — 통근

설계: [통근 ETA](../../../docs/superpowers/specs/2026-10-21-commute-eta-design.md). 키가 아직 없어 실제 API 응답은 보지 못했다 — 아래는 문서 기준으로 짠 부분이다.

### 판단

- 다섯째 탭으로 둔다. 출근/퇴근 방향 하나를 고르면 집 ↔ 회사 지하철 경로(ODsay)와 첫 승차역의 실시간 도착(서울 열린데이터광장)을 합쳐 "탄다 · 서두르면 · 놓침"과 도착 예상 시각을 보인다.
- 경로를 고르면 선호를 저장해 탭에 다시 들어와도 같은 경로가 기본이다. 첫 승차역이 같은 경로로 바꿀 땐 실시간을 다시 부르지 않고 판단 · 예상만 다시 계산한다. 이때 "지금"은 새 시각이 아니라 조회 시각이다(분 단위가 조회 때와 어긋나지 않게).
- 키는 `--dart-define-from-file` 로 주입하고 저장소에 넣지 않는다(`config/commute_keys.example.json` 만 커밋). 키가 없으면 화면이 안내만 보인다.
- 서버 오류 · 네트워크 오류 · 경로 없음 · 실시간 없음(경로 · 예상만)을 `CommuteFailure` 로 나눠 화면 상태가 갈린다.

### 리뷰에서 고친 것

- 노선 코드 매핑(`seoulSubwayIdFor` · `normalizeStationName`)이 도메인 유스케이스에서 data 를 불러 계층 방향을 거슬렀다 — `subway_line_codes.dart` 를 `lib/domain/commute/` 로 옮기고 data 가 도메인을 보게 했다(`9b2ded2`).
- 방향을 연달아 바꾸면 옛 요청 결과가 새 방향 화면을 덮어썼다 — 응답 때 요청 방향을 확인해 버린다. 현재 위치 조회의 위치 예외도 처리했다(`ca4bef0`).
- 위치 실패 스낵바가 모달 시트 뒤(루트 메신저)에 그려져 보이지 않았다 — 시트 안에 안내를 보이고 검색 상태를 정리했다(`4014012`). 테스트는 시트 안 표시를 직접 확인한다.
- 영어 복수형("1 transfers" 등)과 "실시간은 ok 인데 도착이 비어 있을 때 아무것도 안 보이는" 경우를 고쳤다(T8).
- 작업 중 `dart format` 이 `apps/walk` 전체를 건드려 무관한 140개 파일이 바뀐 적이 있다 — 되돌리고(`git checkout -- apps/walk`) 그 태스크 파일만 다시 했다.

### 알려진 한계

- 실제 응답 확인 전이라 `barvlDt` · `ordkey` · `updnLine` ↔ `wayCode` · `subwayCode` 매핑은 추정이다. ODsay 키가 Android 앱에서 되는지도 미확인(안 되면 카카오 `publictraffic` 로 교체).
- 서버 5xx 가 JSON 본문 없이 오거나 모든 경로가 깨지면 서버 오류 대신 빈 결과 · 경로 없음으로 보일 수 있다. `HandshakeException` 은 네트워크 오류로 잡히지 않는다.
- 주소 검색 오류가 "결과 없음"으로 조용히 보인다. 주소 검색 최악 약 16초.
- 같은 승차역 경로로 바꿀 때 실시간 조회가 실패한 상태면 그 실패를 유지한다(다시 조회로 복구).
- 탭 시계는 앱이 일시정지된 동안에도 돈다(setState 뿐). 시각은 `HH:mm` 고정 표기.

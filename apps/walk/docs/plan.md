## 목적

생활에 필요한 작은 도구를 하나의 앱에 모은다. 표시 이름은 **Life Tool**(폴더 · 패키지는 `walk`).
지금 도구는 여섯이다.

- **걷기** — 오늘 걸음을 앱을 열자마자 보고, 이번 주 · 이번 달을 막대그래프로 본다. 걸음은 앱이
  세지 않고 Health Connect 에서 읽는다.
- **알람** — 기상용 알람. 걸음과 연동하지 않는다. 잠금 화면 위로 울리고, 재부팅 · 시간대 변경 뒤에도
  제 시각에 울린다.
- **일기** — 짧은 기록을 스토리로 묶어 쓰는 개인 일기장. 알람 · 걷기와 연동하지 않는다. 사진 · 짧은 영상 ·
  위치 · 해시태그를 붙이고 스토리 동그라미 · 피드 · 뷰어로 돌아본다. 일기 탭만 PIN · 패턴으로 잠근다.
- **물어보기** — 내 일기 · 걸음 · 기상 기록에 대고 말로 묻는 채팅(Claude · GPT API). 통근 탭 자리를 대신한다.
  통근 코드(`lib/*/commute`)와 테스트는 남아 있지만 화면에서 닿지 않는다.
- **지도** — 앱이 꺼져 있어도 이 폰에만 위치 점을 쌓고(상시 알림이 있는 포그라운드 서비스), 하루 · 한 달 · 스토리 기간으로
  머문 곳 · 이동선 · 자주 간 곳과 위치가 붙은 일기를 지도에서 돌아본다. 서버로 보내지 않는다.
- **날씨** — 지금 위치의 현재 날씨 · 시간별 24칸 · 일별 7일 · "비 언제 와" 요약. Open-Meteo(키 없음) 예보를 받고 마지막 성공을 캐시한다. 위치는 날씨 전용으로 따로 읽는다(일기 장소 태그와 무관). 설계: [날씨](../../../docs/superpowers/specs/2026-11-14-walk-weather-design.md).

안드로이드만, 로그인 · 백엔드 없음.

## 화면

하단 탭 셸 `MainShellPage` — [도구 · 일기 · 물어보기], 첫 탭은 **도구**(실사용에서 가장 자주 연다, 2026-11-14 변경). 도구 탭(`ToolsTab`)은 앱바 아래 상단 탭 [알람 · 걷기 · 지도 · 날씨]를 눌러서만 바꾼다(걷기 화면 안에 오늘 · 기록 탭이 있어 밀기와 겹친다). 설정 탭은 없다 — 각 화면 ⋮ 의 "○○ 설정"(`FeatureMenu`)과 "앱 설정"(잠금 · 테마 · 기능별 설정)으로 나눴다. 일기 앱바는 스크롤에 따라 숨는다. 탭마다 자기 `Scaffold` 를 두고
`IndexedStack` 으로 탭을 오가도 상태가 남는다. 라우터 없음(푸시 화면은 알람 편집 · 울림 · 울림 기록과 일기 화면들 ·
잠금 설정 · ⋮ 가 여는 설정 화면들 — 알람 · 걷기 · 일기 · 물어보기 설정과 앱 설정). 일기 화면은 모두 `pushDiaryRoute` 로 열어 셸의 일기 잠금 게이트를 함께 씌운다.

### 걷기

- 접근 상태(Health Connect 없음 · 업데이트 필요 · 권한 없음)는 탭 전체를 `AppPlaceholder` 로 대신하고
  설치 · 권한 요청 버튼을 준다.
- 앱 열 때 · 백그라운드 복귀 때 · 당겨서 새로고침 때 다시 읽는다.
- 걸음만 읽는다. 거리 · 칼로리는 실제 폰에서 오지 않아 뺐다(2026-10-21).
- **하루 목표**(기본 10,000, 설정에서 변경)는 앱 전역 `StepGoalCubit` 이 들고 `AppSettings` 에 저장한다.
  오늘 카드의 링은 목표 대비 비율을 채우고(넘치면 꽉 찬 채), 아래 줄은 남은(넘친) 걸음이다.
- 목표를 채우면 배지 · 초과 걸음 문구와 함께 축하 연출(햅틱 포함)을 **날짜당 한 번** 한다.
  본 날짜는 `AppSettings` 에 남겨 다시 열어도 되풀이하지 않는다.
- 그래프는 목표선을 긋고 높이 기준을 `max(최댓값, 목표)` 로 한다. 달성한 날은 진한 막대.
  값을 읽는 동안 오늘 카드와 기간 영역은 스켈레톤을 보인다. 애니메이션 끄기면 연출을 생략한다.

### 알람

- 알람 정의는 벽시계 시각(시 · 분 · 반복 요일)으로 저장한다. 반복이 없으면 1회성.
- 앞으로 **14일 안의 회차를 미리 예약**하고, 앱 시작 · 복귀 · 저장/삭제/토글 · 울림 뒤에 다시 맞춘다
  (`sync`). 그래서 앱을 14일 넘게 열지 않으면 반복 알람이 멈출 수 있다(앱 안에 따로 안내하지 않는다).
- 남은 시간은 **실제로 예약된 다음 울림** 기준이다(스누즈 포함). 분 단위, 올림. 매분 0초에 갱신.
- 울림:
  - 화면 꺼짐 · 잠금 → 전체 화면 울림 화면
  - 폰 사용 중(다른 앱이 앞) → 상단 헤드업 알림에 같은 두 버튼
  - 이 앱이 앞 → 앱 안에서 울림 화면
- 스누즈는 5분 고정. 울리는 중 앱을 최근 앱에서 밀어도 계속 울린다.
- 재부팅 뒤에는 패키지가 예약을 되살린다. 시간대가 바뀌면 수신기가 예약을 새 시간대의 같은 벽시계
  시각으로 옮긴다.
- 권한은 알람을 처음 저장/켤 때 묻는다(알림 → 정확한 알람). 거부해도 저장하고 경고 배너를 둔다.
- 저장값이 깨졌으면 읽을 수 있는 알람만 살리고 원본은 백업 키에 남긴다.
- 요약 카드는 초록 컨테이너 색, 꺼진 알람 행은 흐린 글자, 스위치에 햅틱. 울림 화면은 시각 뒤로 파동이 퍼진다(애니메이션 끄기면 정지).

### 일기

- 기록은 반드시 **스토리** 하나에 속한다. 기본 스토리 "일상"은 앱이 만들고 닫기 · 삭제할 수 없다(이름 · 표지만).
  스토리는 열린 것 여럿이 동시에 있을 수 있고, 닫은 것은 보관함으로 가며 다시 열 수 있다.
- 일기 탭은 스토리 동그라미 줄과 모든 스토리의 기록 피드 하나다(보기 모드 · "고른 스토리" 없음). 동그라미를 누르면 인스타식 스토리 뷰어가 열린다.
  진행 중 스토리는 마지막 날부터, 닫힌 스토리는 첫날부터 보고, 하루가 막대 하나다. 피드 영상은 자동재생하지 않는다. 화면 구성 · 판단은 [화면 재기획 설계](../../../docs/superpowers/specs/2026-10-21-walk-diary-story-redesign-design.md) 와 [기록](history.md#2026-10-21--일기-화면-재기획).
- 작성: 기본 스토리는 열린 것 중 최근에 기록을 넣은 것. 시각은 미래 불가, 과거로 바꾸면 현재 위치를 빼고 장소 이름을
  직접 넣으며 그 시각이 기간에 드는 열린 스토리를 제안한다. 수정 중 시각을 바꿔도 저장된 위치는 그대로다.
  닫힌 스토리에 새 기록은 못 넣지만, 기존 기록을 닫힌 스토리로 옮길 수는 있다.
- 미디어: 고르는 즉시 임시 폴더에 압축 사본(사진 긴 변 1600px · JPEG 85 · EXIF 제거, 영상 최대 720p · 30초 이하 ·
  썸네일)을 만들고 저장할 때 정식 폴더로 옮긴다. 원본은 건드리지 않는다. 한 번에 하나씩 가져온다.
- 위치: 작성 화면을 열 때 현재 위치를 구해 장소 이름(`locality` · `subLocality` · `thoroughfare` 중 비지 않은 앞의 둘)을 붙인다. 권한 거부 · 실패면 위치 없음.
  이름을 못 얻으면(오프라인) 좌표만 저장하고, 탭에 들어올 때 정리(`maintain`)가 한 번에 20곳까지 다시 묻는다.
- 태그: 칩 입력. `#` · 공백 · 대소문자만 다른 입력은 하나다(최대 30자).
- 검색: 300ms 디바운스. 글은 부분 일치(`%` · `_` · `\` 는 글자 그대로), 스토리 · 태그 · 장소는 추천과 기록 수.
  빈 입력이면 글 · 스토리는 조회하지 않고, 태그 · 장소는 상위 추천을 보인다.
- 삭제는 휴지통으로. 보관 기간(1 · 7(기본) · 30일 · 안 함)이 지나면 탭 정리 때 미디어 파일 · 태그 연결까지 지운다.
  스토리를 지우면 그 기록은 휴지통으로 가고, 복원하면 "일상"으로 돌아온다. 앱 시작 때 DB 에 없는 고아 파일을 치운다(24시간 유예).

### 지도 · 위치 기록

설계: [위치 기록 · 지도](../../../docs/superpowers/specs/2026-11-08-walk-location-map-design.md)(구현 중 정한 것은 맨 아래 절).

- **기록은 네이티브 포그라운드 서비스**(`LocationRecordService`, Fused Location)가 한다 — 앱을 밀어 닫아도 · 재부팅해도 이어진다(`BOOT_COMPLETED` 리시버). 점은 앱 전용 SQLite inbox(`location_inbox.db`)에 쌓이고, 앱이 앞에 올 때 · 지도를 열 때 Dart 가 수거해 drift(`location_points`)로 옮기고 inbox 에서 지운다(멱등).
- **평소**: 균형 정확도 · 3분 · 50m · 최대 지연 10분. **촘촘**(지도 칩 · 설정): 높은 정확도 · 5초 · 10m. 평소 모드는 신체 활동 권한이 있으면 정지 감지(`STILL` 진입 → 점 하나 + 요청 멈춤, 이탈 → 재개 + 즉시 한 점)로 배터리를 아낀다. 권한이 없으면 정지 감지 없이 3분 간격.
- **머문 곳 · 선 · 자주 간 곳은 저장하지 않고 계산한다**(도메인 순수 함수): 반경 100m 안 10분 이상 = 머문 곳, 점 사이 30분 넘게 비면 선을 끊되 `stillStart` 뒤가 100m 안이면 그 사이 전체가 머문 곳. 한 달 선은 단순화한다. 하루 경계는 기기 현지 자정, 점 시각은 UTC 저장.
- **켜기 흐름**: 앱 사용 중 위치 → 항상 허용(시스템 설정 화면, 이유를 먼저 설명) → 신체 활동 → 알림. 항상 허용이 없으면 켜지 않고 설정 행에 남긴다. 신체 활동 · 알림 거부는 기록을 막지 않는다. 켜 둔 사이 항상 허용을 뺏기면 `blocked` 로 칩이 "기록 꺼짐 · 권한 필요".
- 지도 콘텐츠 · 지도 설정은 **일기 잠금 아래**(`DiaryLockGate` · `pushDiaryRoute`). 머문 곳 이름은 하루 보기에서만 `PlaceNamer` 로 붙이고 격자 캐시(`place_names`)에 둔다. 위치 기록은 이 폰에만 — 서버 전송 없음.
- 타일은 OSM(`flutter_map`), User-Agent 에 패키지 이름. 문제가 되면 `TileProvider` 한 곳만 바꾼다.

### 일기 잠금

- 설정에서 켠다. 폰에 화면 잠금이 있어야 한다. PIN 4자리 또는 패턴(점 4개 이상, 건너뛴 가운데 점 자동 포함)을 두 번 입력.
  비밀은 랜덤 salt + SHA-256 10,000번 반복 해시로만 남는다.
- 앱 시작 때 잠김. 백그라운드에서 다시 잠기는 시간(즉시 · 30초 · 1분(기본) · 5분)을 넘기고 돌아오면 다시 잠근다.
  사진 · 영상을 고르러 나간 동안은 세지 않는다. 시계가 거꾸로 가면 잠근다.
- 잠긴 동안 기록 위젯은 트리에 없다. 다시 잠기면 일기 위의 시트 · 다이얼로그를 닫고, 쓰던 글은 메모리에 남아 풀면 돌아온다.
  잠긴 동안에는 정리 · 휴지통 기간 · 다시 잠기는 시간 바꾸기를 막는다.
- 5번 틀리면 30초 차단. "잊어버렸어요" → 폰 인증 성공이면 새 비밀 등록, 실패(폰 쪽 잠김 포함)면 24시간 모든 해제 시도 차단.
  인증 창을 닫는 것은 실패가 아니다. 실패 횟수 · 차단은 재시작 뒤에도 남는다.
- 알람 울림 화면은 일기 잠금과 무관하게 뜬다.

### 물어보기 (채팅)

설계 판단은 [물어보기 설계](../../../docs/superpowers/specs/2026-10-27-walk-life-chat-design.md), 구현 기록은 [기록](history.md#2026-10-27--물어보기-채팅).

- 모델 계약은 벤더 중립(`ChatMessage` · `ModelEvent` · `VendorTurnState`)이고 Anthropic 모양은 `AnthropicChatModel` 안에만 있다.
- **벤더는 Claude · GPT 중 하나** — 물어보기 설정에서 바꾸면 기존 키를 교체하고 전송 동의를 다시 받는다(대화는 이어 간다). **모델은 벤더 목록에서 고른다** — 앱은 모델 id 를 고정하지 않고 추천 계열(Claude Sonnet · GPT 플래그십 별칭)의 최신을 기본으로 쓰며, 목록은 하루 1회 갱신한다. 물어보기 탭의 **모델 칩**에서 고르고(NEW · 새 모델 점), **빠른 출력**은 지원 모델에서만 켜며 요금 안내가 붙는다(지원 표 확인 전엔 스위치가 숨겨져 있다). OpenAI 는 `store: false` 로 서버 저장을 끈다. effort low, 스트리밍. 대화는 **보이는 글만**(질문 · 답 글 · 근거 일기 id · 멈춤 표시) 턴이 끝날 때마다 저장한다 — 끝난 턴과 글이 온 멈춘 턴만, 실패한 턴은 제외. 저장 목록에서 열어 이어갈 수 있고(최근 20턴, 글만) **임시 대화**는 아무것도 저장하지 않는다. 설계는 [대화 기록 · 위키 기획](../../../docs/superpowers/specs/2026-11-01-walk-chat-history-wiki.md).
- 답하려고 **도구 5개**를 쓴다: `search_diary`(기간 · 글 검색) · `view_entry_photos`(기록 사진 보기) ·
  `list_diary_index`(스토리 · 태그 · 장소 목록) · `daily_steps`(날짜별 걸음) · `wake_records`(알람 울림 · 끔 기록).
- 일기를 읽는 도구가 있으므로 **일기 잠금 아래**에 둔다. 잠겨 있으면 탭 대신 잠금 입력이 나오고, 다시 잠겨도 대화는 비우지 않는다(잠긴 동안 가려졌다가 풀면 그대로 보인다).
- 지난 메시지는 고치지 않으므로(thinking 서명 보존) 보낸 사진은 매 요청에 다시 실린다. 그래서 **사진은 한 대화에 12장까지**(저장한 대화를 이어가면 사진이 없으므로 0부터 다시 센다) — 넘기면 사진 없이
  `photo_limit_reached` 오류 결과를 돌려주고, [새 대화]로 다시 볼 수 있다.
- **대기 시간**: 응답(상태 줄)은 60초, 스트리밍 중 SSE 줄 사이는 90초(서버가 ping 을 보낸다)를 넘기면 네트워크 오류로 본다.
- 처음 보낼 때(벤더를 바꾸면 다시) "내 기록이 연결한 벤더(Anthropic · OpenAI)로 전송된다"는 동의를 받는다.
- **연결(키 기획 ②)** — 연결은 벤더 하나(Claude · GPT 중). 키는 보안 저장소 `chat.apiKey` 에만 두고(자동 백업 제외) 화면에는 `벤더 접두사 + 4글자 + ••••` 만 보인다. 저장하기 전에 `GET /v1/models` 로 키를 확인하고, 통과(또는 확인 못 함)하면 요금 경고를 거쳐 등록한다. 연결 상태는 연결됨 · 확인 전 · 키 확인 필요. 물어보기 · 알람 배너에서 설정을 열면 봐야 할 행(연결 행 · 거부된 첫 권한 행)이 두 번 깜빡인다(glow). 키가 없거나 거부되거나 · 크레딧 부족이면 실패 말풍선에 [설정 열기]가 붙는다.
- **주고받는 형식(넘김 규칙)** — 같은 모델이 만든 턴은 원본(`vendorState`)을 그대로 · 같은 벤더의 다른 모델 턴은 text · 도구 호출 · 도구 결과 parts 로 다시 만들어 · 다른 벤더 턴은 글만 넘긴다.
- **기상 기록 보관**: 네이티브 `RingLog`(최근 200줄)는 오래 못 가므로 앱 시작 · 복귀 때, 그리고 `wake_records` 가 돌 때
  drift 의 `ring_archive` 로 복사해 둔다. 알람 기록 화면도 이 보관소(최근 30일)를 읽고, 지워진 알람은 보관된 라벨로 보인다.

- **파일 첨부 · 작업 폴더(1단계)** — 입력칸 [📎]로 사진 · PDF · 텍스트를 질문에 첨부하고(한 질문 3개 · 대화당 PDF+텍스트 5개 · 합계 18MB · 사진은 12장 한도 공유), 답은 말풍선 [파일로 저장]으로 작업 폴더(`workspace/out`)에 `.md` 로 남긴다. 첨부 원본은 `workspace/inbox` 에 사본(임시 대화는 남기지 않음). 물어보기 ⋮ [작업 폴더]에서 보기 · 공유 · 지우기 · 다시 첨부. 설계는 [파일 첨부 · 작업 폴더](../../../docs/superpowers/specs/2026-11-13-walk-chat-files-design.md).
- **작업 폴더 읽기 도구(2단계)** — "내 기록 참고"가 켜진 질문에서 모델이 `list_files`(최신순 100개) · `read_file`(글 20,000자씩 · 사진 · PDF)로 작업 폴더를 스스로 읽는다. 도구로 읽은 사진 · PDF 도 첨부 한도를 같이 쓴다. 설계는 [작업 폴더 읽기 도구](../../../docs/superpowers/specs/2026-11-14-walk-chat-files-read-tools-design.md).
- **작업 폴더 쓰기 도구 · 승인 화면(3단계)** — 모델이 `write_file` · `edit_file` · `delete_file` 로 `out/` 의 글 파일을 만들고 · 고치고 · 지운다. 쓰기마다 승인 시트에서 실제 경로와 내용(보이지 않는 글자는 드러내서)을 보고 승인해야 디스크가 바뀐다. inbox 원본은 바꾸지 않는다. 설계는 [작업 폴더 쓰기 도구](../../../docs/superpowers/specs/2026-11-14-walk-chat-files-write-tools-design.md).

- **진행 표시(체감 속도 3 · 4단계)** — 답 말풍선 위에 진행 줄(단계 · 도구 라벨 · 결과 개수 · 3초부터 경과 초)이 있고, 끝나면 3초 이상일 때만 접힌 요약 · 멈추면 늘 남김(요약 한 줄). 글이 흐르는 중(쓰는 단계)에는 끝에 커서가 깜빡이고, 위로 올려 둔 채 답이 자라면 읽던 자리는 그대로 두고 입력칸 위 [↓ 새 답]이 뜬다. **진행 줄 · 접힌 요약은 저장하지 않는다**(멈춤 표시만 저장).

#### Claude 와 주고받는 형식

미리 만들어 둔 위키는 없다. 기록을 통째로 보내지 않고, 질문마다 Claude 가 도구로 **필요한 만큼만** 꺼내 읽는다.
"지난주에 몇 시에 일어났어?" 한 번이 오가는 모습:

> 요청 규칙: top-level `cache_control`(자동 캐시)을 켜고, 날짜 줄은 시스템 프롬프트 맨 끝에 둬 앞부분 캐시를 지킨다. 진행 노트(`thinking: {adaptive, display: updates}` + beta 헤더)는 `progressNotesDefault` 가 켜졌고 지원 모델일 때만 보내며 대화 중에 바꾸지 않는다. 한 응답의 도구는 동시에 실행하고 결과는 호출 순서로 넘긴다. 진행 이벤트를 언제 내는지는 `chat_model.dart` 의 doc 이 기준이다.

1. **앱 → Claude** — Messages API 요청 하나. 이때 기록은 하나도 실리지 않는다.
   ```json
   { "model": "claude-opus-5-5",
     "system": "너는 사용자의 개인 기록 앱 Life Tool 안의 도우미다. 오늘은 …",
     "tools": [ { "name": "wake_records", "description": "…", "input_schema": { … } }, …5개 ],
     "messages": [ { "role": "user", "content": "지난주에 몇 시에 일어났어?" } ] }
   ```
2. **Claude → 앱** — 답 대신 도구 호출을 돌려준다(`stop_reason: "tool_use"`).
   ```json
   { "type": "tool_use", "name": "wake_records", "input": { "from": "2026-10-26", "to": "2026-11-01" } }
   ```
3. **앱(폰 안)** — `LifeTools` 가 저장소를 읽어 JSON 텍스트를 만들고 `tool_result` 로 다음 요청에 붙인다.
   ```json
   { "rings": [ { "date": "2026-10-27", "alarm": "출근", "rang_at": "07:00", "ended_at": "07:12",
                  "end": "stopped", "snoozes": 2, "skipped": false } ] }
   ```
   Claude 는 한 질문에 도구를 여러 번(최대 8라운드) 부를 수 있다 — 예: 일기를 찾고 그 사진을 본다.
4. **Claude → 앱(답)** — 마크다운 없는 한국어 평문이 SSE 로 흘러와 말풍선에 그대로 보인다. 답 아래 **근거 칩은
   Claude 의 문장이 아니라 3단계에서 앱이 돌려준 일기 id 로** 만든다(그래서 칩은 항상 실제 기록을 가리킨다).

도구별로 Claude 에게 건네는 것(날짜는 `YYYY-MM-DD`, 기간은 양 끝 포함, 최대 366일):

| 도구 | 읽는 곳 | 돌려주는 JSON |
|---|---|---|
| `search_diary` | 일기 DB `searchEntries` | 기록마다 `id` · `at` · `story`(제목) · `place` · `tags` · `text` · `photos` · `videos`, 최대 50개 + `truncated` |
| `view_entry_photos` | 일기 미디어 파일 | `{entry_id, shown, total}` + 사진 최대 4장(1024px JPEG, base64 이미지 블록. 영상은 썸네일) |
| `list_diary_index` | 일기 DB | 스토리(`id` · `title` · 기간 · 기록 수), 상위 30개 태그 · 장소와 개수 |
| `daily_steps` | Health Connect | `{"days":[{"date","steps"}]}` — 하루 합계만 |
| `wake_records` | `ring_archive` | 회차별 `date` · `alarm`(라벨) · `rang_at` · `ended_at` · `end` · `snoozes` · `skipped` |

잘못된 날짜 · 권한 없음 · 사진 한도 같은 실패는 `is_error` 결과(`{"error":"invalid_range"}` 등)로 돌려줘
Claude 가 지어내지 않고 그렇다고 말하게 한다.

- **오류 매핑** — 응답 오류는 `error.type` 만 읽는다(본문 16KB · 2초 상한, 메시지는 읽지 않음): `billing_error`(402) → 크레딧 부족, `not_found_error`(404) → 모델 없음.

#### 멈춤 · 사용량

- **멈춤** — 답하는 중 [■ 멈춤]. 구독 취소 = HTTP 닫기. 멈춘 턴은 `받은 글 + "\n(사용자가 여기서 멈춤)"` 글만으로 다음 문맥에 들어가고(도구 호출 · thinking 은 버림), 받은 글이 없으면 질문까지 되돌려 입력칸에 채운다(입력칸이 비었을 때만).
- **사용량** — 요청(라운드)마다 토큰 사용량을 `ChatUsageLog` 로 넘긴다. 저장은 아직 안 한다(`NoopChatUsageLog`). `display: updates` · 캐시는 진행 표시 단계에서 적는다.

#### 규약(시스템 프롬프트 · 도구 설명)

Claude 에게 주는 지시는 파일이 아니라 코드에 있다 — 고칠 때는 이 두 곳이 기준이다.

- **시스템 프롬프트** — [chat_session.dart](../lib/domain/chat/usecase/chat_session.dart) `_systemPrompt`.
  CLAUDE.md 에 해당한다: 오늘 날짜 · 시간대, "기록에 관한 질문은 도구로 찾아 근거해서 답하고 없으면 '기록에서 찾지 못했어요'",
  "그 밖의 질문은 아는 대로 답하고, 최근 · 불확실한 사실은 웹 검색으로 확인해 출처를 밝힌다",
  "지난주 · 어제를 날짜로 바꿔 도구에 넘긴다", "한국어 · 마크다운 없는 평문".
- **일반 질문 · 웹 검색 · 내 기록 참고 토글**(2026-11-13 결정) — 처음엔 "찾은 기록에 근거해서만 답한다"로
  막아 두었으나, 써 보니 갑자기 궁금한 일반 질문 · 검색을 못 해 불편했다. 그래서 물어보기를 모바일 ChatGPT · Claude
  앱처럼 쓰는 일반 도우미로 넓힌다.
  - **웹 검색** — 벤더가 호스팅하는 검색 도구를 항상 싣는다. Claude 는 `web_search`(지원 모델은 동적 필터링
    `web_search_20260209`, 나머지는 `web_search_20250305`, `max_uses` 5), GPT 는 Responses `web_search`.
    검색 중에는 진행 표시에 "웹 검색: <검색어>"가 뜬다. Claude 의 `pause_turn` 은 사용자 메시지 없이 이어 보낸다.
    검색 1회마다 API 요금이 따로 붙는다. 위키 정리 요청에는 싣지 않는다.
  - **내 기록 참고 토글** — 물어보기 화면의 [내 기록 참고]. 켜면 지금처럼 기록 도구 · 위키에 일반 질문 · 웹 검색이
    더해지고, 끄면 기록 도구 · 위키 · 기록 규칙 없이 일반 도우미(웹 검색은 유지)로 답한다. 마지막 선택을 저장하며
    처음 값은 켜짐. 질문마다 읽으므로 대화 중에 바꾸면 다음 질문부터 적용된다.
- **도구 설명** — [life_tools.dart](../lib/domain/chat/tool/life_tools.dart) `definitions` 의 `description` · `input_schema`.
  Claude 는 이걸 읽고 언제 어떤 도구를 쓸지 정하므로 규약의 나머지 절반이다.

**위키(2단계)** — 메모는 사용자가 만든 것만 있다: 물어보기 ⋮ [위키로 정리]의 후보를 [저장] · [고쳐서 저장]하거나, 말풍선 [위키에 추가] · 위키 화면 [추가]로 쓴 것(그 전에는 위키가 없다). 시스템 프롬프트에는 위키 **색인**(id · 제목 · 한 줄 요약)만 싣고, 본문은 모델이 `read_wiki({ids})` 로 필요할 때 연다. 본문의 `[[id]]` 링크를 따라 더 열 수 있고 `[[일기:id]]` 는 날짜를 주므로 원본은 그 날짜로 `search_diary` 를 부른다. 어떤 메모를 어떻게 실을지는 `WikiContextPolicy` 하나가 정해서 바꿔 끼울 수 있고, **임시 대화에는 색인도 `read_wiki` 도 없다.** 색인 크기는 물어보기 설정에서 고른다. 설계는 [기획 2단계](../../../docs/superpowers/specs/2026-11-01-walk-chat-history-wiki.md), 정리 요청 지시는 [wiki_distiller.dart](../lib/domain/chat/usecase/wiki_distiller.dart) 에 있다.

따로 규약 파일이 필요해지는 때(아직 안 함): 요약 페이지를 Claude 가 스스로 쓰고 합치는 **자동 위키**로 넘어갈 때(페이지 구조 · 합치기 규칙을 정한 문서가 필요하다).

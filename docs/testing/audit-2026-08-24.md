## 고친 것

### 1. 삭제된 게시물에 댓글이 달렸다 (기능 결함)

`post_comments_insert_own` 이 작성자만 확인했다. 소프트 삭제된 게시물에 삽입이
**201 로 성공**했고, 뷰가 가려주므로 어디에도 보이지 않았다. 유출은 아니지만
쓰기가 조용히 성공하는 것이 문제다 — 앱은 낙관적으로 목록에 붙이고, 새로고침하면
사라진다.

`post_reactions_insert_own` 은 처음부터 같은 검사를 하고 있었다. 두 경로의 강도를
맞췄다 (`20260824120000_comment_requires_live_post.sql`). 회귀 확인: 살아 있는 글의
댓글·답글 201 유지, 삭제된 글 403, 3단 답글·삭제된 댓글 답글 거부 그대로.

### 2. 트리거가 던진 문구가 사용자에게 닿지 않았다 (UX 결함)

`enforce_comment_depth()` 는 "답글에는 답글을 달 수 없습니다" 처럼 그대로 보여줄 수
있는 한국어로 예외를 던지는데, `SupabaseErrorMapper` 가 23514 를 일괄로
"입력값이 조건을 만족하지 않습니다" 로 덮었다. 트리거 문구 · `post_comments_content_length`
· 감정 CHECK · 42501 을 매핑에 추가했다.

### 3. 설정에서 프로필을 고쳐도 프로필 탭이 옛 값을 보여줬다 (UI 회귀)

하단 내비게이션 셸이 `IndexedStack` 으로 탭 본문을 살려 두면서 생긴 문제다. 셸 이전에는
프로필 화면을 열 때마다 새로 만들어 항상 최신이었다. 편집 화면이 저장 직후 보내는
`userRefreshRequested` 로 세션 스냅샷이 바뀌는 것을 신호 삼아, **내 프로필일 때만**
다시 읽게 했다.

## 남은 것 (고치지 않고 기록만)

- **이미 읽어둔 피드의 작성자 표시는 즉시 갱신되지 않는다.** 내 닉네임·아바타를 바꿔도
  화면에 남아 있는 목록 항목은 서버가 그때 내려준 스냅샷을 들고 있다. 당겨서
  새로고침하면 맞춰진다. 목록 전체를 훑어 고치는 것은 이득보다 복잡도가 크다고 봤다
- **Patrol E2E 는 실행하지 못했다.** 에뮬레이터와 로컬 Supabase 가 함께 필요하다.
  화면 변경(로그아웃 위치 · 버튼 라벨)은 코드에 반영해 뒀다 ([E2E](e2e.md))
- **게시물 수정에서 이미지 교체 불가** — 설계 그대로다. 넣으려면 Storage 업로드·삭제와
  `post_images` 행 정리를 원자적으로 묶는 RPC 가 필요하다 ([post 계획](../features/post/plan.md))

# 다국어 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 앱 언어(시스템 · 한국어 · 영어 · 일본어)를 고르고 저장하며, 화면·검증·오류 문구 전부가 선택 언어로 뜬다.

**Architecture:** gen-l10n(ARB, template=ko) + `features/theme` 를 `features/preferences` 로 개명해 `LanguageCubit` 을 나란히 둔다. 오류는 `Failure` 에 `FailureCode` 를 더해 domain 이 locale 을 모른 채 코드만 나르고 presentation 확장이 번역한다. DB 트리거 문구는 DB 계약으로 유지하고 error mapper 의 정확 문자열 매칭 자리에서 코드로 바꾼다.

**스펙 (요구사항의 단일 기준):** [docs/features/preferences/plan-language.md](../../features/preferences/plan-language.md)

## Global Constraints

- **domain 은 locale · material · `AppLocalizations` 를 모른다.** 번역은 presentation 확장에서만
- **DB 트리거 문구·마이그레이션은 손대지 않는다.** 매칭 키(한국어)는 DB 계약이다
- **기존 한국어 테스트 단언은 유지한다** — 하니스에 delegates + `Locale('ko')` 를 고정해 통과시킨다. 단언을 약화하거나 지워서 통과시키지 않는다
- **`Result` · `Failure` 의 공개 계약을 깨지 않는다.** `message` 는 fallback 으로 남는다
- 생성 파일(`app_localizations*.dart` 포함)은 직접 수정하지 않는다
- 커밋은 한국어 현재형, body 끝에 `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`
- 검증: `cd app && flutter analyze && flutter test` 전체 무결

### Task 3: 오류·검증 코드화

**Files:** `core/error/failure_code.dart`(신설) · `core/error/failure.dart`(각 variant 에 `FailureCode? code2` 가 아니라 **`FailureCode? failureCode` 추가** — 기존 `String? code` 와 충돌 금지) · `core/l10n/failure_localizations.dart`(신설) · `core/validation/validators.dart` · `core/data/mapper/supabase_error_mapper.dart` · domain scenario · datasource 의 `Failure.auth(message: '로그인이 필요합니다')` 류 · `failure.message` 소비처 19곳 · ARB 3개 · 대응 테스트

- [ ] `FailureCode` enum — 현재 한국어로 만들어지는 모든 Failure 문구를 열거한다 (mapper 의 제약·트리거 매칭 전부, validators 전부, scenario · datasource 의 고정 문구 전부). 각 값이 ARB 키 하나와 1:1
- [ ] `SupabaseErrorMapper`: **매칭 조건(한국어 문자열 · 제약 이름)은 그대로**, 산출만 `failureCode` 를 채운 Failure 로. `message` 에는 지금 문구를 그대로 남긴다(fallback + 기존 mapper 테스트 유지)
- [ ] `Validators`: 반환을 `ValidationError?` enum 으로. 폼 호출부는 presentation 확장 `.localized(context)` 로 감싼다
- [ ] presentation 확장 `failure.localizedMessage(BuildContext)`: `failureCode` 있으면 번역, 없으면 `message` 원문, 그것도 없으면 공통 '문제가 발생했습니다' 키
- [ ] `failure.message` 소비처 19곳을 `localizedMessage(context)` 로 이행
- [ ] en·ja 오류 번역 작성. **방향 중립 원칙 유지** — 차단 관련 문구는 어떤 언어로도 차단 사실·방향을 드러내지 않는다 ([차단 계획](../../features/safety/plan-block.md)의 standing rule)
- [ ] 테스트: mapper 가 코드+fallback 둘 다 채움 · validators enum · `localizedMessage` 3분기 · en 으로 pump 한 폼 오류 스모크 1건

**Verification:** analyze 무경고 · 전체 테스트 통과 · 기존 mapper 테스트가 문구 단언을 유지한 채 통과

# walk — 물어보기 작업 폴더 쓰기 도구 · 승인 화면 (3단계)

> 작성 2026-11-14 · 앱: [Life Tool(walk)](../../../apps/walk/docs/README.md) · 계획: [walk 계획](../../../apps/walk/docs/plan.md)
> 앞선 설계: [파일 첨부 · 작업 폴더(1단계)](2026-11-13-walk-chat-files-design.md) · [읽기 도구(2단계)](2026-11-14-walk-chat-files-read-tools-design.md)
> 상태: **설계(2026-11-14)**. 사용자가 "3단계 진행해"라고 했고, 1 · 2단계처럼 질문 없이 기본안으로 진행한다. 결정은 대부분 **[기본안]** 이다.

## 왜

목표는 Claude Code 처럼 Claude 가 내 파일을 읽고 · 만들고 · 고치는 것이다. 1단계로 작업 폴더(`inbox` 첨부 원본 · `out` 저장한 답)가 생겼고,
2단계로 Claude 가 그 폴더를 스스로 읽는다. 3단계는 **Claude 가 `out` 에 파일을 만들고 · 고치고 · 지우는** 것이다
("영수증 PDF 들을 표로 정리해서 csv 로 만들어 줘", "저번 요약 파일에 오늘 내용 덧붙여 줘").

쓰기는 되돌리기 어렵고, 첨부 · 도구로 읽은 파일 · 웹 검색 결과 안에 숨은 지시가 쓰기를 부추길 수 있다(2단계 기록의 3단계 메모).
그래서 **모든 쓰기는 사용자가 실제 경로와 실제 내용을 보고 승인해야 실행된다.** 프롬프트 줄은 보조일 뿐 방어선이 아니다.

## 목표 · 비목표 · 반목표

**목표**
- 도구 `write_file` · `edit_file` · `delete_file` 로 모델이 `out/` 의 글 파일을 만들고 · 고치고 · 지운다. Claude · GPT 둘 다.
- 쓰기 하나마다 승인 시트가 뜨고, 사용자가 [저장](또는 [고치기] · [지우기])을 눌러야 디스크가 바뀐다. 거절하면 모델은 거절됐다는 결과를 받고 답을 이어 간다.
- 진행 줄에 "승인 기다리는 중 · NAME", "파일 저장 중 · NAME" 등이 보인다. 저장 뒤 스낵바에서 바로 열어 볼 수 있다.

**비목표(3단계 밖)**
- "이번 대화 동안 항상 허용" 같은 자동 승인.
- 사진 · PDF · docx · xlsx 만들기(글 파일만).
- 하위 폴더 만들기, 파일 옮기기 · 이름 바꾸기.
- 답 아래 "만든 파일" 칩 · 쓴 파일 목록을 대화 기록에 저장하기.
- 실패 · 멈춤 때 이미 쓴 파일 되돌리기(승인된 쓰기는 남는다).

**반목표**
- `inbox/`(사용자 원본)를 바꾸는 것. 고친 판은 `out/` 에 새로 만든다.
- 승인 없이 디스크가 바뀌는 것 — 어떤 오류 · 경쟁 · 멈춤 · 대화 전환 경로에서도.
- 승인 시트가 보여 준 것과 실제로 쓴 것이 다른 것(보여 준 뒤 파일이 바뀌었으면 쓰지 않는다).
- 승인 시트가 내용을 렌더링(마크다운 · 링크)하거나 보이지 않는 글자를 숨기는 것.
- 작업 폴더 밖을 쓰는 것(경로 탈출 · 링크). 모든 경로는 `Workspace` 를 거친다.

## 지금 모습(코드로 확인, 2026-11-14 main deeee985)

- `WorkspaceTools`(`list_files` · `read_file`)는 `run(name, input)` 하나로 결과를 준다. `ChatSession._run` 의 `StopKind.toolUse` 가지는
  호출을 모두 바로 시작해(병렬) 끝나는 순서로 `toolFinished` 를 내고, 결과를 호출 순서로 모아 `_capped` · `_cappedDocs` · `_cappedText` 를 지난다.
- 기록을 끈 질문은 도구를 싣지 않고, 부르면 `_recordsOffJson`. 실패 · 멈춤 · 초기화는 세대(`stale()`)로 끊고 턴 시작 스냅숏으로 되돌린다.
- `Workspace` 는 `writeOut(fileName, content)`(이름이 겹치면 `-2`) · `readBytes` · `delete` · `exists` · `list` · `absolutePath`. 경계는 `_check` + `_checkReal`.
- `read_file` 은 `inbox/` · `out/` 아래, 숨김 이름 없는 경로만(2단계 R2).
- 진행 줄은 `ChatEvent.toolStarted/Finished` → 큐빗 `ChatProgress` → `chat_progress_text.dart`.

## 접근

| 안 | 내용 | 판단 |
|---|---|---|
| **A. 세션 안에서 기다리는 승인 [기본안]** | 세션이 쓰기 호출마다 `ChatEvent.approvalRequested` 를 내고 `Completer` 를 기다린다. 큐빗이 시트를 띄우고 `session.decide(callId, approved)` 로 답한다 | 도구 루프 · 라운드 · 세대 끊기를 그대로 쓴다. 멈춤 · 초기화가 기다림도 함께 끝낸다 |
| B. 턴을 끝내고 다음 질문으로 승인 | 모델이 "이렇게 쓸까요?"로 턴을 끝내고, 사용자 답에 쓰기 | 모델이 보여 준 것과 실제 쓰는 것이 같다는 보장이 없다 — 반목표에 걸린다 |
| C. 쓰기를 모아 답 뒤에 한 번에 승인 | 쓰기 결과를 미리 "성공"으로 돌려주고 끝에 묶어 승인 | 모델이 거절을 모른 채 답한다. 거절된 것을 썼다고 말하게 된다 |

A 로 간다.

## 설계

### 1. 도구 셋 — `WorkspaceTools` 에 더한다

모든 쓰기 경로는 `out/<이름>` 하나뿐이다 **[기본안]**: 하위 폴더 없음, 숨김 이름(`.` 시작) 없음, 확장자는 `md · txt · csv · json` 만,
이름에 1단계 `AnswerFile` 의 금지 글자가 없고 120자 이하. 아니면 `{"error":"invalid_path"}`(`inbox/…` 면 `{"error":"read_only"}` — 원본은 못 고친다고 모델이 알게).

**`write_file`** — 입력 `{"path": "out/…", "content": "…", "overwrite": false}`.
- 내용 최대 **100,000자**(코드 포인트) **[기본안]**, 넘으면 `too_large`.
- 이미 있고 `overwrite` 가 true 가 아니면 `{"error":"exists"}`(모델이 덮어쓸지 다른 이름을 쓸지 고른다).
- 결과 `{"path", "name", "chars", "created": true|false}`.

**`edit_file`** — 입력 `{"path": "out/…", "old_text": "…", "new_text": "…"}`. Claude Code 의 Edit 와 같은 규칙: `old_text` 가 정확히 한 번 나와야 한다.
- 없으면 `no_match`, 둘 이상이면 `not_unique`, 파일 없으면 `not_found`, 글 파일이 아니면(UTF-8 아님) `not_text`, 결과가 100,000자를 넘으면 `too_large`.
- `old_text` 가 비면 `invalid_input`(덧붙이기는 write_file 덮어쓰기로).
- 결과 `{"path", "name", "chars"}`.

**`delete_file`** — 입력 `{"path": "out/…"}`. 없으면 `not_found`. 결과 `{"path", "name", "deleted": true}`.

**두 단계: 준비 → 실행.** `WorkspaceTools.prepareWrite(name, input)` 은 디스크를 바꾸지 않고 검증한 뒤
- 오류면 바로 `ToolResult`(isError),
- 아니면 `WritePlan`(도메인 freezed union: `create` · `overwrite` · `edit` · `delete`)을 준다. 계획에는 경로 · 이름 · 새 내용 전체 · (덮어쓰기 · 고치기 · 지우기면) **준비 때 읽은 지금 내용**이 들어 있다.

`WorkspaceTools.apply(plan)` 은 쓰기 직전에 지금 내용을 다시 읽어 계획의 것과 같은지 본다. 다르면(그 사이 사용자가 작업 폴더 화면에서 지웠거나 다른 쓰기가 바꿨거나) 쓰지 않고 `{"error":"changed"}`.
`create` 는 그 사이 파일이 생겼으면 `exists`. 실행 결과도 던지지 않고 `ToolResult` 로 준다.

**`Workspace` 에 더할 것**: `writeText(path, content, {required bool overwrite})` — 정확히 그 경로에 UTF-8 로 쓴다(이름 바꾸기 없음).
경계는 지금 `_safe` 와 같고, 쓰기는 같은 폴더의 임시 파일에 쓴 뒤 `rename` 으로 바꾼다 **[기본안]**(중간에 앱이 죽어도 반쯤 쓴 파일이 남지 않게). 임시 파일 이름은 `.` 로 시작해 `list` 에 안 보인다.

### 2. 세션 — 승인 기다리기

- "내 기록 참고"가 켜진 질문에서 읽기 도구 뒤에 쓰기 도구 셋을 싣는다 **[기본안]**. 꺼지면 싣지 않고, 부르면 지금처럼 `_recordsOffJson`.
- 임시 대화에서도 쓸 수 있다(매번 승인하므로) **[기본안]**.
- `StopKind.toolUse` 에서 호출을 나눈다. 읽기 · 기록 도구는 지금처럼 바로 병렬로 시작한다. 쓰기 호출은 **호출 순서대로 하나씩**:
  1. `prepareWrite` → 오류면 그 결과.
  2. 계획이면 `ChatEvent.approvalRequested(callId, plan)` 을 내고 `Completer<bool>` 을 기다린다.
  3. 승인이면 `toolStarted` 다음 `apply`, 거절이면 `{"error":"user_declined"}`(isError) 결과.
  4. `toolFinished`.
  읽기 도구 결과(병렬)와 쓰기 결과는 지금처럼 호출 순서로 모아 tool_result 로 보낸다.
- `ChatSession.decide(String callId, bool approved)` — 기다리는 것이 없거나 callId 가 다르면 무시.
- **멈춤 · 초기화 · 대화 전환 · 실패**(세대가 바뀌는 모든 경로)는 기다리는 `Completer` 를 **거절로** 끝낸다. 끝난 뒤 `stale()` 이면 `apply` 하지 않고 돌아간다 — 승인 뒤라도 세대가 바뀌었으면 쓰지 않는다.
  큐빗이 보낸 `decide` 가 세대가 바뀐 뒤에 오면 무시된다.
- 기다리는 동안 라운드 시간 · 스트림 타임아웃은 재지 않는다(사용자를 기다리는 시간). 따로 승인 시간 제한은 두지 않는다 **[기본안]**.
- 쓰기 결과는 `_cappedText` 를 거치지 않는다(돌려주는 JSON 이 작다). 트레이스는 `toolStart`/`toolEnd` 에 이름과 승인 여부만, 경로 · 내용은 찍지 않는다.
- 시스템 프롬프트(기록 켜짐, 2단계 작업 폴더 줄 뒤): `out 에 파일을 만들거나(write_file) 고치거나(edit_file) 지울(delete_file) 수 있다. 사용자가 질문에서 요청했을 때만 쓰고, 쓰기마다 사용자가 승인한다. 거절되면 같은 쓰기를 다시 시도하지 말고 답에서 알린다. inbox 의 원본은 바꾸지 않고, 고친 판은 out 에 새로 만든다.`

### 3. 승인 시트 — 실제 경로 · 실제 내용

큐빗은 `approvalRequested` 를 받으면 상태에 `pendingApproval`(callId · plan)을 두고, 화면은 그것이 생기면 모달 하단 시트를 띄운다.

```
┌─────────────────────────────────────┐
│ 파일 만들기                    (제목)│   ← 만들기 · 덮어쓰기 · 고치기 · 지우기
│ out/영수증-정리.csv   · 1.2KB       │   ← 실제 상대 경로 그대로, 크기
│ Claude 가 이 파일을 만들려고 해요    │
│ ┌─────────────────────────────────┐ │
│ │날짜,가게,금액                   │ │   ← 고정폭, 렌더링 없음, 스크롤
│ │2026-11-02,편의점,4500           │ │
│ │…                                │ │
│ └─────────────────────────────────┘ │
│        [거절]          [저장]        │
└─────────────────────────────────────┘
```

- **만들기 · 덮어쓰기**: 새 내용 전체. 덮어쓰기는 제목을 "파일 덮어쓰기"로 하고 "지금 내용 N자를 바꿔요" 줄을 둔다.
- **고치기**: "지울 부분" · "넣을 부분" 두 상자(`old_text` · `new_text` 그대로), 그 위에 바뀌는 곳 앞뒤 한 줄씩 맥락.
- **지우기**: 경로 · 크기 · 앞 20줄 미리 보기, 버튼은 [지우기](파괴적 색).
- 내용은 **글자 그대로** 보인다: 마크다운 · 링크 렌더링 없음, 선택 가능. 보이지 않는 글자(제어 문자 · 방향 바꾸는 글자 U+202A–U+202E · U+2066–U+2069 · 폭 없는 글자 U+200B–U+200F · U+FEFF)는
  `⟨U+202E⟩` 처럼 드러낸다 **[기본안]**. 긴 내용은 시트 안에서 스크롤한다(잘라 보이지 않는다).
- 시트를 밖을 눌러 닫거나 뒤로 가면 **거절** 이다. [저장]은 한 번만 눌린다.
- 기다리는 쓰기가 다른 이유로 끝나면(멈춤 · 대화 전환 · 실패) 큐빗이 `pendingApproval` 을 비우고 시트도 닫힌다.
- 버튼 · 색 · 여백은 `AppButton` · 디자인 토큰. 시트 틀은 지금 앱의 다른 시트(`bubble_actions_sheet` 등)와 같은 모양.
- 저장 · 고치기 성공 뒤 `AppSnackBar`: "out/NAME 에 저장했어요" + [열기](1단계 작업 폴더 보기 화면). 지우기는 "지웠어요".

### 4. 진행 줄

`ChatToolKind` 에 `writeFile` · `editFile` · `deleteFile`.
- 승인 기다리는 동안: "승인 기다리는 중 · NAME".
- 실행 중: "파일 저장 중 · NAME" · "파일 고치는 중 · NAME" · "파일 지우는 중 · NAME".
- 끝: 성공은 "저장함 · NAME" 류, 거절은 "거절함", 오류는 지금 오류 표시 규칙.
- NAME 은 path 마지막 부분 20자 줄임(2단계와 같다). 영어 · 일본어는 l10n.

### 5. 작업 폴더 화면

쓰기가 끝나면 작업 폴더 화면이 열려 있을 때 목록이 새로 고쳐진다(작업 폴더 큐빗이 다시 읽게 하는 신호 하나) **[기본안]**. 만든 파일은 1단계 보기 · 공유 · 지우기를 그대로 쓴다.

## 제약

- 벤더 어댑터는 바꾸지 않는다(쓰기 도구는 보통 함수 도구, 결과는 JSON 뿐).
- 경로는 `Workspace` 로만. 도구 · 세션은 `dart:io` 를 쓰지 않는다.
- 테스트는 구현 구조를 따른다. 꼭 못 박을 것: 승인 전 디스크 불변, 거절 · 시트 닫기 · 멈춤 · 초기화 때 쓰지 않음, 승인 뒤 세대가 바뀌면 쓰지 않음, 보여 준 뒤 파일이 바뀌면 `changed`, `inbox` 는 `read_only`, 경계(`..` · 절대 경로 · 링크 · 하위 폴더 · 숨김 이름), 보이지 않는 글자 드러내기.
- 새 패키지 없음.

## 빌더에게 맡기는 것

- `WritePlan` 필드 이름 · `toString`(내용 없이 길이만).
- 승인 시트 위젯 이름 · 파일 위치(`presentation/chat/workspace/` 아래), 고치기 맥락 줄 계산.
- 진행 줄 · 시트 문구의 영어 · 일본어.
- 작업 폴더 새로 고침 신호의 모양(스트림 · 콜백).

# walk — 하단 탭 재구성 · 설정 분산 설계

> 작성 2026-11-01 · 앱: [Life Tool(walk)](../../../apps/walk/docs/README.md) · 계획: [walk 계획](../../../apps/walk/docs/plan.md)
> 상태: **기획만(코드 미착수)** · 함께 맞출 기획: [API 키 입력](2026-11-01-walk-chat-key-input.md) · [대화 기록 · 기억](2026-11-01-walk-chat-history-wiki.md)

경로는 모두 `apps/walk/` 기준이다.

## 왜

- **설정 탭이 모든 feature 의 설정을 한 목록에 모아 불편하다.** 걷기 · 알람 · 일기 · 채팅 · 권한 · 테마가 한 `ListView` 에
  이어져 있어, 원하는 설정을 찾으려면 스크롤해야 하고 지금 보던 기능과 끊긴다.
- **하단 탭이 feature 하나에 하나씩이라 더 늘릴 자리가 없다.** 지금 5개(알람 · 걷기 · 일기 · 물어보기 · 설정). 앞으로 기능이
  더 생길 것으로 보지만 무엇일지는 아직 모른다.
- **이 앱의 중심은 일기와 물어보기다**(사용자). 알람 · 걷기는 쓰지만 그만큼 자주 열지 않는다. 지금 첫 탭은 걷기다.

성공한 모습: 자주 쓰는 일기 · 물어보기가 한 번에 열리고, 어느 화면에서든 "그 기능의 설정"이 같은 자리(⋮)에 있으며,
새 기능이 생겨도 하단 탭을 늘리지 않고 넣을 곳이 있다.

## 목표 · 비목표 · 반목표

**목표**

1. 하단 탭을 **일기 · 물어보기 · 도구** 3개로 줄인다. 일기가 첫 화면이다.
2. 알람 · 걷기(그리고 나중 기능)는 **도구** 탭 하나에 묶고, 앱바 아래 **상단 탭**으로 바꾼다.
3. 설정 탭을 없애고 설정을 **각 기능 화면의 ⋮ 메뉴 → "○○ 설정"** 으로 나눈다. 공통 항목은 **앱 설정** 화면에 둔다.
4. 일기 화면은 **스크롤을 내리면 앱바가 숨고, 올리면 다시 나온다.**
5. 잠금은 **비밀번호 하나로 일기 · 물어보기를 함께** 잠근다.

**비목표**

- 설정 항목 자체(걸음 목표 시트, 공휴일 출처, 잠금 설정 화면, 키 입력 대화상자 등)의 동작 · 모양 변경. 자리만 옮긴다.
- 새 기능 추가. 도구 탭에 "나중 기능 자리"를 그리지 않는다.
- 다른 화면(알람 · 걷기 · 물어보기)의 앱바 숨김.

**반목표**(기술적으로 돌아가도 실패)

- 앱바가 아이콘으로 붐빈다. 화면마다 오른쪽 위 모양이 다르다.
- 일기에서 앱바가 숨은 채 다른 탭으로 넘어가 앱바를 다시 꺼낼 방법이 없다.
- 설정이 어디 있는지 몰라 헤맨다(⋮ 를 모르는 사람이 설정에 닿을 길이 없다).
- 일기 · 물어보기 중 하나만 풀리고 다른 하나는 잠겨 있는 상태가 생긴다.

바뀌는 것은 **설정 위치와 이름**뿐이다.

## 결정

### 1. 하단 탭

| 순서 | 탭 | 내용 |
|---|---|---|
| 1 | 일기 | 지금 일기 탭. **앱 첫 화면** |
| 2 | 물어보기 | 지금 물어보기 탭 |
| 3 | 도구 | 상단 탭 **알람 \| 걷기** |

- `ShellTab` 은 `diary, chat, tools` 셋. 첫 탭 `diary`.
- 알람 울림으로 켜지면(지금 `_select(ShellTab.alarm)`) → **도구 탭 + 알람 상단 탭**.
- 탭 이름 "도구"와 아이콘은 **임시(builder 판단)**. 바꾸기 쉽게 l10n 한 곳에 둔다.

### 2. 도구 탭 — 상단 탭

- 앱바 아래 `TabBar`: **알람 \| 걷기**. 좌우 밀기로도 넘어간다(알람 · 걷기 화면에 가로 밀기 제스처가 없음을 확인했다).
- 앱 실행 중에는 마지막으로 본 상단 탭을 기억한다. 앱을 새로 켜면 알람(**builder 판단**: 저장하지 않음).
- 도구 탭 앱바는 고정(숨기지 않음).
- 앱바 제목은 "도구"가 아니라 **선택된 기능 이름**을 쓸지, "도구"를 쓸지 — **builder 판단**. 목업은 "도구".
- 기능이 4~5개를 넘어 상단 탭이 비좁아지면 **요약 카드 목록**(토스 '전체' · 삼성 헬스 방식)으로 바꾼다. 이번 범위 아님.

### 3. 앱바 규칙(모든 탭 공통)

- 오른쪽 위 = **그 화면의 핵심 행동 아이콘 + ⋮**. 아이콘은 되도록 하나.
- ⋮ 은 공통 `AppOverflowMenu`. 메뉴 끝 두 항목은 언제나 **"○○ 설정"** 과 **"앱 설정"**(구분선 위아래), 그 위에 화면별 항목.

| 화면 | 아이콘 | ⋮ 메뉴 |
|---|---|---|
| 일기 | 검색 | 모든 스토리 · 휴지통 · ─ · 일기 설정 · 앱 설정 |
| 물어보기 | 새 대화 | ─ · 물어보기 설정 · 앱 설정 (대화 기록 기획의 [대화 목록] · [위키] 는 이 메뉴 위쪽에 들어간다) |
| 도구 › 알람 | 쉬기 | 알람 기록 · ─ · 알람 설정 · 앱 설정 |
| 도구 › 걷기 | (없음) | 걷기 설정 · 앱 설정 |

- 알람의 [기록] 아이콘을 ⋮ 안으로 옮기는 것은 이 규칙에서 나온 **내 판단**이다(쉬기가 더 자주 쓰인다고 봄).
- 도구 탭은 앱바가 하나이므로 actions 와 ⋮ 내용이 **선택된 상단 탭에 따라 바뀐다.**
- 잠긴 동안 일기 · 물어보기 앱바는 지금처럼 화면별 행동을 숨긴다. ⋮ 는 남기되 **"앱 설정"만** 보인다
  (일기 설정 · 물어보기 설정은 잠금 아래 — §6).

### 4. 설정 분산

설정 탭(`ShellTab.settings` · 하단 탭)을 없앤다. 항목은 아래로 옮긴다. 각 "○○ 설정"은 셸 위로 push 하는 **화면 하나**이다
(시트 아님 — 항목이 여럿이고 그 안에서 또 시트를 연다).

| 지금 설정 탭의 항목 | 옮길 곳 |
|---|---|
| 걷기: 걸음 목표 | 걷기 설정 |
| 권한: Health Connect | 걷기 설정 |
| 알람: 공휴일 미리 알림 · 공휴일 출처 | 알람 설정 |
| 권한: 알림 · 정확한 알람 · 전체 화면 | 알람 설정 |
| 일기: 휴지통 보관 기간 · 저장 공간 | 일기 설정 |
| 일기: 잠금 · 재잠금 시간 | **앱 설정 › 잠금** |
| 채팅: API 키(와 키 입력 · 대화 기록 기획이 더하는 행) | 물어보기 설정 |
| 테마 | 앱 설정 |

**앱 설정 화면**

```
앱 설정
  잠금
    잠금           PIN / 패턴 / 끔
    다시 잠그기     즉시 / 30초 / 1분 / 5분
    (설명) 일기와 물어보기를 함께 잠급니다
  화면
    테마           시스템 / 밝게 / 어둡게
  기능별 설정
    일기 설정 ›
    물어보기 설정 ›
    알람 설정 ›
    걷기 설정 ›
```

- "기능별 설정" 바로가기는 ⋮ 를 거치지 않고도 모든 설정에 닿게 하는 안전망이다(반목표 3).
- 앱 설정에서 연 "○○ 설정"의 뒤로가기는 앱 설정으로 돌아온다.

**다른 화면에서 설정으로 보내던 길**

- 알람 권한 배너(`AlarmListPage.onOpenSettings`) → **알람 설정** 화면을 바로 연다.
- 물어보기 [설정 열기](`ChatTab.onOpenSettings`) → **물어보기 설정** 화면을 바로 연다.
- 둘 다 이제 "탭 전환"이 아니라 "화면 push"다. 콜백 이름 · 모양은 builder 판단.

**코드 위치(builder 판단, 제안)** — 기존 섹션 위젯(`DiarySettingsSection`, `ChatSettingsSection`, 걷기 · 알람 · 권한 블록)을
화면별로 나눠 재사용한다. 화면은 `lib/presentation/settings/page/` 에 `app_settings_page.dart` · `walk_settings_page.dart` 등.
권한 행은 알람 몫과 걷기 몫으로 나눈다(`SettingsPermissionsCubit` 은 하나로 두고 화면이 필요한 행만 그려도 된다).
`DiarySettingsSection` 은 잠금 부분(앱 설정)과 보관 · 저장 공간(일기 설정)으로 쪼갠다.

**설정 cubit 의 소유** — 지금은 셸이 소유하고 설정 탭 `active` 일 때 다시 읽는다. 설정이 push 화면이 되면 화면이 열릴 때
읽으면 된다. 셸이 계속 소유할지, 화면이 만들지는 builder 판단. 단, 알람 목록 · 권한 배너가 **설정 화면에서 돌아올 때 다시
읽는** 지금 동작(권한을 켜고 오면 배너가 사라짐)은 지켜야 한다.

### 5. 일기 화면 — 스크롤하면 숨는 앱바

- 일기 타임라인을 내리면 앱바가 위로 숨고, 조금이라도 올리면 바로 다시 나온다(`SliverAppBar(floating: true, snap: true)` 류).
- 숨는 것은 앱바뿐. 하단 탭과 ＋ 버튼은 그대로.
- **다른 탭으로 갔다 오면 앱바가 보이는 상태로 돌아온다**(반목표 2). 일기 탭이 다시 보일 때 앱바를 펼친다.
  같은 이유로 잠금 화면(`DiaryLockGate`)이 보일 때도 앱바는 펼친다.
- '애니메이션 줄이기'(`AppMotion.enabled(context) == false`)면 미끄러지는 전환 없이 바로 숨고 나온다.
- 일기에서 push 하는 화면(검색 · 스토리 · 휴지통 등)은 이번 범위 밖 — 고정 앱바 그대로.

### 6. 잠금

- 비밀번호(PIN · 패턴) **하나**, 스위치 **하나**. 켜면 일기와 물어보기가 함께 잠기고, 한쪽에서 풀면 둘 다 풀린다.
  일기만 · 물어보기만 잠그는 선택지는 두지 않는다. (지금 동작과 같다. 문구와 위치만 바뀐다.)
- 설정은 **앱 설정 › 잠금**. 끄기 · 바꾸기는 지금처럼 풀린 상태에서만. 잠긴 채 앱 설정에 들어와 잠금 · 다시 잠그기 행을
  누르면 **잠금 화면을 먼저 거치고**, 풀리면 그 행의 동작을 이어 한다(아래 바로가기와 같은 방식 · **내 판단**).
- **일기 설정 · 물어보기 설정 화면도 잠금 아래**에 둔다 — 물어보기 설정은 키 · 대화 기록 행을, 일기 설정은 저장 공간을 보여
  준다. 잠긴 동안 ⋮ 에는 "앱 설정"만 있고, 앱 설정의 바로가기 "일기 설정 › · 물어보기 설정 ›"을 누르면 잠금 화면을 거친다
  (`pushDiaryRoute` 처럼). 알람 · 걷기 설정과 앱 설정 자체는 잠금 밖.
  > 대화 기록 기획 §5 는 "보관 기간 · 모두 지우기 · 사용량은 내용을 보여주지 않으므로 잠금 밖"이라 했다. 화면 단위로 잠그면 이
  > 행들도 잠금 아래가 된다. 더 엄격한 쪽이라 이 설계를 따른다(**내 판단**).
- 이름: 코드의 `DiaryLock*` 이름을 바꿀지는 builder 판단(바꾸지 않아도 동작은 같다). 사용자에게 보이는 문구는
  "일기 잠금" → **"잠금"**, 설명 "일기와 물어보기를 함께 잠급니다".

## 다른 기획에 미치는 영향

**[API 키 입력](2026-11-01-walk-chat-key-input.md)**

- §3 "물어보기 → 설정 탭으로 넘어가 채팅 섹션까지 스크롤 + glow", Q2 "알람 권한 배너 → 권한 섹션 glow" — **설정 탭이 없어지므로
  "물어보기 설정 · 알람 설정 화면을 바로 연다"로 바뀐다.** 섹션까지 스크롤할 필요가 없다.
  - 화면을 연 뒤 해당 행을 한 번 glow 로 짚는 것은 남겨도 된다(짚을 행이 화면 맨 위 근처). 남길지는 그 기획에서 정한다.
  - `SettingsPage(focus:)` · 섹션 `GlobalKey` · `ensureVisible` 부분은 필요 없어진다.
- "설정 탭에 벤더 아이콘 + 연결됨", "설정 탭이 보일 때 모델 목록 갱신" → **물어보기 설정 화면**으로 읽는다.
- 파일 목록의 `settings_page.dart` 변경 → 새 `chat_settings_page.dart`(이름 builder 판단)로.

**[대화 기록 · 기억](2026-11-01-walk-chat-history-wiki.md)**

- "설정 채팅 섹션"(보관 기간 · 모두 지우기 · 사용량) → **물어보기 설정 화면**.
- §5 잠금: 위 §6 대로 물어보기 설정 화면 전체가 잠금 아래.
- 물어보기 앱바 ⋮ 에 [대화 목록] · [위키] 가 들어갈 때 끝 두 항목(물어보기 설정 · 앱 설정)은 그대로 둔다.

**구현 순서** — 이 재구성을 **먼저** 하거나, 적어도 키 입력 기획의 glow 부분(②단계)보다 먼저 한다. 그래야 없어질 설정 탭에
glow · 스크롤을 만들지 않는다.

- `apps/walk/docs/status.md` — 진행 상태(여기에만).
- `apps/walk/docs/history.md` · `testing.md` — 완료 시.
- `CLAUDE.md` 의 walk 소개("알람 · 걷기 · 일기 · 채팅 탭") — 탭 구성이 바뀌었음을 반영.

## 테스트로 확인할 것

- 셸: 하단 탭 3개, 첫 화면 일기. 알람 울림으로 켜지면 도구 › 알람.
- 도구 탭: 상단 탭 전환(탭 · 밀기), 선택에 따라 앱바 actions · ⋮ 내용이 바뀜.
- 각 화면 ⋮ 끝 두 항목 → 올바른 설정 화면이 열림. 앱 설정의 바로가기 넷.
- 옮긴 항목이 각 설정 화면에 다 있고, 설정 탭에만 있던 항목이 하나도 빠지지 않음.
- 알람 권한 배너 → 알람 설정, 권한을 켜고 돌아오면 배너가 사라짐.
- 물어보기 [설정 열기] → 물어보기 설정.
- 잠금: 잠긴 동안 ⋮ 에 앱 설정만. 앱 설정 › 일기 설정 · 물어보기 설정 → 잠금 화면 거침. 한쪽에서 풀면 둘 다 풀림.
- 일기 앱바: 내리면 숨고 올리면 나옴. 다른 탭 갔다 오면 보임. 애니메이션 줄이기면 전환 없음.
- 기존 설정 섹션 테스트는 새 화면 위치로 옮긴다(`test/presentation/settings/...`).

# 걷기(Life Log) 앱 백업 · 복원 설계

> 2026-11-16 · 상태: **기획(승인 대기)** · 앱: `apps/walk` · [걷기 허브](../../../apps/walk/docs/README.md)
>
> 처음엔 일기만 백업하려 했다가, 사용자 요청("LLM 위키나 앱의 모든 정보도 백업")으로 **앱 전체 백업**으로 넓혔다.
> 파일 이름의 `diary-backup` 은 첫 범위의 흔적이다.

## 1. 왜

이 앱은 백엔드 없이 모든 걸 폰 안에만 둔다. 일기 사진 · 동영상은 앱 저장소에 사본이 있어 갤러리 원본을 지워도
남지만, **앱을 지우거나 앱 데이터를 지우면 일기 · 위키 · 대화 · 알람이 모두 사라진다.** 안드로이드 자동 백업은
구글 클라우드 한도가 앱당 25MB 라 사진이 쌓이면 **앱 전체 백업이 통째로 실패**한다. 사용자가 직접 들고 있을 수 있는
백업 파일이 필요하다.

사용자 걱정(원문 요지): 개인정보가 많은데 파일로 내보냈다가 유출되면 문제가 되지 않을까.

### 목표

- 설정에서 앱 데이터를 **zip 파일 하나**로 기기의 원하는 위치에 저장한다.
- 무엇을 담을지 **영역별 체크박스**로 고른다(사용자 결정).
- **암호화는 토글**로 고른다(사용자 결정, 기본 켬).
- 그 파일로 **복원**하면 재설치 · 새 폰에서도 고른 영역이 그대로 돌아온다. 알람은 다시 울린다.
- 복원이 실패하거나 잘못 복원해도 **원래 데이터가 남는다**.

### 하지 않는 것(비목표)

- 구글 드라이브 API 직접 연동 · 계정 로그인. 드라이브에 두고 싶으면 저장 위치 창에서 드라이브를 고른다.
- 주기적 자동 백업(WorkManager). 1차는 수동만(사용자 결정). 대신 "마지막 백업" 시각을 보여준다.
- 기존 데이터와 **합치기**. 1차는 영역별 바꿔 넣기만(§6).
- API 키 백업(사용자 결정, §3).

### 실패로 치는 것(반목표)

- 백업에 API 키나 잠금 PIN 이 들어간다.
- 비밀번호를 잊으면 복원이 안 된다는 사실을 모른 채 암호화한다.
- 복원 도중 앱이 죽거나 파일이 깨져서 **원래 데이터까지 잃는다**.
- 오래된 앱이 새 포맷을 반쯤 읽어 데이터가 어긋난다.
- 복원했는데 알람이 울리지 않는다.

## 2. 저장 위치 — 결정: 위치 고르기(SAF) 로컬 zip

| 안 | 장점 | 단점 | 판단 |
|---|---|---|---|
| **SAF "저장 위치 고르기"(ACTION_CREATE_DOCUMENT)** | 로그인 없음. 기기 폴더 · 다운로드 · 구글 드라이브 앱 · USB 어디든. 복원도 같은 문서 고르기 창 | 매번 위치를 고른다 | **채택**(사용자 선택: 로컬 zip) |
| 공유 시트(share_plus) | 간편 | 메신저 용량 제한 · 재압축. 앱 캐시에 큰 파일이 남는다 | 뺌 |
| WorkManager 주기 백업 | 잊어도 된다 | 폴더 권한 유지 · 실패 알림 · 보관 개수 관리 | 다음 단계 후보 |
| Google Drive API | 진짜 클라우드 | OAuth · 앱 등록 · 계정 연동 | 뺌 |

구현 메모: `file_picker` 의 `saveFile` 은 안드로이드에서 **바이트 배열 전체를 메모리로** 받는다. 동영상이 쌓이면
수백 MB 가 될 수 있어 쓰지 않는다. 앱 캐시에 백업 파일을 먼저 만든 뒤, 작은 네이티브 채널
(`com.karma.walk/backup_file`)이 `ACTION_CREATE_DOCUMENT` 로 받은 URI 에 **스트림으로 복사**한다.
복원은 `ACTION_OPEN_DOCUMENT` 로 받은 URI 를 캐시로 스트림 복사한다(`file_picker` 의 `pickFiles` 도 캐시 사본을
만들므로 써도 된다. 빌더가 정한다). 캐시 사본은 끝나면 반드시 지운다.

## 3. 영역과 범위

앱의 로컬 저장소를 다 훑었다(2026-11-16 기준): drift DB 4개(`diary` · `chat` · `ring_archive` · `location`),
문서 폴더의 `diary/`(미디어) · `workspace/`(물어보기 작업 폴더), `app_flutter/alarm_sounds/`(내 파일 알람음 사본),
Flutter SharedPreferences, 네이티브 SharedPreferences(`walk_reminders` · `walk_widget` · `walk.calendar_permission` ·
`location_record` · `walk_ring_log`), 보안 저장소(API 키).

내보내기 시트의 체크박스와 기본값:

| 영역 | 담는 것 | 기본 |
|---|---|---|
| **일기** | `diary` DB 전부(스토리 · 기록(휴지통 포함) · 장소 · 태그 · 기록-태그 · 미디어 행) · `diary/media/` 파일 · 일기 설정(`walk.diary.*`) | 켬 |
| **물어보기 대화** | `chat` DB 의 대화 · 턴 · 사용량 기록 · `workspace/`(첨부 · 작업 폴더 파일) · 대화 설정(`walk.chat.retention` · `walk.chat.useRecords`) | 켬 |
| **LLM 위키** | `chat` DB 의 `wiki_notes` · `walk.chat.wikiIndexSize` | 켬 |
| **알람** | 알람 목록(`walk.alarms`) · 내 파일 알람음 사본(`alarm_sounds/`) · 울림 보관(`ring_archive` DB) · 공휴일 알림(`walk.holidayReminder`) · 쉬는 기간(`walk.pauseFrom` · `walk.pauseUntil`) | 켬 |
| **앱 설정** | 테마 · 걸음 목표 · 지도 스타일 · 위치 기록 보관 기간 · 물어보기 벤더/모델/빠른 모드 · 통근 집/회사 | 켬 |
| **위치 기록** | `location` DB(이동 점 · 머문 곳) | **끔**(내 판단, 아래) |

위치 기록 기본 끔: 하루 동선이라 일기보다 민감하고, 지금 설계가 "이 폰에만 남긴다"이다. 사용자가 체크하면 담는다.
체크한 채 암호화를 끄면 "위치 기록이 암호화 없이 저장돼요" 경고를 한 줄 보여준다(막지는 않는다).

**어느 영역에도 넣지 않는 것:**

| 뺌 | 이유 |
|---|---|
| 물어보기 API 키(보안 저장소 · `chat.apiKey` · 옛 `anthropic_api_key`) | **사용자 결정.** 파일이 새면 남이 내 요금으로 API 를 쓴다. 키스토어에 묶여 있어 옮겨도 못 읽는다. 키는 콘솔에서 다시 복사하면 된다 |
| 키 상태 · 벤더 동의(`chat.keyStatus` · `chat.consentedVendor`) | 키가 없으니 상태는 무의미하고, 대화를 외부로 보내는 동의는 새 기기에서 다시 받는다 |
| 일기 잠금(`walk.lock.*`) | 기기마다 다시 정한다. 잊은 PIN 이 따라오면 잠겨 버린다 |
| 캐시(`walk.holidays.cache` · `weather.cache.v1` · `chat.models*`) | 다시 받으면 된다 |
| 네이티브 상태(`walk_reminders` · `walk_widget` · `walk_ring_log` · `walk.calendar_permission` · `location_record`) | 알람 · 위젯 · 위치 서비스가 지금 기기에서 다시 만든다(§6 복원 후 처리) |
| 그 밖(`walk.goalCelebratedOn` · `walk.alarms.corrupt` · `diary/tmp/`) | 일시 상태 |

설정 화면 안내: "API 키와 잠금은 담지 않습니다. 복원 후 다시 입력하세요."

## 4. 포맷과 버전

zip 한 파일. 이름 `lifelog-backup-YYYYMMDD-HHmm.zip`, 암호화하면 `….lifelog`(§5).

```
manifest.json
diary/data.json            diary/media/<id>.jpg|.mp4|_thumb.jpg
chat/conversations.json    chat/workspace/…
wiki/notes.json
alarm/data.json            alarm/sounds/<hash>.<ext>      alarm/ring_archive.json
settings/prefs.json
location/data.json
```

`manifest.json`:

```json
{
  "format": "lifelog.backup",
  "formatVersion": 1,
  "appVersion": "1.0.0+1",
  "createdAt": "2026-11-16T21:30:00+09:00",
  "areas": {
    "diary":    {"schema": {"diary": 1}, "counts": {"entries": 120, "media": 210}},
    "chat":     {"schema": {"chat": 3},  "counts": {"conversations": 40}},
    "wiki":     {"schema": {"chat": 3},  "counts": {"notes": 25}},
    "alarm":    {"schema": {"ringArchive": 1, "alarmsJson": 1}, "counts": {"alarms": 4}},
    "settings": {"schema": {"prefs": 1}},
    "location": {"schema": {"location": 1}, "counts": {"points": 50000}}
  },
  "files": [{"path": "diary/media/abc.jpg", "bytes": 312345, "sha256": "…"}]
}
```

- 담지 않은 영역은 `areas` 에 없다. `files` 는 JSON 을 포함한 **모든** 파일의 크기 · sha256 이다.
- 데이터는 테이블별 행 배열 JSON 이다. 컬럼 이름 · 값은 drift 행 그대로(날짜는 ISO-8601 문자열). wiki 의 정수 id 도
  그대로 둔다. **SQLite 파일을 통째로 복사하지 않는다** — DB 하나에 여러 영역(대화 · 위키)이 있고, 스키마가 바뀌어도
  JSON 을 그 시점 스키마로 넣을 수 있게.
- SharedPreferences 값은 `{key: {type, value}}` 로, 영역에 속한 **허용 목록 키만** 담는다(목록 밖 키는 새로 생겨도
  자동으로 따라가지 않는다 — 비밀 값이 실수로 섞이지 않게). 허용 목록은 테스트가 고정한다.
- 미디어 · 소리 파일은 이미 압축돼 있어 zip 에 **저장(store)** 으로, JSON 만 deflate 한다.

**버전 처리:**

- `format` 이 다르면 "Life Log 백업이 아닙니다".
- `formatVersion` 이 이 앱이 아는 것보다 크면 파일 전체를 거절한다: "앱을 업데이트한 뒤 복원하세요".
- 영역의 `schema` 중 하나라도 이 앱보다 크면 **그 영역만** 복원 목록에서 회색으로 막고 같은 안내를 단다. 나머지 영역은
  복원할 수 있다(예: 새 앱에서 만든 백업을 옛 앱에서 열면 일기만 스키마가 올라갔을 때 위키 · 알람은 복원 가능).
- 작으면 영역별 단계 변환(`v1→v2` …)으로 올린 뒤 넣는다. 지금은 모두 v1(대화 DB 는 3)뿐이다.

## 5. 암호화 — 결정: 토글, 기본 켬

일기 잠금(PIN)은 **앱 화면만** 막는다. DB · 사진 파일은 암호화돼 있지 않고, 백업 zip 도 그대로면 누구나 열어 본다.
내보내기 시트의 "비밀번호로 잠그기" 토글을 **기본으로 켜 둔다.** 끄면 "이 파일은 누구나 열 수 있어요"를 보여준다.

- 켜면 zip 을 통째로 감싼다. 컨테이너:
  - 헤더: 매직 `LLBK` · 컨테이너 버전 1 · KDF 이름 · 반복 수 · salt(16B) · nonce 접두(8B 무작위)
  - 키: PBKDF2-HMAC-SHA256 600,000회(OWASP 2023 권고), 32B
  - 본문: AES-256-GCM, **1 MiB 덩어리**마다 암호화(nonce = 접두 8B ‖ 덩어리 번호 4B, AAD = 헤더 ‖ 덩어리 번호 ‖
    마지막 여부). 큰 파일도 메모리에 다 올리지 않고, 덩어리 순서 바꾸기 · 잘라내기를 잡는다
  - 틀린 비밀번호 · 손상은 첫 덩어리 태그 검증에서 걸린다 → "비밀번호가 틀렸거나 파일이 손상됐어요"
- 비밀번호 8자 이상, 두 번 입력. "잊으면 복원할 수 없어요" 확인란을 체크해야 저장 버튼이 켜진다. 저장하지 않는다.
- 라이브러리는 빌더가 정한다(`cryptography` + `cryptography_flutter`, 또는 Kotlin `javax.crypto` 채널). 기준:
  PBKDF2 가 중급 폰에서 2초 안쪽, 덩어리 스트리밍. Java GCM 은 복호화 때 전체를 버퍼링하므로 덩어리마다 새 Cipher.
- 복원 시 첫 4바이트로 판별: `PK\x03\x04` 면 일반 zip, `LLBK` 면 비밀번호를 묻는다.

## 6. 복원 — 결정: 영역별 바꿔 넣기 + 되돌리기 한 번

**합치기 대신 바꿔 넣기**를 고른 이유: 쓰임새가 "재설치 · 새 폰"이라 현재 데이터가 거의 비어 있다. 합치기는 같은 이름
다른 id 의 장소 · 태그, 기본 스토리, 지운 기록 되살아남, 위키 정수 id 충돌 같은 규칙이 많고 결과를 예측하기 어렵다.
**체크한 영역만** 바꾸고 나머지는 그대로 둔다.

흐름:

1. 설정 → 백업 → "백업에서 복원" → 파일 고르기 → (암호화면) 비밀번호
2. **검증**(현재 데이터에 손대지 않음): 작업 폴더에 풀고 manifest · 버전 · sha256 · JSON 파싱 · 영역 안 참조
   무결성(기록 → 스토리 · 장소, 미디어 → 기록, 턴 → 대화)을 본다. 실패하면 끝, 작업 폴더를 지운다.
3. **복원할 영역 고르기**: 백업에 있는 영역만 체크박스로(기본 모두 체크, 막힌 영역은 회색 + 이유). 영역마다 개수와
   "지금 데이터를 바꿉니다"를 보여준다.
4. 확인 다이얼로그(`AppConfirmDialog`, 파괴적): "고른 영역의 지금 데이터를 백업(날짜) 것으로 바꿉니다. 지금 데이터는
   되돌리기용으로 잠시 보관됩니다."
5. **되돌리기 지점**: 고른 영역의 현재 데이터를 같은 포맷(암호화 없음)으로 앱 내부 `restore_undo/` 에 내보낸다. 한 개만
   둔다(다음 복원이 덮어씀). 자동 백업 규칙에서 뺀다(§7).
6. **바꾸기**(영역마다):
   - 파일 폴더(`diary/media/` · `workspace/` · `alarm_sounds/`): 현재 폴더를 `<폴더>.old/` 로 이름 바꾸고, 작업 폴더의
     것을 옮긴다. 작업 폴더는 같은 파일 시스템(문서 폴더 아래 `restore_staging/`)에 두어 rename 으로 옮긴다.
   - DB: DB 마다 한 트랜잭션에서 그 영역의 테이블을 비우고 JSON 행을 넣는다. 일기의 기본 스토리가 없으면
     `_ensureDailyStory` 규칙으로 만든다.
   - prefs: 영역 허용 목록 키를 지우고 백업 값을 쓴다.
   - 실패하면 그 영역의 `.old/` 를 되돌린다(DB 는 롤백). **이미 끝난 영역은 되돌리기 지점으로 되돌린다** — 반쯤 복원된
     상태로 두지 않는다.
   - 모두 성공하면 `.old/` 들을 지운다.
7. 앱 시작 시 `.old/` · `restore_staging/` 이 남아 있으면(도중에 죽음) 되돌리기 지점으로 전체를 되돌리고 정리한다.
   고아 청소(`cleanOrphans`)는 이 폴더들을 건드리지 않는다.
8. 설정에 "복원 전으로 되돌리기"(되돌리기 지점이 있을 때만). 같은 복원 흐름을 돈다(확인 다이얼로그 포함).

### 복원 후 처리

- **알람**: 기존 알람 동기화(전체 다시 예약 · 다음 알람 위젯 · 미리 알림 갱신)를 돌린다. 내 파일 알람음은 경로를
  지금 기기의 `alarm_sounds/` 기준으로 다시 맞춘다(사용자 · 기기마다 절대 경로가 다를 수 있다). 파일이 없으면 기본
  알람음으로 바꾸고 알린다. 정확한 알람 · 알림 권한이 없으면 복원 결과에 "알람 권한을 켜 주세요"를 띄운다.
- **위치 기록**: 데이터만 복원하고 **서비스는 켜지 않는다**(네이티브 `location_record` 는 백업하지 않음). 결과에
  "위치 기록은 꺼져 있어요. 지도 설정에서 켜세요"를 띄운다. 복원 중 네이티브 inbox 가져오기는 멈추고, 끝나면 남은
  inbox 점을 평소처럼 덧붙인다. 위치 보관 기간이 짧으면 다음 정리에서 오래된 점이 지워진다는 점을 결과에 적는다.
- **물어보기 · 위키 ↔ 일기 참조**: 대화 턴의 `citedEntryIds` 는 일기 기록 id 를 가리킨다. 영역을 따로 고를 수 있으니
  가리키는 기록이 없을 수 있다 → 고치지 않고 두고, 화면은 없는 기록을 건너뛴다(빌더가 현재 동작을 확인하고 필요하면
  처리). 위키의 `sourceConversationId` 가 없는 대화를 가리키면 복원 때 null 로 바꾼다(지금 삭제 규칙과 같다).
  위키만 복원할 때 대화 테이블은 건드리지 않는다.
- **API 키**: 물어보기 탭은 이미 "키 없음" 상태를 보여준다. 결과에 "API 키를 다시 넣어 주세요"를 띄운다.
- 화면들은 drift 스트림을 보고 있어 저절로 갱신된다. prefs 를 읽어 둔 cubit(테마 · 걸음 목표 등)은 다시 읽게 한다
  (빌더가 방법을 정한다. 가장 단순하면 복원 뒤 "앱을 다시 시작합니다"로 재시작).

### 공통

- 일기가 잠겨 있으면(`LockUnlocked` 아님) 내보내기 · 복원 행을 막는다 — 잠금을 우회해 데이터를 빼낼 수 없게.
- 복원 중에는 전체 화면 진행 표시로 다른 조작을 막는다.

## 7. 안드로이드 자동 백업 규칙

지금은 일기 미디어 · 작업 폴더까지 클라우드 백업에 들어가 25MB 를 넘으면 **앱 전체 백업이 실패**한다.

- `backup_rules.xml`(API ≤30)과 `data_extraction_rules.xml` 의 `<cloud-backup>` 에서 큰 파일 폴더를 뺀다:
  `app_flutter/diary/` · `app_flutter/workspace/` · `app_flutter/restore_staging/` · `app_flutter/restore_undo/`.
  **DB 와 설정은 남긴다** — 작다. 클라우드로 복원된 기록의 사진은 없을 수 있고, 이미 있는 "사진 없음" 표시
  (`entry_media_view.dart` 의 `_Missing`)가 보인다.
- `<device-transfer>`(기기 간 이전, 25MB 한도 없음)에는 미디어 · 작업 폴더를 그대로 두고 `restore_*` 만 뺀다.
- 경로(`getApplicationDocumentsDirectory()` = `app_flutter`)는 구현 때 에뮬레이터에서 확인한다.
- 설정 안내: "사진 · 동영상 · 첨부 파일은 구글 자동 백업에 들어가지 않아요. 백업 파일을 만들어 두세요."

## 8. 화면

설정 첫 화면(`app_settings_page.dart`)에 "백업" 행 하나를 더하고 새 화면 `backup_page.dart` 로 들어간다. 기존 섹션
파일은 건드리지 않는다.

```
백업
  [↑] 백업 파일 만들기          마지막 백업: 3일 전
  [↓] 백업에서 복원
  [↺] 복원 전으로 되돌리기       (되돌리기 지점이 있을 때만)
  API 키와 잠금은 담지 않습니다.
```

내보내기 시트:

```
담을 것
  [x] 일기          기록 120 · 사진·영상 210 (310MB)
  [x] 물어보기 대화  40개 · 파일 12
  [x] LLM 위키      25개
  [x] 알람          4개
  [x] 앱 설정
  [ ] 위치 기록     점 50,000
비밀번호로 잠그기  (●)       ← 토글, 기본 켬
  비밀번호 / 다시 입력
  [ ] 비밀번호를 잊으면 복원할 수 없어요
            [저장 위치 고르기]
```

하나도 체크하지 않으면 저장 버튼을 끈다. 진행 중: 단계와 퍼센트. 완료: `AppSnackBar` "백업했어요 (310MB)".
마지막 백업 시각은 성공했을 때만 적고, 30일이 넘으면 "오래됨" 표시(알림 없음). 공통 위젯 · 토큰만 쓰고, l10n arb 는
필요한 키만 더한다.

## 9. 구조(빌더 안내)

- `domain/backup/`: `BackupArea` enum · `BackupManifest` · `BackupFailure`(형식 아님 · 새 버전 · 비밀번호/손상 ·
  무결성 · 공간 부족 · 취소) · 영역 포트 `BackupAreaSource`(내보내기 · 검증 · 바꿔 넣기 · 복원 후 처리) · 유스케이스
  (`exportBackup` · `inspectBackup` · `restoreBackup` · `undoRestore`).
- `data/backup/`: 영역별 구현(일기 · 대화 · 위키 · 알람 · 설정 · 위치) · zip 읽기/쓰기(`archive` 패키지, 파일 스트림) ·
  암호 컨테이너 · 시작 시 정리 · 네이티브 파일 채널 래퍼. 영역 구현은 기존 저장소를 거치지 않고 각 drift DB 를 직접
  다룬다(행 그대로 옮기기).
- `presentation/backup/`: `BackupCubit`(+ freezed union 상태) · 화면 · 시트.
- 무거운 일(압축 · 해시 · 암호화)은 `Isolate.run` 으로 UI 스레드 밖에서.
- 저장 공간: 내보내기 전 캐시 여유가 예상 크기보다 작으면, 복원 전 여유가 백업 크기의 2배보다 작으면 실패로 알린다.
- 기능 문서는 `apps/walk/docs/` 에(status · history · testing).

## 10. 테스트(완료 조건)

- 영역별 왕복: 메모리 DB + 임시 폴더로 각 영역 내보내기 → 비우기 → 복원 → 모든 행 · 파일 바이트 같음.
  전체 왕복은 암호화 켬/끔 둘 다.
- 일부 영역만 복원하면 나머지 영역은 그대로.
- 틀린 비밀번호 · 덩어리 하나 바꾼 파일 · 잘린 파일 · sha256 불일치 · 모르는 `format` · 큰 `formatVersion` → 각 실패,
  **현재 데이터 그대로**. 영역 schema 가 크면 그 영역만 막힘.
- 둘째 영역에서 실패 → 첫 영역까지 되돌려짐. 시작 시 정리.
- 되돌리기: 복원 → 되돌리기 → 복원 전과 같음.
- 백업에 API 키 · 키 상태 · 동의 · 잠금 값이 없음(허용 목록 · 파일 목록 · JSON 키 검사).
- 복원 후 처리: 알람 동기화 호출 · 알람음 경로 재설정 · 없는 대화를 가리키는 위키 출처 null · 위치 서비스 꺼진 채.
- cubit 상태 전이 · 체크 0개면 저장 막힘 · 잠김 상태에서 행 막힘 · 화면 위젯 테스트.
- 에뮬레이터: 내보내기(다운로드) → 앱 데이터 지우기 → 복원 → 피드 사진 · 위키 · 알람 다시 예약 확인.
- `flutter analyze` 0, 문서 갱신.

# walk 물어보기 — 위치 · 알람 · 날씨 기록 조회 도구

- 날짜: 2026-11-16
- 앱: `apps/walk`(Life Tool) 물어보기 탭
- 상태: **기획 · 사용자 결정 대기(§7)**. 승인 전에는 구현하지 않는다.
- 관련: [채팅 설계](2026-10-27-walk-life-chat-design.md) · [지도 · 위치 기록 설계](2026-11-08-walk-location-map-design.md)(§열어 둔 것: "물어보기 도구에 위치 기록(`search_places`)을 붙이는 건 다음에")

## 1. 왜

사용자 피드백(2026-11-16): 물어보기에 "최근 내가 어디를 갔는지" 물었더니 일기 내용만 보고 답했다.
위치 정보 · 알람 · 걷기 같은 앱의 다른 기록도 다 조회되면 좋겠다.

성공: "지난주에 어디 갔어?", "요즘 자주 가는 곳은?", "내 알람 몇 시로 돼 있어?", "내일 비 와?" 같은 질문에
앱이 실제로 가진 기록을 근거로 답한다.

## 2. 지금 어떻게 동작하나(진단)

- **도구 호출 방식이다**(컨텍스트 주입 아님). `LifeTools`(`lib/domain/chat/tool/life_tools.dart`)가 모델에 도구를
  주고, 모델이 부르면 앱이 로컬에서 실행해 JSON 을 돌려준다. `ChatSession` 의 `useRecords`("내 기록 참고하기")가
  켜진 질문에서만 `LifeTools.definitionsFor` · 위키 · 작업 폴더 도구를 붙이고 기록 규약을 시스템 프롬프트에 넣는다.
- 지금 있는 기록 도구는 다섯 개:

  | 도구 | 읽는 것 |
  |---|---|
  | `search_diary` | 일기(본문 · 태그 · **일기에 붙인 장소 이름** · 스토리), 최대 50개 · 최대 366일 |
  | `view_entry_photos` | 일기 사진(사진 되는 모델만) |
  | `list_diary_index` | 스토리 · 자주 쓴 태그 · 장소 상위 30 |
  | `daily_steps` | Health Connect 하루별 걸음 수 |
  | `wake_records` | 알람 울림 기록(울린 시각 · 스누즈 · 끈 시각) |

- 시스템 프롬프트도 기록 범위를 "일기 · 걸음 수 · 알람 기상 기록"으로 적는다.
- 그래서 "어디 갔나"에 모델이 쓸 수 있는 근거는 **일기에 장소 태그를 단 글뿐**이었다. 위치 기록 도구는 지도 기능
  스펙에서 "다음에"로 미뤄 둔 상태다.

## 3. 앱이 실제로 가진 데이터

| 영역 | 저장하는 것 | 채팅에서 지금 | 비고 |
|---|---|---|---|
| **위치(지도)** | 상시 위치 기록을 켰으면 GPS 점 전체(drift `LocationDatabase`, 이 폰에만 · 백업 제외, 보관 3개월/1년/지우지 않음). 점 → `TrackAnalyzer` 가 **머문 곳**(반경 100m · 10분 이상)과 이동선을 뽑고, `StayNamer` 가 격자(소수 3자리 ≈100m) 단위로 장소 이름을 캐시(Android Geocoder) | **없음** | 기록을 켠 적 없으면 점이 없다. 기본은 꺼짐 |
| 일기 장소 | 글마다 장소 이름 + 좌표(선택) | `search_diary` 의 `place`(이름만) | |
| **알람 설정** | 알람 정의(시각 · 반복 요일 · 라벨 · 켜짐 · 1회성 시각 · 스누즈 · 건너뛰기 등) | **없음** | |
| 알람 울림 | 울림 기록 아카이브 | `wake_records` | |
| 걷기 | Health Connect 하루 걸음 합계만. 거리 · 칼로리 · 운동 세션(걷기 기록)은 읽지 않는다(2026-10-21 QA 결정) | `daily_steps` | "걷기 기록"이라는 별도 저장은 없다 |
| **날씨** | 마지막으로 받은 예보 하나(지금 · 시간별 24칸 · 일별 7일, 24시간 캐시). **지난 날씨 이력은 저장하지 않는다** | **없음** | Open-Meteo, 키 없음 |
| 통근 | 집 · 회사 장소 | 없음 | 탭에서 빠져 있어 범위 밖 |

**"최근 어디 갔나"의 근거**: 위치 기록을 켜 둔 사용자라면 **머문 곳 이력이 이미 폰에 있다**. 새로 모을 필요가 없다.
위치 기록을 켜지 않았다면 근거는 일기 장소뿐이고, 그때는 "위치 기록이 꺼져 있어 일기 장소로만 답한다"고 말하게 한다.
→ **새 데이터 수집은 하지 않는다**(제안). 걷기 운동 세션 · 날씨 이력을 새로 쌓는 것도 이번 범위 밖.

## 4. 목표 · 비목표 · 안티 목표

- 목표: 위치(머문 곳 · 자주 간 곳) · 알람 설정 · 지금 날씨 예보를 물어보기 도구로 조회한다. "내 기록 참고하기"가
  켜진 질문에서 기존 도구와 함께 쓰인다.
- 비목표: 새 데이터 수집(위치 이력 신규 · Health Connect 운동 세션 · 날씨 이력), 지도 화면 열기 칩, 이동선(경로)
  자체 전송, 채팅 화면 UI 변경(다른 세션이 앱바를 고치는 중), 알람을 채팅으로 바꾸기(쓰기).
- 안티 목표:
  - **원시 GPS 좌표 · 이동선이 AI 로 나가는 것.** 질문에 답하는 데 장소 이름과 시간이면 충분하다.
  - **모르는 사이 위치가 나가는 것.** 동의 문구에 위치가 없는데 위치를 보내면 실패다.
  - 기록이 없을 때 지어내기. 위치 기록이 꺼져 있으면 꺼져 있다고 말해야 한다.

## 5. 접근

1. **도구를 늘린다(추천)** — `LifeTools` 에 읽기 도구를 더한다. 지금 구조 그대로, 모델이 필요할 때만 불러 비용 ·
   전송량이 질문에 비례한다.
2. 컨텍스트 주입 — 질문마다 최근 7일 머문 곳 · 알람 목록을 시스템 프롬프트에 넣는다. 도구 호출 왕복이 줄지만
   묻지 않은 위치까지 매번 나가고, 날마다 바뀌어 캐시 접두부를 깬다. 안티 목표에 걸린다.
3. 범용 `query_records(kind, …)` 도구 하나 — 정의 토큰은 줄지만 모델이 인자를 틀리기 쉽고 기존 도구와 모양이 갈린다.

→ 1 로 간다.

## 6. 설계(1 기준)

### 6.1 새 도구

모든 도구는 기존과 같이 `from` · `to`(YYYY-MM-DD, 로컬, 양 끝 포함) 규약과 `{"error": code}` 실패 모양을 따른다.

**`visited_places`** — 기간의 머문 곳을 시간순으로.

- 입력: `from`, `to`(필수). 최대 **31일**(넘으면 `to` 기준으로 자르고 `clamped: true`).
- 처리: `LocationRepository.pointsAround` → `TrackAnalyzer.analyze(clipFrom, clipTo, openEnd: 기록 중이면 지금)` →
  머문 곳마다 `StayNamer.nameFor`. 지도 화면과 같은 계산을 쓴다.
- 출력(머문 곳 하나): `{"date":"2026-11-14","start":"09:12","end":"18:40","minutes":568,"place":"OO동 OO빌딩"}`.
  이름을 못 얻으면 `place: null`(§7-1 결정에 따라 대략 위치를 더할 수 있음). **좌표는 보내지 않는다.**
- 상한: 머문 곳 **최대 150개**, 넘으면 **최근 것부터 남기고** `truncated: true`(기간을 줄이라는 뜻).
  새 이름 조회(Geocoder 호출)는 한 번 부를 때 **최대 20곳**, 나머지는 캐시에 있는 이름만 — 느려지는 걸 막는다.
- 함께 주는 상태: `recording`(지금 위치 기록이 켜져 있는지: on · off · blocked), `has_history`(점이 하나라도 있는지).
  점이 하나도 없으면 오류 `location_not_recorded`.

**`frequent_places`** — 기간의 자주 간 곳 상위 10.

- 입력: `from`, `to`(필수). 최대 **366일**(기존 `_maxDays` 와 같게).
- 처리: 위와 같은 머문 곳 → `frequentPlaces(stays, limit: 10)` → 이름.
- 출력: `{"place":"…","visits":12,"hours":40.5,"last":"2026-11-14"}`. 좌표 없음.
- 기간이 길면 점이 많다(1년 · 3분 간격이면 수십만 점). 날 단위로 나눠 읽어 메모리를 묶는다 — 세부는 빌더 몫.

**`list_alarms`** — 지금 알람 설정.

- 입력 없음.
- 출력(알람 하나): `{"time":"07:00","repeat":["mon","tue",…]|[],"label":"…","enabled":true,"next":"2026-11-17T07:00"|null,
  "skip_next":false,"snooze_minutes":5,"snooze_limit":3|null}`. 소리 파일 경로 · 볼륨 같은 기기 세부는 보내지 않는다.

**`weather_forecast`** — 날씨 탭이 쓰는 위치의 예보.

- 입력 없음.
- 처리: 날씨 탭과 같은 경로(캐시가 10분 안이면 캐시, 아니면 새로 받기, 실패하면 24시간 안 캐시). 예보는 앞으로
  것만 있다 — 지난 날씨는 "기록이 없다"고 답하게 한다.
- 출력: 장소 이름(날씨 탭이 보이는 이름) · 받은 시각 · 지금 · 오늘 남은 시간별(최대 24칸) · 일별 7일. 좌표 없음.
- 실패: `weather_unavailable`(위치 권한 없음 · 오프라인이고 캐시도 없음).

걷기: 새 도구 없음. 걸음 수 외의 걷기 데이터가 앱에 없다. `daily_steps` 설명만 "걷기 탭의 하루 걸음 수"로 다듬는다.

### 6.2 "내 기록 참고하기"와 연결

- 새 도구는 `LifeTools.definitionsFor` 목록 **끝에** 붙인다. 그래서 `useRecords` 가 켜진 질문에만 자동으로 실리고,
  꺼진 질문에는 실리지 않는다(지금 일기 도구와 같은 경로). 채팅 화면 · cubit 은 손대지 않는다.
- 시스템 프롬프트 `_recordRules` 의 기록 목록을 "일기 · 위치 기록(머문 곳) · 걸음 수 · 알람(설정 · 기상 기록) · 날씨
  예보"로 바꾸고 한 줄을 더한다: "어디 갔는지는 위치 기록 도구로 찾고, 위치 기록이 없으면 일기 장소로 답하며 그렇다고
  밝힌다."
- `ChatToolKind` 에 `visitedPlaces` · `frequentPlaces` · `alarms` · `weather` 를 더하고 진행 줄 문구(l10n)를 단다.
  진행 줄은 `presentation/chat/widget/chat_progress_text.dart` 의 switch 에 한 줄씩 — 화면 배치(`page/`)는 건드리지 않는다.
- 참고한 기록 칩은 일기만(지금 그대로). 위치 칩(지도 열기)은 다음에.

### 6.3 잠금 · 전송 고지 · 동의

- 채팅 탭은 이미 일기 잠금 아래다. 지도도 같은 잠금이라 새 우회는 없다.
- 동의 · 설정 안내 문구(`walkChatConsentNotice` · `walkChatSettingsNotice`)의 "일기 · 사진 · 걸음 · 기상 기록"을
  "일기 · 사진 · 위치 기록(머문 곳 이름 · 시간) · 걸음 · 알람 · 기상 기록"으로 바꾼다.
- 이미 동의한 사용자에게 다시 동의를 받을지는 **§7-2**.

### 6.4 비용

- 도구 정의 4개가 늘어 요청마다 약 400~600 토큰이 더 붙지만, 시스템 프롬프트 · 도구는 캐시 접두부라 두 번째 질문부터 싸다.
- 결과 크기: 머문 곳 하나 ≈ 25 토큰 → 31일 · 150개 상한이면 ≈ 4K 토큰. 자주 간 곳 10개 ≈ 300 토큰. 알람 · 날씨 ≈ 1K 미만.
- 한 질문 안의 도구 왕복 상한은 지금 세션 규칙을 그대로 쓴다.

### 6.5 실패 처리

| 상황 | 결과 | 모델이 할 말 |
|---|---|---|
| 위치 점이 하나도 없음 | `location_not_recorded` | 위치 기록이 꺼져 있어 일기 장소로 답한다(일기도 찾아본다) |
| 기간에 머문 곳 없음 | 빈 목록 + `recording` | 그 기간 기록이 없다 / 꺼져 있었을 수 있다 |
| Geocoder 오프라인 · 이름 없음 | `place: null` | "이름을 모르는 곳"으로 말한다 |
| 날짜 형식 · 순서 틀림 | `invalid_range` | (기존과 같음) |
| 날씨 실패 | `weather_unavailable` | 날씨를 가져오지 못했다 |
| 그 밖 예외 | `tool_failed` | (기존과 같음) |

## 7. 사용자가 정할 것

1. **장소 이름을 못 얻은 머문 곳을 어떻게 보낼까**
   - (a) 이름 없이 시간만 — 좌표가 전혀 나가지 않는다. 대신 이름 없는 곳은 "어딘가"로만 답한다. *추천*
   - (b) 대략 좌표(소수 2자리 ≈ 1km)를 함께 — 모델이 "OO역 근처" 정도로 추정할 수 있지만 위치값이 나간다.
2. **이미 동의한 사용자에게 위치 전송 동의를 다시 받을까**
   - (a) 문구만 바꾸고, 다음 질문 때 한 번 다시 동의를 받는다(동의에 범위 버전을 더한다). *추천* — 위치는 일기보다 민감하다.
   - (b) 문구만 바꾸고 다시 묻지 않는다.
3. (선택) **물어보기에 위치를 아예 빼는 스위치**가 필요할까 — 앱 설정 › 물어보기에 "위치 기록 참고" 켬/끔(기본 켬).
   필요 없다면 "내 기록 참고하기"를 끄는 것으로 대신한다. *추천: 이번엔 만들지 않음*

## 8. 빌더 몫

- `LifeTools` 를 쪼갤지(위치 도구를 `location_tools.dart` 로) — 400줄이 넘으니 나누는 쪽을 권한다.
- 날 단위 읽기 · 메모리 상한, 이름 조회 동시성, JSON 필드 이름 세부, 진행 줄 문구.
- 날씨 도구가 날씨 cubit 과 로직을 나눠 쓰도록 유스케이스로 빼는 범위.

# walk — 내 기록에 묻는 채팅 설계

> 작성 2026-10-27 · 앱: [Life Tool(walk)](../../../apps/walk/docs/README.md) · 계획: [walk 계획](../../../apps/walk/docs/plan.md)

## 의도

Life Tool 에는 이미 내 하루가 모인다 — 일기 · 스토리(무엇을 했고 무엇을 먹었고 어디 있었는지),
걸음 수(얼마나 움직였는지), 알람 울림 기록(몇 시에 일어났는지). 이걸 **채팅으로 물어보면 내 기록을
근거로 답해 주는 탭**을 만든다. "10월 3일에 뭐 했지?", "지난주에 뭐 먹었지?", "요즘 몇 시에
일어나?", "제주 여행 때 하루에 얼마나 걸었어?" 같은 질문.

출발점은 "LLM 위키"(LLM 이 개인 기록을 정리해 위키로 키우는 것)였다. 하지만 아직 위키로 무엇을
할지 감이 없고, 날짜 · 사실 질문은 정리된 요약보다 **원본 기록을 직접 찾아보는 쪽**이 정확하다.
그래서 첫 버전은 위키 없이 Claude 가 도구로 기록을 찾아 읽고 답하는 채팅으로 만들고, 써 보면서 자주
하는 질문이 보이면 그때 위키(요약 페이지)를 얹는다.

사용자는 앱 주인 한 명이다(개인 · 토이 프로젝트).

## 목표 · 비목표 · 안티 목표

**목표**

- 새 탭에서 자연어로 묻고, Claude 가 일기 · 걸음 · 기상 기록을 찾아 근거 있게 답한다.
- 답에 쓴 기록을 눌러 원래 일기로 갈 수 있다.
- 기상 기록을 오래 남긴다 — 지금은 네이티브에 최근 200줄만 있어 몇 주 · 몇 달 지나면 사라진다.

**비목표(이번에 안 함)**

- LLM 위키(요약 · 주제 페이지 자동 생성).
- 음성 · 회의록 받아쓰기, 외부 파일 넣기.
- 서버 · 프록시 · 다른 사람에게 배포. 키는 사용자 본인 것.
- 위치 이동 기록 수집(통근은 장소 설정만 있다). 어디 갔는지는 일기의 장소로만 안다.
- 통근 기능 손보기 · 탭 구조 재설계.
- 걸음 외 건강 데이터(수면 · 심박 · 운동 종류).

**안티 목표(기술적으로 돌아가도 실패)**

- **기록에 없는 걸 지어내는 답.** 찾지 못하면 "기록에 없어요"라고 말해야 한다. 그럴듯한 추측을
  사실처럼 말하면 실패다.
- **모르는 사이에 일기가 밖으로 나가는 것.** 일기 설정은 "이 폰에만 저장"이라고 안내한다. 채팅은
  필요한 기록을 Anthropic API 로 보내므로, 처음 쓸 때 이를 분명히 알리고 동의를 받는다.
- **일기 잠금 우회.** 일기를 PIN · 패턴으로 잠갔는데 채팅으로 내용을 읽을 수 있으면 안 된다.
- **API 키 노출.** 평문 SharedPreferences · 로그 · 오류 메시지에 키가 남으면 안 된다.

## 결정된 것

### 화면

- 하단 탭은 다섯 개를 유지한다: **통근 탭을 빼고 그 자리에 채팅 탭을 넣는다** — [알람 · 걷기 · 일기 ·
  채팅 · 설정]. 통근은 나중에 다시 다룬다(사용자 결정, 2026-10-27). 통근 코드(`lib/{data,domain,presentation}/commute/`)와
  테스트는 지우지 않고 셸에서 연결만 끊는다 *(설계자 판단)*. 탭 이름 · 아이콘은 빌더 몫(예: "물어보기").
  탭 수 줄이기 · UI 정리는 기능을 만든 뒤 따로 한다.
- 채팅 탭은 **일기 잠금 게이트 아래** 둔다(일기 탭과 같은 잠금 · 같은 해제 상태 공유).
- 화면은 Claude 채팅창처럼 — 메시지 목록 + 아래 입력칸, 답은 스트리밍으로 흘러나온다. 대화 시작 전
  빈 상태에 예시 질문 몇 개를 칩으로 보인다.
- 답 아래에 **참고한 기록** 칩(날짜 · 본문 앞부분 또는 썸네일)을 붙이고, 누르면 그 기록을 연다(일기의
  기존 화면 재사용 — 스토리 뷰어 등). 칩은 이번 답을 만들며 도구가 돌려준 일기 기록에서 만든다.
- 설정 탭에 **채팅 섹션**: API 키 입력 · 교체 · 삭제, 데이터 전송 안내.
- 키가 없으면 채팅 탭은 `AppPlaceholder` 로 "설정에서 키를 넣어 주세요" + 설정으로 가는 버튼.
- 처음 채팅을 열 때 한 번, "질문에 필요한 일기 · 사진 · 걸음 · 기상 기록이 Anthropic 으로 전송된다"
  안내와 동의를 받는다. 동의 여부는 저장한다.

### Claude 호출

- Anthropic Messages API 를 HTTP 로 직접 호출한다(Dart 공식 SDK 없음). 스트리밍(SSE).
- 모델 기본값 `claude-opus-5-5`. 채팅이라 effort 는 낮게(`low` 부터) 시작한다.
- **도구 사용(tool use) 루프**: Claude 가 도구를 부르면 앱이 로컬에서 실행해 결과를 돌려주고, 끝날 때까지
  반복한다. `tool_choice` 는 `auto`(이 모델은 강제 도구 호출을 받지 않는다).
- 시스템 프롬프트에 오늘 날짜 · 시간대, "기록에 근거해서만 답하고 없으면 없다고 말한다", 한국어로
  답한다를 담는다.
- 키는 **기기 보안 저장소**(예: `flutter_secure_storage`)에 둔다.

### 도구(첫 버전)

Claude 에게 주는 도구. 이름 · 매개변수 · 반환 형식의 세부는 빌더 몫이지만 아래 능력은 있어야 한다.

| 도구 | 하는 일 | 근거 데이터 |
|---|---|---|
| 기간의 일기 | 날짜 구간(+선택: 본문 검색어 · 태그 · 장소 · 스토리)으로 일기를 찾는다. 기록마다 시각 · 본문 · 장소 · 태그 · 스토리 제목 · 사진/영상 개수와 id. 휴지통 제외 | `DiaryRepository` — **스토리를 가리지 않는 날짜 구간 조회는 지금 없어 새로 만든다** |
| 기록 사진 보기 | 기록 id(또는 미디어 id)로 사진을 이미지로 돌려준다(영상은 썸네일). "그때 뭐 먹었지?"처럼 글에 없고 사진에만 있는 경우 | 앱 폴더의 미디어 파일 |
| 스토리 · 태그 · 장소 목록 | 무엇이 있는지 훑기(이름과 기록 수) | `watchStories` · `watchTagCounts` · `watchPlaceCounts` |
| 기간의 걸음 수 | 날짜 구간의 하루 걸음 합계 | `ActivityRepository.dailyActivities` (Health Connect, 권한 없으면 그렇다고 알린다) |
| 기간의 기상 기록 | 날짜 구간의 알람 울림 · 끔 · 스누즈와 그날의 "일어난 시각" | 아래 새 기상 기록 저장소 |

### 기상 기록 오래 남기기

- 지금: 알람 포크 네이티브 `RingLog` 가 SharedPreferences 에 최근 200줄(`MAX_ENTRIES`)만 둔다. 앱이
  꺼져 있어도 울림을 남기기 위한 것이라 이 구조는 유지한다.
- 추가: 앱이 **열릴 때 · 앞으로 돌아올 때** 네이티브 기록을 읽어 앱의 drift DB 로 옮겨 담는다(중복은
  `at` + `packageId` + `kind` 로 거른다). 200줄은 그 사이의 완충 역할만 한다.
- 옮겨 담을 때 **그 알람의 라벨 · 설정 시각을 함께 적어 둔다** — 나중에 알람을 지우거나 고쳐도 "출근
  알람을 7:12 에 껐다"를 말할 수 있게.
- 이 기능을 넣기 전의 기록은 남아 있는 200줄까지만 가져온다.
- 기존 **알람 울림 기록 화면**(`AlarmHistoryPage` · `AlarmHistoryCubit`)도 이 새 저장소를 읽게 바꾼다 —
  두 곳이 서로 다른 기간을 보여 주지 않게. 지운 알람은 옮길 때 적어 둔 라벨 · 시각으로 보인다.
  *(설계자 판단)*

## 빌더에게 맡기는 것

- "그날 일어난 시각"의 정의 — 예: 그날 처음 `stopped`(사용자가 끔)된 시각, 자동 멈춤만 있으면 별도 표시.
- 대화 저장 방식(대화 하나를 이어 쓸지, 목록으로 남길지)과 긴 대화의 문맥 관리. → [대화 기록 · 위키 기획](2026-11-01-walk-chat-history-wiki.md)(1단계 구현됨)
- 도구 결과 크기 제한(한 번에 돌려줄 기록 수 · 사진 수 · 사진 해상도)과 페이지 나눔.
- 기상 기록 테이블을 어느 drift DB 에 둘지(일기 DB 와 분리 권장 — 일기 잠금 · 휴지통 규칙과 무관).
- 네트워크 오류 · 잘못된 키 · 요금 한도 · 거절(`refusal`) 응답의 안내 문구(`AppSnackBar` · `AppPlaceholder`).
- 탭 이름 · 아이콘 · 예시 질문 문구. UI 는 [CLAUDE.md](../../../CLAUDE.md)의 공통 위젯 · 토큰 규칙을 따른다.
- 계층 배치는 walk 의 기존 구조(`lib/{data,domain,presentation}/<feature>/`)와 [아키텍처](../../architecture.md)를 따른다.

## 이후(위키로 가는 길)

채팅을 써 보며 반복되는 요약형 질문("요즘 나 어때?", "이번 달 돌아보기")이 보이면, Claude 가 주간 ·
월간 요약 페이지를 만들어 폰에 저장하고 채팅이 그 페이지도 읽는 도구를 더한다. 그게 LLM 위키의
첫 페이지가 된다. 기록과 위키 기획은 [대화 기록 · 위키 수정](2026-11-01-walk-chat-history-wiki.md).

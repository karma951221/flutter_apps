# 물어보기 추천 질문을 AI 가 만든다 — 설계(짧은 판)

날짜: 2026-11-17 · 앱: `apps/walk`(Life Log) · 상태: 승인 대기

## 1. 의도

물어보기 첫 화면(빈 대화)에는 고정 예시 질문 칩 3개(어제 · 먹은 것 · 기상)가 있다. 실사용에서
이 칩을 잘 누르지 않는다. 사용자가 실제로 자주 묻는 질문을 바탕으로 AI 가 추천 질문을 만들게 해서
첫 화면에서 바로 누를 만한 질문이 보이게 한다. 사용자 원문: "대화 턴을 여러번 이어나가면 ai가
자동으로 최근 질문들을 바탕으로 추천질문을 만드는거야. 그걸 shared preference같은 내부 저장소에
저장해두면 좋을거 같음".

- 목표: 최근 질문을 바탕으로 만든 짧은 질문 4개가 첫 화면 칩으로 보인다. 자동으로 갱신되고, 손으로 새로 만들 수도 있다.
- 비목표: 대화 중(말풍선 아래) 이어 묻기 추천. 첫 화면의 기존 대화 목록 변경. 입력칸 · 앱바 · 설정 시트(`walk-chat-input` 세션 영역).
- 반(反)목표: 사용자가 모르는 사이 비용이 계속 드는 것. 동의 범위를 넘어 기록(일기 · 위치 등)을 보내는 것. 첫 화면이 생성 때문에 늦게 뜨는 것.

## 2. 접근

| 안 | 내용 | 판단 |
|---|---|---|
| A. 첫 화면이 뜰 때 필요하면 생성(채택) | 빈 대화 화면이 보일 때 "마지막 생성 뒤 새 질문이 N개 이상"이면 백그라운드로 생성. 저장된 추천(또는 기본)을 먼저 보이고 끝나면 바꾼다 | 화면이 실제로 쓰일 때만 부르므로 낭비가 적다. 채팅 전송 흐름(`ChatCubit` · `ChatSession`)을 건드리지 않아 입력 세션과 충돌하지 않는다 |
| B. 턴이 저장될 때마다 세서 생성 | 답이 저장된 뒤 카운터가 N 이면 생성 | 사용자 말과 가장 가깝지만 전송 흐름에 끼어든다. 첫 화면을 열지 않으면 버리는 호출이 생긴다 |
| C. 하루 한 번 | 날짜가 바뀌면 생성 | 질문을 안 해도 부르고, 많이 물은 날엔 늦다 |

A 를 쓴다. 사용자 체감("여러 턴 이어가면 자동으로 바뀐다")은 같다 — 다음에 빈 화면을 열 때 바뀌어 있다.

## 3. 동작

**입력** — 저장된(임시 대화가 아닌) 질문 중 최근 20개의 글과 물은 날짜, 오늘 날짜 · 요일, 앱 언어.
질문 하나는 200자까지 자른다. 답 · 기록 · 위키 · 첨부는 보내지 않는다.

**생성 조건** — 모두 맞을 때만 부른다.
- 키가 있고 연결 벤더가 있으며, 그 벤더로의 물어보기 동의(`consentedVendor == connectedVendor`)가 있다.
- 저장된 질문이 3개 이상이다.
- 마지막 생성 뒤 새로 저장된 질문이 5개 이상이다(처음이면 3개 이상이면 된다). 기준은 마지막 생성 때 본 가장 최근 질문 시각.
- 마지막 시도(실패 포함)에서 10분이 지났다 — 실패가 반복되어도 화면을 열 때마다 부르지 않는다.
- 이미 생성 중이 아니다.

**출력** — 질문 4개. 한 줄에 하나, 각 40자 이하, 사용자 말투(1인칭 질문). 앱이 답할 수 있는 종류
(내 일기 · 걷기 · 위치 · 알람 기록을 돌아보는 질문, 일반 질문)로, 최근 질문을 그대로 베끼지 말고 비슷한
관심사를 다른 기간 · 각도로 묻게 한다. 파싱: 줄 단위, 번호 · 글머리표 · 따옴표 제거, 빈 줄 · 40자 넘는 줄 ·
중복 제거, 앞 4개. 3개 미만이면 실패로 보고 저장된 것을 그대로 둔다.

**모델 · 비용** — 일기 초안과 같은 "같은 벤더의 싼 모델"(`draftModelOf`: Haiku · gpt-N-mini). 도구 · 웹 검색 ·
생각 없이 한 라운드, 출력 상한 200 토큰. 사용량은 새 쓰임 `ChatUsagePurpose.chatSuggest` 로 기록하고
사용량 화면에 "추천 질문"으로 보인다.

**저장** — SharedPreferences 키 `walk.chat.suggestions` 에 JSON
`{questions: [...], generatedAt, basedOnAskedAt, vendor}`, 마지막 시도 시각은 `walk.chat.suggestionsTriedAt`.
모르는 모양이면 없는 것으로 본다. 백업 · 복원에는 넣지 않는다(복원 뒤 다시 만들어진다).

**보이기** — 빈 화면 칩은 다음 순서로 고른다.
1. 저장된 질문이 하나도 없으면(대화를 모두 지운 경우 포함) 기본 질문 3개 — 지금의 고정 질문을 그대로 기본값으로 쓴다. 지운 대화에서 나온 추천이 남아 보이지 않게 한다.
2. 저장된 추천이 있으면 그 4개.
3. 없으면 기본 질문 3개.

추천을 보일 때 칩 아래에 작은 "새로 만들기"(↻) 버튼을 둔다. 누르면 조건의 "새 질문 N개 · 10분"을
무시하고 바로 생성한다(키 · 동의 · 질문 3개 조건은 유지). 생성 중엔 버튼 자리에 작은 진행 표시, 실패하면
기존 `AppSnackBar.show` 로 한 줄 알린다(자동 생성 실패는 조용히). 키 · 동의가 없거나 질문이 3개 미만이면
버튼을 숨긴다. 칩을 누르면 지금처럼 바로 보낸다.

**"내 기록 참고하기"가 꺼져 있을 때** — 생성 · 표시는 같다. 추천 생성은 원래 질문 글만 보내고 기록은 보내지
않으므로 이 스위치와 무관하다. (꺼진 채로 "어제 뭐 했지?"를 누르면 지금 고정 칩과 같이 기록 없이 답한다.)

**동의 범위** — 물어보기 동의는 "질문과 대화를 연결 벤더로 보낸다"는 범위다. 추천 생성은 이미 그 벤더로
보낸 질문 글만 같은 벤더로 다시 보내므로 새 동의를 받지 않는다. 벤더를 바꿔 새로 동의했다면 그 벤더도
물어보기 대화 이어가기로 옛 질문을 받을 수 있으므로 같은 범위로 본다. 동의 문구는 바꾸지 않는다.

## 4. 구조

- `domain/chat/suggest/` — `ChatSuggestions`(저장 모델), `ChatSuggestionStore`(인터페이스), `SuggestPrompt`(프롬프트 · 파싱), `ChatSuggester`(조건 판단 · 생성 · 사용량 기록, `DraftWriter` 와 같은 모양).
- `data/chat/prefs_chat_suggestion_store.dart` — SharedPreferences 구현.
- `ChatHistoryRepository.recentQuestions(limit)` — 대화를 가로질러 askedAt 내림차순 (질문, 시각) 목록. drift 구현 추가.
- `presentation/chat/cubit/chat_suggestions_cubit.dart` + `widget/chat_examples.dart` 확장. `chat_tab.dart` 는 `_Conversation` 에서 cubit 을 주입하는 한두 줄만 바꾼다.
- l10n: 새로 만들기 툴팁 · 실패 문구 · 사용량 "추천 질문".

## 5. 빌더에게 맡기는 것

프롬프트 문구, 칩 · 버튼의 정확한 배치(기존 `ChatExamples` 모양 유지), JSON 필드 이름.

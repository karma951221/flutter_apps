# walk — 알람 남은 시간 · 요약 카드 · 울림 버튼 기획

> 작성 2026-09-29 · 상태: **검토 중** · 앱 문서 [walk 허브](../../../apps/walk/docs/README.md) ·
> 선행 설계 [walk 알람 · 설정 탭](2026-09-27-walk-alarm-design.md)

## 1. 목적

알람 탭을 열었을 때 **"다음 알람이 언제, 얼마 뒤에 울리는지"**를 한눈에 보이게 하고,
알람마다 남은 시간을 보여준다. 스위치로 켜고 끄면 그 숫자가 곧바로 바뀐다. 울릴 때는
어떤 상황이든 **[5분 뒤 다시 울림] · [알람 끄기]** 두 버튼을 함께 보여준다.

## 2. 사용자 요구 (2026-09-29)

1. 알람마다 남은 시간을 보여준다. 초 단위는 필요 없다. 맨 위에는 가장 먼저 울릴 알람을
   요약한 카드를 둔다.
2. 목록에서 스위치로 알람을 켜고 끈다. 그러면 1번의 시간도 갱신된다.
3. 알람이 울리면 [5분 뒤 다시 울림]과 [알람 끄기]를 함께 둔다.
   화면이 꺼져 있을 때는 **전체 화면 울림 화면**, 폰을 쓰는 중에는 **상단 알림(헤드업)**.

## 3. 지금 상태 (2026-09-29 코드 기준)

| 항목 | 지금 | 이번에 바꿀 것 |
|---|---|---|
| 목록 머리 | `다음 알람까지 7시간 12분` 텍스트 한 줄 | 요약 카드 |
| 행 | 시각 · `라벨 · 반복` · 스위치 | 남은 시간 한 줄 추가 |
| 갱신 | 탭을 연 시점부터 1분마다 저장소를 다시 읽는다 — 표시가 최대 59초 늦다 | 매분 0초에 맞춰 갱신, 저장소는 읽지 않는다 |
| 스위치 | 있다. 스위치를 먼저 움직이고 저장한 뒤 다시 읽는다 | 그대로. 카드 · 행 시간이 저장 직후 함께 바뀌는지 테스트로 고정 |
| 울림 화면 | `[5분 뒤] [끄기]` 나란히 | 문구 변경 |
| 알림 | 제목 = 라벨 또는 "알람", 본문 = `21:45`, 버튼 `끄기` · `5분 뒤` | 문구 변경, 본문을 기기 언어 시각으로 |

## 4. 화면

### 4.1 요약 카드 (목록 맨 위)

```
┌──────────────────────────────┐
│ 다음 알람                     │
│ 7시간 12분 후                 │  ← headlineMedium, primary
│ 내일 (화) 오전 7:00 · 출근     │  ← bodyMedium, onSurfaceVariant. 라벨 없으면 생략
└──────────────────────────────┘
```

- 켜진 알람 중 **실제로 가장 먼저 울릴 시각**을 보여준다. 스누즈로 미룬 회차도 포함한다(§5 · §7).
- 날짜 표기: 오늘이면 `오늘`, 내일이면 `내일`, 그 뒤는 `10월 3일`. 뒤에 `(요일)`과 시각.
  예: `오늘 (월) 오후 9:45`, `내일 (화) 오전 7:00`, `10월 3일 (금) 오전 7:00`.
- 가장 이른 시각에 알람이 둘 이상이면 id 가 작은 것의 라벨을 쓴다.
- 알람은 있는데 모두 꺼져 있으면 카드에 `켜진 알람이 없어요` 한 줄만.
- 알람이 하나도 없으면 카드를 숨기고 기존 빈 상태(`AppPlaceholder`)만 보인다.
- 카드는 누를 수 없다.
- 권한 경고 배너가 있으면 배너 → 카드 순서.

### 4.2 알람 행

```
오전 7:00                          [●]
출근 · 평일
7시간 12분 후                        ← bodySmall, primary
```

- 켜진 알람에만 셋째 줄(남은 시간)을 보인다. 꺼진 알람은 지금처럼 흐리게, 셋째 줄 없음.
- 남은 시간은 그 알람이 **실제로 다음에 울릴 시각**까지다(요약 카드와 같은 계산, 스누즈 포함).

### 4.3 남은 시간 표기

기존 `AlarmFormat.duration` 규칙을 그대로 쓰고 뒤에 `후`를 붙인다.

| 남은 시간 | 표기 |
|---|---|
| 0초 초과 ~ 1분 이하 | `1분 후` |
| 1분 30초 | `2분 후` (분은 올림) |
| 3시간 | `3시간 후` |
| 3시간 5분 | `3시간 5분 후` |
| 1일 3시간 20분 | `1일 3시간 후` (하루 넘으면 분 생략) |
| 2일 0시간 | `2일 후` |

올림을 쓰는 이유: 곧 울릴 알람이 `0분 후`로 보이지 않게 하고, 알람 저장 스낵바
(`N시간 M분 뒤에 울려요`)와 같은 숫자를 보이기 위해서다.

### 4.4 울림

| 상황 | 보이는 것 | 버튼 |
|---|---|---|
| 화면 꺼짐 · 잠금 | 전체 화면 `AlarmRingingPage` (확인됨 2026-09-27) | 왼쪽 `5분 뒤 다시 울림`(secondary) · 오른쪽 `알람 끄기`(primary) |
| 폰 사용 중 · 다른 앱이 앞 | 상단 헤드업 알림 | 알림 액션 `알람 끄기` · `5분 뒤 다시 울림` (순서는 패키지가 정한다) |
| 폰 사용 중 · 이 앱이 앞 | 앱 안에서 `AlarmRingingPage` 가 푸시된다 (기존 `AlarmRingListener`) | 위와 같음 |
| 헤드업 알림 본문을 누름 | 앱이 열리고 `AlarmRingingPage` | 위와 같음 |

- 알림 제목 = 라벨 또는 `알람`(그대로), 본문 = 기기 언어 시각(`오전 7:00`).
- 버튼 문구가 길어진다(`5분 뒤 다시 울림`). 울림 화면 버튼은 반씩 나눈 폭에서 두 줄까지
  허용하고 가운데 정렬한다 — 320dp 폭에서 잘리지 않아야 한다.
- 안드로이드는 사용 중인 화면을 전체 화면 알림으로 덮지 않고 헤드업으로 바꾼다. 이 동작은
  OS 규칙이라 바꾸지 않는다.

## 5. 상태와 갱신

`AlarmListLoaded` 를 바꾼다.

```dart
const factory AlarmListState.loaded({
  required List<Alarm> alarms,
  required Map<int, DateTime> nextAt,   // 켜진 알람 id → 실제 다음 울림. 없으면 키 없음
  required DateTime now,                 // 표시 기준 시각(분 경계)
  @Default(true) bool canRing,
}) = AlarmListLoaded;
```

- 남은 시간은 상태에 넣지 않는다. 화면이 `nextAt[id]!.difference(now)` 로 계산한다.
  요약 카드는 `nextAt` 의 최솟값(같으면 id 작은 것).
- `nextAt` 은 **예약된 것이 기준**이다. use case 에 `Future<Map<int, DateTime>> nextRings()` 를
  더한다 — `AlarmScheduler.scheduled()` 의 패키지 id 들을 `alarmIdOf` 로 알람별로 묶어
  `now` 보다 뒤인 가장 이른 시각. 스누즈(같은 패키지 id 를 `now+5분` 으로 다시 건 것)가
  자연히 들어간다. 켜진 알람만 남긴다. 규칙으로 계산(`upcomingTriggers`)하지 않는 이유:
  스누즈를 놓치고, 권한 문제로 예약이 빠졌을 때 "울리지 않을 알람"을 울릴 것처럼 보인다.
- **1회성 자동 끄기 조건을 좁힌다**: 지금 sync 는 `oneShotAt <= now` 면 끈다. 스누즈 중인
  1회성도 꺼져 버려 카드에서 사라지므로, **그 알람의 예약(스누즈 포함)이 하나도 남지 않았을
  때만** 끈다.
- **`tick()`** — 저장소를 읽지 않고 `now` 만 바꿔 emit. 새 `now` 가 어떤 `nextAt` 이상이면
  (알람이 울릴 시각이 지났으면) 대신 `load()` 해 다음 회차로 넘긴다.
- **분 경계 타이머** — 목록 페이지가 `Timer(다음 분 0초까지)` → 그 뒤 `Timer.periodic(1분)`
  으로 `tick()`. 다른 탭에 가려져 있으면(`TickerMode`) 건너뛴다. 탭이 다시 보이면 즉시 `tick()`.
- 기존 `load()` 호출 시점(시작 · 복귀 sync 뒤 · 편집/울림 화면이 닫힐 때 · 토글 뒤)은 유지.
- 스위치: 지금처럼 스위치를 먼저 움직이고(`alarms` 만 낙관적 갱신) 저장 → `load()`.
  카드 · 행 시간은 `load()` 가 끝나는 순간(저장 직후) 바뀐다. 실패하면 `load()` 가
  스위치를 되돌리고 스낵바 `알람을 저장하지 못했어요`(기존).

## 7. 경계 사례

- **스누즈 중인 알람**: 카드 · 행이 스누즈 시각(`4분 후`)을 보인다. 반복 알람도 스누즈가
  끝나면 다음 `load()` 에서 원래 규칙의 다음 회차로 돌아간다.
- **스누즈 중인 1회성 알람**: 스위치가 켜진 채로 남고(§5 자동 끄기 조건), 스누즈가 울리고
  꺼진 뒤 sync 에서 꺼진다.
- **알람이 막 울림**: `tick()` 이 `nextAt` 경과를 보고 `load()` → 울린 회차는 `now` 보다
  앞이라 빠지고 다음 예약으로 넘어간다. 1회성의 스위치를 끄는 것은 다음 sync(복귀 · 울림 화면
  닫힘)가 한다.
- **권한이 없어 예약이 안 걸림**: `nextAt` 에 키가 없어 행 셋째 줄 · 카드가 비고, 기존 경고
  배너가 원인을 알려준다. 알람이 켜져 있는데 예약이 없으면 카드는 `켜진 알람이 없어요` 대신
  아무 알람도 보이지 않는다 — 배너와 함께 보이므로 허용.
- **자정을 넘김**: `오늘`/`내일` 판정은 표시 기준 `now` 로 한다. 자정 tick 에서 `내일` 이
  `오늘` 로 바뀐다.
- **기기 시각 · 시간대 변경**: 다음 tick 또는 복귀 `load()` 에서 바로잡힌다(허용).
- **24시간제**: 시각은 `AlarmFormat.time` 이 기기 설정을 따른다(기존).

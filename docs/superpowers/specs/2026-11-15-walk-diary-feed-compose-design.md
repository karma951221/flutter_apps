# 일기 — 피드형 작성 · 사진으로 초안 쓰기

> 작성 2026-11-15 · 대상 앱 `apps/walk`(Life Tool) · 앞선 설계: [일기](2026-10-10-walk-diary-design.md) · [화면 재기획(스토리형)](2026-10-21-walk-diary-story-redesign-design.md)
> 진행 상태는 [걷기 진행 현황](../../../apps/walk/docs/status.md) 에만 적는다.

## 1. 왜

실사용 피드백 두 가지.

1. **"스토리 형태로 일기 작성하는 게 불편하다. 그냥 일반 피드 쓰듯이 쓰고 싶다."**
   지금은 ＋ → 고르기 시트(앨범 · 카메라 · 글만) → 큰 사진 미리보기 → "어디에 올릴까요?" 스토리 동그라미 →
   글 순서다. 글을 쓰려면 시트를 한 번 거치고, 스토리를 고르는 일이 가장 앞에 있다. 카드를 누르면 전체 화면
   스토리 뷰어가 열린다.
2. **"매번 쓰는 게 귀찮다. 갤러리 사진과 짧은 설명으로 간단한 피드를 자동으로 써 주면 좋겠다."**

## 2. 결정 요약

사용자와 정한 것(2026-11-15 기획 질의):

| 질문 | 고른 답 |
|---|---|
| 스토리를 어떻게 | 뒤로 숨김 — 데이터 · 뷰어는 남기고 탭 동그라미 줄을 빼고, 작성 화면엔 맨 아래 한 줄(F3 · F4) |
| 피드 카드 | 일반 피드식 — 머리는 날짜 · 시각 + 장소, 사진을 눌러야 전체 화면(F5) |
| 사진을 모델로 보낼지 | 기본 끔 + 도구줄 토글(마지막 선택 기억, 켤 때 확인)(A2) |
| 초안 진입점 | 작성 화면 ✨ 버튼 하나(A1) |
| 초안 길이 | 기본 2~4문장. 사진 개수 · 메모 길이에 따라 늘거나 준다(§4 길이 규칙) |
| 초안 문체 | 일기 설정에서만 고른다 — 4가지, 기본 일기체(§4 문체). 작성 화면 칩은 두지 않는다 |

| # | 결정 | 근거 |
|---|---|---|
| F1 | ＋ 는 시트 없이 **작성 화면을 바로** 연다 | 한 단계 줄이기. 사진은 작성 화면 안 도구줄에서 붙인다 |
| F2 | 작성 화면은 **글이 맨 위**(새 기록은 자동 포커스) → 붙인 사진 줄 → 도구줄(앨범 · 사진 · 영상 · ✨ 초안) → 정보 행(장소 · 시각 · 태그 · 스토리) | SNS 글쓰기와 같은 순서 |

| F6 | **DB 스키마 · 저장 형식은 바꾸지 않는다** | 필요한 필드(글 · 사진 · 장소 · 시각 · 태그 · 스토리)가 이미 있다. 마이그레이션이 없으니 기존 기록은 그대로 보인다 |
| A1 | ✨ 초안 = 글 칸(메모) + 사진 촬영 시각 등 → 물어보기에 연결된 벤더의 빠르고 싼 모델 한 번 호출 → **글 칸에 스트리밍** | 기존 연결 · 동의 재사용, 비용은 초안 전용 모델로 |
| A2 | **사진 자체는 기본으로 보내지 않는다**. 도구줄 "사진 보여 주기" 토글(기본 꺼짐 · 마지막 선택 기억 · 켤 때 확인) | 아래 §4 |

## 3. 작성 화면(F1~F3)

```
[✕]  새 기록                      [올리기]
┌────────────────────────────────────┐
│ 오늘 어땠나요?                      │  ← 글 = 초안의 메모(minLines 4, 새 기록은 자동 포커스)
└────────────────────────────────────┘
[▢][▢][▢]  ← 붙인 사진 · 영상 썸네일(× 빼기, 길게 눌러 순서)
#태그 칩 입력
📍 장소 행 (기존 PlaceInput)
🕒 시각 행 (기존 TimeRow) [찍은 시각으로(어제 15:20)]  ← §4 시각 · 장소
📚 스토리 · 일상 ›  (StoryPickerSheet, 고치기는 지난 스토리까지)
──────────────────────────────────────
[🖼] [📷] [🎥]   [🖼 사진 보여 주기]   [✨]   ← 도구줄: 화면 아래 · 키보드 바로 위에 고정
```

- 상태 · 규칙은 `EntryEditorCubit` 그대로(임시 사본 · 버릴지 묻기 · 잠금 뒤 유지).
- **도구줄은 키보드 위에 고정**한다(R-F2). 목록과 따로 화면 아래에 두고 키보드가 올라오면 함께 올라온다 — 글을 쓰는 중에도 가려지지 않는다.
- 미디어 한도(`MediaLimits`)를 다 채우면 앨범 · 사진 · 영상 버튼이 꺼진다.
- **기본 스토리**는 지금 규칙 그대로(열린 것 중 최근에 기록을 넣은 것, R-F1). 저장 스낵바는 저장한 스토리가 "일상"이면 "올렸어요",
  아니면 "'제주 여행'에 올렸어요" — 모르는 사이 다른 스토리로 들어간 것을 알 수 있게.
- `openEntryEditor(initialPick:)` 는 **지운다**(쓰는 곳이 없다, R-F5). 다른 앱에서 사진 공유로 여는 진입점은 후속 과제(§7).
- 한 기록만 여는 뷰어(피드의 사진 탭)는 **자동 넘김 타이머 · 진행 막대를 끈다**(R-F3) — 넘기기는 손으로.
- 일기 탭: 빈 상태 문구에 "＋ 를 눌러 첫 기록을 남겨 보세요" 안내, 읽는 중은 빈칸 대신 공통 위젯의 로딩 표시(R-F4).

## 4. 자동 초안(A1~A3, 2026-11-15 리뷰 반영)

### 흐름(R-A1)

- **메모는 글 칸의 내용이다.** 메모를 다시 입력하는 시트는 없다. ✨ 를 한 번 누르면 바로 생성하고 **글 칸에 스트리밍으로** 채운다.
- 시트 · 다이얼로그는 세 경우에만 뜬다: **키 없음**(안내 + [설정 열기]) · **첫 사용 동의**(물어보기와 같은 `consentedVendor`) ·
  **사진 전송 확인**(사진 보여 주기를 켜는 순간 한 번 — "사진 n장까지 ○○로 보내져요").
- 생성 중: 글 칸은 읽기 전용, ✨ 자리는 [■ 멈추기]. 멈추면 그때까지의 글이 남는다.
- 끝나면 스낵바 [되돌리기] → 원래 메모로. ✨ 는 **[다시 쓰기]**(같은 자리, 툴팁만 바뀜)가 된다.
- **다시 쓰기 규칙(R-A3)**: `DraftCubit` 이 첫 생성 때의 **원래 메모**를 보관한다.
  - 글 칸이 마지막 초안 그대로면 → 원래 메모로 다시 생성한다(문장만 바뀐 새 초안).
  - 사용자가 초안을 고친 뒤 누르면 → 그 고친 글을 **다듬는다**(메모 = 지금 글, "새 사실을 더하지 말고 다듬기" 지시).
- **재료가 없으면 ✨ 를 끈다(R-A4)**: 글 칸이 비고 사진 보여 주기가 꺼져 있으면 비활성. 길게 누르면(툴팁)
  "한 줄 적거나 사진 보여 주기를 켜세요".
- 실패(네트워크 · 거절 · 빈 응답): 글 칸을 원래 메모로 되돌리고 스낵바로 이유. 손으로 계속 쓴다(A3).
- **잠금(R-A9)**: 생성 중 일기가 다시 잠기면 생성을 취소한다. 글 칸에는 그때까지의 글(없으면 원래 메모)이 남는다.

### 문체(R-A2)

- 문체는 **일기 설정 › 자동 초안에서만** 고른다(4가지, 아래 표). 작성 화면에는 문체 칩이 없다 — 초안은 늘 설정의 문체로 쓴다.

| 값 | 이름 | 지시 요지 | 예 |
|---|---|---|---|
| `diary`(기본) | 일기체 | 반말 '~했다', 해시태그 · 이모지 없음 | 성수동 카페에서 책을 읽었다. 창가 자리가 따뜻했다. |
| `polite` | 존댓말 | 담백한 '~했어요', 해시태그 · 이모지 없음 | 성수동 카페에서 책을 읽었어요. 창가 자리가 따뜻했어요. |
| `sns` | SNS 포스트체 | 가벼운 말투, 이모지 1~2개까지, 해시태그 없음(태그는 태그 칸 몫) | 성수동 카페에서 독서 타임 ☕ 창가 자리 최고였다 |
| `memo` | 메모체 | 짧게 끊어 '~함' · 명사형 | 성수동 카페, 독서. 창가 자리 따뜻함. |

### 사진 보여 주기(R-A4)

- 도구줄의 토글(사진이 1장 이상일 때만 보임). 기본값은 꺼짐이고 **마지막 선택을 기억**한다(`diary.draft.includePhotos`,
  일기 설정 › 자동 초안의 같은 값).
- 켜는 순간 한 번 확인 다이얼로그. 켜 두면 압축 사본 최대 4장(`ChatImageSource`, 1024px JPEG · EXIF 없음)을 보낸다.
- 초안 모델이 이미지를 못 받으면(모델 목록의 `supportsImages == false`) 토글을 끄고 "이 모델은 사진을 볼 수 없어요"를 보인다.

### 사진을 기본으로 보내지 않는 이유(A2)

- **비용**: 사진 1장은 대략 1,000~1,500 입력 토큰. 메모 · 메타데이터만 보내면 200 토큰 안팎이라 5~10배 차이.
- **프라이버시**: 일기 사진에는 얼굴 · 집 안 · 문서가 찍힌다. 물어보기도 사진은 모델이 부를 때만 보낸다.
- **품질**: 메모가 주 재료다. 메모가 비고 사진만 있을 때 켜면 사진을 보고 쓴다.

### 시각 · 장소(R-A5 · R-A6)

- 사진을 가져올 때 원본 EXIF 에서 **촬영 시각만** 읽는다(`DateTimeOriginal`, 메모리에만, 저장 안 함). **GPS → 장소 이름 찾기는 v1 에서 뺀다**
  (`PlaceNamer` 호출 없음, 좌표도 읽지 않는다).
- 고른 사진의 촬영 시각(가장 이른 것)이 **지금과 3시간 넘게** 다르면 시각 행에 칩 "찍은 시각으로(어제 15:20)"를 보인다. 누르면 기록 시각이
  그 시각이 되고, 기존 과거 시각 규칙대로 현재 위치가 빠지고 장소를 직접 입력한다.
- 그 상황(촬영 시각이 3시간 넘게 다름)에서 장소가 **자동으로 잡힌 현재 위치**면 프롬프트에서 장소를 뺀다 — 지금 있는 곳이 사진 속 장소가 아닐 수 있다.
  사용자가 직접 넣은 장소는 보낸다.
- 프롬프트의 시각은 **기록의 시각**(바꿨으면 바뀐 값)이다. 촬영 시각 범위는 맥락 줄로 따로 준다.

### 모델 · 비용(R-A7)

- 물어보기에서 고른 모델을 쓰지 않는다. **같은 벤더의 빠르고 싼 모델을 고정**한다 — Claude 는 Haiku 계열, GPT 는 mini 계열.
  모델 목록(`ChatModelCatalog`)에서 그 계열의 최신을 고르고, 목록이 없으면 상수(`claude-haiku-5-5` · `gpt-5-mini`)를 쓴다. 고르는 규칙은 `chat_model_rules.dart` 한 곳.
- **출력 토큰 상한**(약 600)을 두고 **thinking(추론)은 끈다**. 도구 · 웹 검색 없음.
- 사용량은 반드시 남긴다(`ChatUsagePurpose.diaryDraft`, 사용량 화면 "· 일기 초안").

### 언어(R-A8)

- "한국어" 고정이 아니라 **메모의 언어를 따른다**. 메모가 비면(사진만) 앱 locale 의 언어로 쓴다.

### 길이 규칙

- 기본 2~4문장. 프롬프트에 목표 범위를 숫자로 준다(앱이 계산, 모델이 대략 따른다 — 잘라 내지는 않는다).
- 메모 20자 이하이고 사진 1장 이하 → 1~2문장. 사진 4장 이상이거나 메모 100자 이상 → 3~6문장(긴 메모는 다듬기 지시).
- 경계값은 `DraftLength` 한 곳.

### 모델에 보내는 것

- system: 개인 일기 글, 1인칭, 메모 · 맥락에 없는 사실을 지어내지 않기, 글만 돌려주기 + 언어 · 길이 · 문체 지시(다듬기면 다듬기 지시).
- user: 메모 + 맥락 줄 — 기록 시각, 장소 이름(위 규칙으로 뺄 수 있음), 사진 · 영상 개수, 사진 촬영 시각 범위, 붙인 태그. 좌표 없음.

## 7. 하지 않는 것 · 후속

- 스토리 기능 삭제 · 스키마 변경. 스토리 뷰어 · 스토리 페이지 · 모든 스토리는 그대로 남는다.
- EXIF GPS → 장소 이름(v1 에서 뺌). 사진 촬영 시각으로 기록 시각을 **자동으로** 바꾸기(칩으로만).
- 작성 화면 문체 칩(문체는 설정에서만).
- 다른 앱에서 사진을 공유받아 작성 화면을 여는 진입점(공유 인텐트, 후속).
- 갤러리를 앱이 스스로 훑어 하루치 피드를 만들어 두는 것.

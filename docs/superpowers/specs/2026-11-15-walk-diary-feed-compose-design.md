# 일기 — 피드형 작성 · 사진으로 초안 쓰기

> 작성 2026-11-15 · 대상 앱 `apps/walk`(Life Tool) · 앞선 설계: [일기](2026-10-10-walk-diary-design.md) · [화면 재기획(스토리형)](2026-10-21-walk-diary-story-redesign-design.md)
> 진행 상태는 [걷기 진행 현황](../../../apps/walk/docs/status.md) 에만 적는다.

## 1. 왜

실사용 피드백 두 가지.

1. **"스토리 형태로 일기 작성하는 게 불편하다. 그냥 일반 피드 쓰듯이 쓰고 싶다."**
   지금은 ＋ → 고르기 시트(앨범 · 카메라 · 글만) → 큰 사진 미리보기 → "어디에 올릴까요?" 스토리 동그라미 →
   글 순서다. 글을 쓰려면 시트를 한 번 거치고, 스토리를 고르는 일이 가장 앞에 있다. 카드를 누르면 전체 화면
   스토리 뷰어가 열린다.
2. **"매번 쓰는 게 귀찮다. 갤러리 사진과 짧은 설명으로 간단한 피드를 자동으로 써 주면 좋겠다."**

## 2. 결정 요약

사용자와 정한 것(2026-11-15 기획 질의):

| 질문 | 고른 답 |
|---|---|
| 스토리를 어떻게 | 뒤로 숨김 — 데이터 · 뷰어는 남기고 탭 동그라미 줄을 빼고, 작성 화면엔 맨 아래 한 줄(F3 · F4) |
| 피드 카드 | 일반 피드식 — 머리는 날짜 · 시각 + 장소, 사진을 눌러야 전체 화면(F5) |
| 사진을 모델로 보낼지 | 기본 끔 + 초안 시트 스위치(A2) |
| 초안 진입점 | 작성 화면 ✨ 버튼 하나(A1) |
| 초안 말투 | 짧은 일기체 2~4문장 — 1인칭 반말('~했다'), 지어내지 않기, 해시태그 · 이모지 없음 |

| # | 결정 | 근거 |
|---|---|---|
| F1 | ＋ 는 시트 없이 **작성 화면을 바로** 연다 | 한 단계 줄이기. 사진은 작성 화면 안 도구줄에서 붙인다 |
| F2 | 작성 화면은 **글이 맨 위**(새 기록은 자동 포커스) → 붙인 사진 줄 → 도구줄(앨범 · 사진 · 영상 · ✨ 초안) → 정보 행(장소 · 시각 · 태그 · 스토리) | SNS 글쓰기와 같은 순서 |
| F3 | 스토리는 **지우지 않고 뒤로** 뺀다 — 작성 화면 맨 아래 "스토리" 한 행(기본값 그대로, 누르면 시트) | 데이터 모델 · 뷰어 · 지도 · 물어보기 도구가 스토리에 기대고 있다. 고르는 일만 선택 사항으로 |
| F4 | 일기 탭 맨 위 **스토리 동그라미 줄을 뺀다**. 피드만 남고, 스토리는 ⋮ 모든 스토리 · 카드의 스토리 이름으로 간다 | "스토리 형태가 불편"의 가장 눈에 띄는 부분 |
| F5 | 피드 카드 머리는 **날짜 · 시각 + 장소**, 스토리 이름은 "일상"이 아닐 때만 작은 글씨로. 카드 몸통을 눌러도 뷰어로 가지 않고, **사진을 누르면** 그 기록만 전체 화면으로 본다 | 일반 피드처럼 읽는 곳은 목록 자체 |
| F6 | **DB 스키마 · 저장 형식은 바꾸지 않는다** | 필요한 필드(글 · 사진 · 장소 · 시각 · 태그 · 스토리)가 이미 있다. 마이그레이션이 없으니 기존 기록은 그대로 보인다 |
| A1 | ✨ 초안 = 메모 한 줄 + 사진 메타데이터 → 물어보기에 연결된 벤더(Claude · GPT) 한 번 호출 → **글 칸을 채운다**(사용자가 고친 뒤 저장) | 기존 연결 · 모델 선택 · 동의를 그대로 재사용 |
| A2 | **사진 자체는 기본으로 보내지 않는다**. 초안 시트에 "사진도 보여 주기" 스위치(기본 꺼짐, 마지막 값 기억) | 아래 §4 |
| A3 | 키 없음 · 동의 없음 · 실패 · 취소면 **손으로 쓰기로 자연스럽게** 돌아간다(글 칸 그대로, 시트에 이유 한 줄) | 피드백의 핵심은 "덜 귀찮게" — 막히면 안 된다 |

## 3. 작성 화면(F1~F3)

```
[✕]  새 기록                      [올리기]
┌────────────────────────────────────┐
│ 오늘 어땠나요?                      │  ← 글(minLines 4, 새 기록은 자동 포커스)
└────────────────────────────────────┘
[▢][▢][▢]  ← 붙인 사진 · 영상 썸네일(× 빼기, 길게 눌러 순서)
[🖼 앨범] [📷] [🎥]            [✨ 초안]  ← 도구줄
#태그 칩 입력
📍 장소 행 (기존 PlaceInput)
🕒 시각 행 (기존 TimeRow)
📚 스토리 · 일상 ›  (StoryPickerSheet, 고치기는 지난 스토리까지)
```

- 상태 · 규칙은 `EntryEditorCubit` 그대로(임시 사본 · 버릴지 묻기 · 잠금 뒤 유지 · 저장 스낵바).
- 미디어 한도(`MediaLimits`)를 다 채우면 앨범 · 사진 · 영상 버튼이 꺼진다.
- `openEntryEditor(initialPick:)` 는 남긴다(다른 진입점에서 쓸 수 있다). ＋ 는 넘기지 않는다.
- 저장 스낵바 "○○에 올렸어요" 는 스토리를 일부러 바꿨을 때만 의미가 있으니 "올렸어요"로 줄인다.

## 4. 사진으로 초안 쓰기(A1~A3)

### 흐름

1. 작성 화면 도구줄 ✨ → 초안 시트.
2. 시트: 메모 한 줄(글 칸에 이미 쓴 짧은 글이 있으면 그것으로 채움) · "사진도 보여 주기" 스위치(사진이 있을 때만) ·
   [초안 쓰기]. 아래에 "메모 · 시각 · 장소 이름(사진을 켜면 사진도)이 ○○(벤더)로 보내져요" 한 줄.
3. 쓰는 중에는 진행 표시 + [멈추기]. 성공하면 시트가 닫히고 글 칸을 초안으로 바꾼다. 원래 글이 있었으면
   스낵바 [되돌리기].
4. 키가 없으면 [초안 쓰기] 대신 안내("물어보기 설정에서 키를 넣으면 쓸 수 있어요") + [설정 열기]. 동의가 없으면
   기존 전송 동의 문구로 한 번 묻고 기록한다(물어보기와 같은 `consentedVendor`).

### 모델에 보내는 것

- system: 짧은 한국어 개인 일기 글(2~4문장, 1인칭 반말 일기체 '~했다', 해시태그 · 이모지 없음, 메모 · 맥락에 없는 사실을 지어내지 않기), 글만 돌려주기.
- user: 메모 + 맥락 줄 — 기록 시각(초안 화면의 시각), 장소 이름(있으면), 사진 · 영상 개수, 사진 촬영 시각 범위 ·
  촬영 장소 이름(EXIF 가 있으면), 붙인 태그.
- 도구 없음 · 웹 검색 없음 · 스트리밍으로 받아 마지막 글만 쓴다. 사용량은 물어보기 사용량 로그에 남긴다(가능하면).

### 사진을 기본으로 보내지 않는 이유(A2)

- **비용**: 사진 1장(긴 변 1024px)은 대략 1,000~1,500 입력 토큰. 메모 · 메타데이터만 보내면 200 토큰 안팎이라
  한 번에 5~10배 차이. 매일 쓰는 기능이라 기본은 싼 쪽.
- **프라이버시**: 일기 사진에는 얼굴 · 집 안 · 문서가 찍힌다. 앱은 지금까지 "이 폰에만 저장"이 원칙이었고, 물어보기도
  사진은 모델이 `view_entry_photos` 를 부를 때만 보낸다. 같은 결로 사진은 사용자가 그때그때 켤 때만.
- **품질**: 사용자가 원한 것은 "간단한 description 으로" 쓰는 짧은 글이라 메모가 주 재료다. 메모가 비고 사진만 있을 때
  스위치를 켜면 사진을 보고 쓴다.
- 켜면 기존 `ChatImageSource`(1024px JPEG, EXIF 없음 — 이미 압축 사본) 최대 4장을 user 메시지에 붙인다.

### 메타데이터

- 고른 원본은 압축할 때 EXIF 를 지우고 `MediaPicker.release` 로 원본 복사본도 지운다. 그래서 **가져오는 순간** 원본에서
  촬영 시각(`DateTimeOriginal`)과 GPS 를 읽어 메모리에만 들고 있다(`exif` 패키지, 순수 Dart). 저장하지 않는다.
- GPS 는 모델에 좌표를 보내지 않고 `PlaceNamer` 로 이름만 구해 보낸다(이름을 못 구하면 뺀다).
- Android 사진 선택기는 위치 EXIF 를 지울 수 있다(`ACCESS_MEDIA_LOCATION` 없음). 그러면 장소는 작성 화면의 장소만 쓴다.

## 5. 계층

| 위치 | 새것 |
|---|---|
| `domain/diary/draft/` | `PhotoMeta`(촬영 시각 · 좌표), `DraftContext`(메모 · 시각 · 장소 · 개수 · 촬영 범위 · 태그), `DraftWriter` 유스케이스(벤더 호출 · 결과 union: `text` · `failed(ChatFailure)` · `cancelled`), 프롬프트 빌더 |
| `data/diary/media/` | `ExifPhotoMetaReader`(원본 경로 → `PhotoMeta?`) |
| `presentation/diary/` | `EntryEditorPage` 재배치, `ComposerMediaStrip` · `ComposerToolbar`, `DraftSheet` + `DraftCubit`, 피드 카드 머리 · 탭 동작 |

`DraftWriter` 는 `WikiDistiller` 처럼 세션과 따로 돈다(원문 키를 직접 읽고 연결 벤더 · `ChatModelChoice.currentModel`).
Freezed 는 저장소 규칙(단일 모델 Primary Constructor, union 은 sealed + factory).

## 6. 테스트

- 도메인: 프롬프트 빌더(메모 · 맥락 줄 · 빈 값 생략 · 좌표 미포함), `DraftWriter`(키 없음 · 동의 없음 · 성공 · 거절 · 오류 · 취소 · 사진 켜면 첨부 · 끄면 없음).
- 데이터: EXIF 읽기(시각 · GPS 있음 / 없음 / 깨진 파일 → null).
- 화면: 작성 화면(글이 위 · 자동 포커스 · 도구줄 · 한도 · 스토리 행 · 저장), 초안 시트(키 없음 안내 · 생성 → 글 칸 · 되돌리기 · 실패 시 글 그대로),
  일기 탭(동그라미 줄 없음 · ＋ 가 바로 작성 화면), 피드 카드(머리 · 사진 탭 → 뷰어 · 몸통 탭은 뷰어 아님).

## 7. 하지 않는 것

- 스토리 기능 삭제 · 스키마 변경. 스토리 뷰어 · 스토리 페이지 · 모든 스토리는 그대로 남는다.
- 사진 촬영 시각으로 기록 시각을 자동으로 바꾸기(과거 시각 규칙 · 위치 규칙과 얽힌다 — 후속 후보).
- 갤러리를 앱이 스스로 훑어 하루치 피드를 만들어 두는 것(권한 · 배터리 · 프라이버시가 커서 따로 기획).

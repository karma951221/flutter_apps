## 범위

내 프로필 조회·수정(닉네임 · 자기소개 · 프로필 사진), 타인 프로필 조회, 프로필 내
게시물 목록. 데이터·권한 설계는 [기획 F2](../../overview.md)와 [스키마 `profiles`](../../schema.md)가 기준이다.

## 화면 목록

| 화면 | 역할 | 진입 경로 |
|---|---|---|
| 프로필 | 닉네임 · 자기소개 · 아바타 · 게시물 목록. 내/타인 공용 위젯, 소유 여부로 분기 | 탭(내 프로필) / 피드·댓글의 작성자 탭(타인) |
| 프로필 편집 | 닉네임 · 자기소개 수정, 아바타 선택 → 압축 → 업로드 | 내 프로필의 편집 버튼 |
| 프로필 꾸미기 | 편집 화면의 setup 모드. 제목 "프로필 꾸미기", 안내 한 문장, "계속"(저장) 아래에 "나중에". 둘 다 홈으로 간다. 뒤로가기 없음 | 가입 성공 직후 redirect (`/profile/setup`) |

내 프로필에만 노출: 편집 버튼 · 로그아웃. 타인 프로필에만 노출: (2단계 이후) 신고 · 차단 메뉴.

## 화면별 상태

| 화면 | 상태 | UI |
|---|---|---|
| 프로필 | 로딩 | 공통 `loading_view` |
| 프로필 | 오류 | 공통 `error_view` + 재시도 |
| 프로필 | 게시물 없음 | 공통 `empty_view` ("아직 게시물이 없습니다") |
| 프로필 | 게시물 목록 | 커서 페이지네이션 무한 스크롤 (feed와 같은 커서 규칙) |
| 프로필 (내) | 완성도 카드 | 닉네임·사진·자기소개·첫 게시물·첫 팔로우 다섯 칸을 진행바로 세고, 목록에는 **남은 항목만** 줄로 세운다. 닉네임은 항상 완료라 20% 에서 시작한다. 다섯 개가 끝나면 사라진다 |
| 편집 | 닉네임 중복 | 디바운스 사전 확인 표시. 최종 판정은 DB 제약 — 저장 실패 시 문구 매핑 |
| 편집 | 업로드 중 | 아바타 업로드 진행 표시, 저장 버튼 비활성 |
| 편집 | 저장 실패 | 입력 값 유지 + 오류 문구 |

## 입력 검증

- 닉네임: 2~20자 (DB CHECK · `lower(nickname)` 유니크 인덱스와 동일 기준)
- 자기소개: 최대 200자
- 아바타: X3 media 재사용 — 선택 → 긴 변 1080px · WebP · q80 압축 → 버킷 `avatars`의
  `{user_id}/` 경로 업로드 (본인 경로만 쓰기 가능, Storage RLS)

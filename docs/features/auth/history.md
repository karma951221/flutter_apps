## 설계 판단

### 비밀번호 재설정에 딥링크를 쓰지 않는다

Supabase 기본 템플릿은 `{{ .ConfirmationURL }}` 링크를 보내고, 앱이 이를 받으려면
Universal Links / App Links 설정이 필요하다. 대신 `{{ .Token }}` 6자리 코드를 보내고
앱 안에서 입력받으면 **딥링크 설정이 통째로 필요 없어진다.**

- `supabase/templates/recovery.html` — 코드 방식 템플릿
- `supabase/config.toml` — `[auth.email.template.recovery]`
- 앱은 `verifyOTP(type: recovery)` 로 검증

### passwordRecovery 를 로그인으로 취급하지 않는다

`verifyOTP` 가 성공하면 Supabase 는 **세션을 발급한다.** 이걸 그대로 로그인으로 보면
**메일 코드만 알아도 홈 화면에 진입할 수 있다.** `authStateChanges()` 에서
`AuthChangeEvent.passwordRecovery` 를 걸러내 이 경로를 막았다.

비밀번호 변경 후에는 명시적으로 `signOut()` 하고 로그인 화면으로 되돌린다.

### 로그인 실패 시 원인을 구분하지 않는다

"없는 계정"과 "비밀번호 틀림"을 나눠 알려주면 계정 열거(enumeration)가 가능해진다.
둘 다 "이메일 또는 비밀번호가 올바르지 않습니다"로 응답한다.

### 화면이 직접 이동하지 않는다

로그인·회원가입 성공 시 `context.go(...)` 를 호출하지 않는다. `AuthBloc` 이 상태를
바꾸고 라우터의 `redirect` 가 이동시킨다. 화면마다 "로그인했나?"를 확인하지 않으므로
새 화면을 추가할 때 보호를 빠뜨릴 여지가 없다.

## 겪은 버그

### `await for` 로 브로드캐스트 스트림을 소비하면 이벤트가 유실된다

**증상**: 회원가입이 DB 에는 성공하는데 앱이 가입 화면에 그대로 머문다.
앱을 재시작하면 그제서야 로그인된 상태로 홈에 진입한다.

**원인**: `authStateChanges()` 를 이렇게 썼다.

```dart
await for (final event in _client.auth.onAuthStateChange) {
  yield await _loadProfile(user);   // ← 이 await 동안 구독이 일시정지된다
}
```

`onAuthStateChange` 는 **브로드캐스트** 스트림이다. `await for` 는 본문이 `await` 하는
동안 구독을 일시정지하는데, 브로드캐스트 스트림은 일시정지된 구독을 위해 이벤트를
버퍼링하지 않고 **버린다.** 회원가입 직후의 `signedIn` 이벤트가 그렇게 사라졌다.

세션 자체는 정상 저장됐기 때문에 재시작하면 복구된 것처럼 보였고, 이 점이 원인 파악을
늦췄다.

**해결**: 콜백 방식 `listen()` 으로 바꿨다. 콜백은 구독을 멈추지 않으므로 유실이 없다.
`StreamController` 로 감싸 초기 상태와 이후 이벤트를 한 스트림으로 합친다.

**교훈**: 브로드캐스트 스트림을 `await for` + 비동기 본문으로 소비하지 않는다.

### 스트림 오류가 인증을 영구히 죽인다

`listen()` 에 `onError` 가 없으면 스트림이 한 번 실패한 뒤 구독이 끝나고,
**이후 어떤 로그인도 반영되지 않는다.** `onError` 를 추가하고, 프로필 조회 실패가
로그인 자체를 막지 않도록 최소 정보로 폴백한다. 회귀 테스트로 고정했다.

### 단일 구독 StreamController 는 리스너가 없으면 close() 가 완료되지 않는다

테스트 `tearDown` 이 30초 타임아웃으로 죽었다. 구독하지 않는 테스트에서
`controller.close()` 의 Future 가 영영 완료되지 않아서다. `.broadcast()` 로 바꿔 해결.

### 검증 오류 문구가 갱신되지 않는다

값을 고쳐도 이전 오류가 남았다. `Form` 에 `autovalidateMode: onUserInteraction` 을
지정해 제출 이후에는 입력하는 대로 재검증하게 했다.

## 검증

실기기(Android 에뮬레이터)에서 확인한 것:

- 빈 폼 제출 → 필드별 오류 표시
- 잘못된 비밀번호 → "이메일 또는 비밀번호가 올바르지 않습니다"
- 로그인 성공 → 홈 자동 이동, 프로필(닉네임) 조인 정상
- **앱 강제 종료 후 재실행 → 로그인 화면 없이 홈** (세션 유지)
- 로그아웃 → 로그인 화면 리다이렉트
- 회원가입 → 홈 자동 이동, `profiles` 행 생성 확인
- **닉네임 중복(대소문자 무시) → 가입 차단** (`SecondTester` ↔ `secondtester`)
- 재설정: 코드 발송 → Mailpit 수신 → 검증 → 새 비밀번호 → 새 비밀번호로 로그인 성공
- 재설정 중 코드 검증 성공 시점에 **홈으로 튕기지 않음** (passwordRecovery 가드)

자동화 테스트의 현재 범위와 실행 명령은 [auth 테스트 문서](../../testing/features/auth.md)를
단일 기준으로 삼는다.

## 2026-08-24 — 로그인 화면 개편

세 인증 화면(로그인 · 회원가입 · 재설정)이 각자 여백과 배치를 들고 있어서 필드가
하나 늘 때마다 조금씩 어긋났다. 공통 뼈대를 두 위젯으로 뽑았다.

- `AuthScaffold` — 여백 · 최대 너비(440) · 스크롤 규칙. 항상 스크롤 가능하되 내용이
  짧으면 세로 중앙에 놓는다. 작은 화면에서 키보드가 올라오면 폼이 화면을 넘기기
  때문이고, 그렇다고 늘 위쪽에 붙이면 로그인 화면이 허전해진다
- `AuthHeader` — 앱 이름(워드마크)과 한 줄 설명

그 밖에 바꾼 것.

- 비밀번호 보기 토글과 `textInputAction` 연결(이메일 → 비밀번호 → 제출)
- 제출 중에는 입력과 다른 화면 진입을 모두 막는다. 요청 결과를 받을 화면이 사라지는
  경로를 없앤다
- `autovalidateMode: onUserInteraction` — 한 번 제출한 뒤에는 고치는 대로 다시
  검증한다. 없으면 값을 고쳐도 이전 오류 문구가 남는다
- 화면 전환은 여전히 화면이 하지 않는다. `AuthBloc` 이 상태를 바꾸고 라우터의
  redirect 가 보낸다

E2E 셀렉터(`signIn.email` 등)는 그대로 뒀다. 라벨 문구가 바뀌어도 Patrol 테스트가
깨지지 않아야 한다.

## 남은 것

- **비밀번호 재설정 배포용 SMTP** — 로컬은 Mailpit 으로 동작. 운영에는 발송사(Resend 등) + 도메인 필요
- **이메일 확인(enable_confirmations)** 은 꺼져 있다. 가입 즉시 세션이 발급된다. 운영 전 재검토
- **iOS 검증** — Xcode 미설치로 미확인. Keychain 동작은 플랫폼별로 다르게 실패할 수 있어 확인 필요
- `AuthChangeEvent` 로깅(`debugPrint`)은 남겨뒀다. 시끄러워지면 제거
